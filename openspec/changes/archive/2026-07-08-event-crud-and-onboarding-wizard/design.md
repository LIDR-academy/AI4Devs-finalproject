## Context

Aura needs a core Event entity to manage weddings and parties. The Event entity acts as the root aggregate for everything else (guests, RSVPs). We must implement a full backend CRUD for this entity, and an automated data retention policy. On the frontend side, an onboarding wizard is required to guide hosts through setting up an event step-by-step.

## Goals / Non-Goals

**Goals:**
- Implement `EventService` and `EventsController` with full CRUD for the `Event` entity.
- Generate unique, URL-safe slugs for each event automatically.

- Ensure automated creation of `DataRetentionJob` entities upon event creation to delete the event 30 days after its end date.
- Protect all endpoints with `EventOwner` authorization policy.
- Build a multi-step onboarding wizard in the frontend Angular app using reactive forms and control flow syntax.

**Non-Goals:**
- Full CSV guest import (this will be handled in a separate story, PSRP-008). We only need an optional manual guest input or a skip option in the onboarding wizard.
- Soft-delete recovery mechanism. For MVP, we will do a hard delete or simple soft-delete without user-facing recovery UI.

## Decisions

- **Slug Generation**: Slugs will be generated by converting the event name to lowercase, replacing spaces with hyphens, and removing special characters, appended with the event year. If a duplicate exists, we will append an incrementing number (`-2`, `-3`).

- **Frontend Wizard Architecture**: We will use Angular's new `@switch` control flow for managing the visibility of the steps inside the onboarding wizard to keep the component clean and avoid complex routing for a simple linear flow.
- **Data Retention**: We will create a `DataRetentionJob` at the time of event creation.

## Risks / Trade-offs


- **Slug Collisions**: High concurrency could cause slug collision during generation.
  *Mitigation*: We will enforce a database unique constraint on the slug and implement a retry mechanism with incremented suffixes on DbUpdateException.
