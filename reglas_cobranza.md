> Documentation of what is **implemented** in code (web2py / DB `fugger` master = `db_maestro`).
> No code was modified. Each rule cites file + line/function.
> **Scope:** SaaS billing (plan, empresa_plan, pago, corte_plan, consumo_plan).
> Do not confuse with `cxc_cuenta_por_cobrar` (AR from **client sales**, a different domain).

## Unconfirmed assumptions (require validation)

1. **⚠️ `empresa_plan.estatus` contradiction.** The comment in `db.py:756` says `4 = Blocked` and `2/3 = Contracted/Pending`, but the **live code does not use 2 or 3**, and treats `4` as **billable** (`IN (1,4)`), not as a terminal block. Need to confirm which version is current in production. Both documented (#2a vs #2b).
2. **Operational definition of "BLOCKED".** In the code there is no localized `SET estatus = 4`; the idea of blocking for "2 pending payments" comes from the **docstring** of `dh_plan.activar_plan`, not from a found statement. Did not verify where/when `estatus = 4` is assigned.
3. **Threshold `total > 10`.** Assumed as a "minimum billable amount" rule (amounts ≤ 10 are marked paid). No named constant or comment explaining it.
4. **`pagos_pendientes.py` vs `cron_plan.py`.** Nearly identical (two versions of the same process). `pagos_pendientes.py:399` has **hardcoded dates** (`'2021-09-02'..'2021-09-07'`) → appears to be a one-time backup/migration script; the active cron is `cron_plan.py:503` (`now()-1 day`). Confirm which one runs in production.
5. **Reactivation after non-payment.** The flow when `obtener_pago_pendientes == 0` **revives** the plan (new `empresa_plan` estatus=1) automatically; did not confirm the exact transition when the count is ≥ 1 (left at 0/expired or moved to 4?).
6. **Volume price / scale.** The subtotal uses `complemento_volumen` (price per quantity) with fallback to MIN(price); did not validate the behavior of `complemento_escala` / `plan_complemento_escala` (appear unused in the charge calculation).
7. **TZ.** Assumed single-timezone server; did not confirm `timezone` of PostgreSQL or the OS where the cron runs.
