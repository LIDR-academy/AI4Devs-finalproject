# 🎫 TK-007-B: Pantalla de Login por PIN en Frontend

## 📝 Descripción
Este ticket consiste en implementar la pantalla táctil de autenticación de operarios en la cocina. Debe proporcionar un teclado numérico en pantalla (1-9, borrar, confirmar) optimizado para interacciones táctiles en tablets de cocina, permitiendo ingresar el PIN de 4 dígitos, enviarlo al backend (`POST /api/auth/pin`) y almacenar de forma segura el token JWT recibido en la sesión activa.

*   **ID US Relacionada:** `US-001`
*   **Módulo / Vertical Slice:** `auth` (Autenticación y Sesiones)
*   **Estimación (Story Points):** 3
*   **Prioridad MoSCoW:** Must Have
*   **Prerrequisitos:** `TK-002` (API de autenticación del backend)

---

## 🔀 Alcance de Modificación (Hexagonal Layers)
*   **Domain / Application:** Representación cliente del estado de autenticación (usuario logueado, expiración de sesión).
*   **Infrastructure / Frontend:**
    *   Componente de UI `PinPad.tsx` (teclado numérico ergonómico con botones de mínimo `64px`).
    *   Componente `LoginView.tsx` que maneja el envío al backend y la validación de errores visuales (ej. PIN inválido, credenciales incorrectas).
    *   Servicio de cliente HTTP `AuthClient` para conectar con `/api/auth/pin`.
    *   Almacenamiento de tokens en almacenamiento local encriptado o de sesión.

---

## ⚠️ Mitigación de Riesgos Técnicos
1.  **Bloqueo de UI ante Respuestas Lentas de Red:** El ingreso del PIN debe deshabilitar temporalmente el teclado numérico en pantalla y mostrar un indicador de carga para evitar reenvíos múltiples o clics duplicados del operario.
2.  **Manejo Seguro del PIN en UI:** El PIN ingresado no debe mostrarse como texto plano en pantalla. Utilizar puntos de máscara (ej. `••••`) y asegurar que se borre automáticamente de la memoria del estado tras el intento.

---

## ✅ Criterios de Aceptación & DoD (Definition of Done)

### Criterio de Aceptación 1: Autenticación exitosa
*   **Given** que el operario ingresa a la aplicación
*   **When** presiona los dígitos "1", "2", "3", "4" y hace clic en "Confirmar"
*   **Then** se realiza la petición al backend, se guarda el JWT y se le redirige al feed de alertas de cocina.

### Criterio de Aceptación 2: Error por credenciales incorrectas
*   **When** el operario ingresa un PIN incorrecto (ej: "9999") y confirma
*   **Then** la UI muestra un mensaje de error claro en color rojo ("PIN incorrecto. Intente de nuevo.") y limpia la máscara de entrada.

### DoD Estricto:
1.  **Diseño Responsivo / Táctil:** Botones numéricos de tamaño mínimo `64px` con espaciado de `12px` para evitar pulsaciones erróneas.
2.  **Testing:** Suite de pruebas con Vitest y Testing Library que verifique la interactividad del teclado numérico, la máscara de entrada y la simulación del endpoint de login.
