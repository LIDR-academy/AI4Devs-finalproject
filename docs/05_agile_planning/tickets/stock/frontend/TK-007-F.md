# 🎫 TK-007-F: Pantalla de Registro de Extracciones de Bodega en Frontend

## 📝 Descripción
Este ticket consiste en desarrollar la interfaz táctil que le permite al personal autorizado registrar la extracción de insumos cerrados desde la bodega para ser abiertos en el área de cocina. La pantalla debe permitir seleccionar el insumo, ingresar la cantidad extraída y la ubicación destino, enviando los datos a `POST /api/stock/extraction`.

*   **ID US Relacionada:** `US-002`
*   **Módulo / Vertical Slice:** `stock` (Control de Bodega)
*   **Estimación (Story Points):** 3
*   **Prioridad MoSCoW:** Must Have
*   **Prerrequisitos:** `TK-003` (API de registro de extracciones)

---

## 🔀 Alcance de Modificación (Hexagonal Layers)
*   **Domain / Application:** Definición cliente de la extracción y tipos de unidad de medida.
*   **Infrastructure / Frontend:**
    *   Formulario de extracción táctil `WarehouseExtractionForm.tsx`.
    *   Servicio `StockClient` para conectar con `POST /api/stock/extraction`.
    *   Integración con el lector de código de barras virtual o buscador de insumos táctil rápido.

---

## ⚠️ Mitigación de Riesgos Técnicos
1.  **Doble Envío Accidental:** Los operarios pueden presionar repetidamente el botón de confirmación. Asegurar que el botón "Registrar Extracción" quede deshabilitado en cuanto se presiona, mostrando un estado visual de carga.
2.  **Validación de Unidades e Invariantes:** Impedir el ingreso de cantidades negativas o iguales a cero en el cliente, mostrando alertas de validación antes de realizar la petición HTTP.

---

## ✅ Criterios de Aceptación & DoD (Definition of Done)

### Criterio de Aceptación 1: Registro exitoso de extracción
*   **Given** que el operario autorizado abre la pantalla de extracciones
*   **When** selecciona el insumo "Salsa de Tomate Pomodoro", ingresa la cantidad `1.0000` y pulsa "Registrar Extracción"
*   **Then** la API responde con éxito y la UI notifica la apertura del remanente, redirigiendo al feed de remanentes activos.

### Criterio de Aceptación 2: Rechazo por cantidad inválida
*   **When** se intenta ingresar una cantidad de `0` o `-1.5`
*   **Then** el botón de envío se deshabilita y se muestra un aviso en rojo indicando que la cantidad debe ser mayor a cero.

### DoD Estricto:
1.  **Diseño:** Interfaz optimizada para el ingreso de datos rápido mediante un teclado de números virtual amplio.
2.  **Testing:** Pruebas unitarias en Vitest que simulen el envío del formulario y verifiquen el bloqueo de cantidades inválidas en el cliente.
