# 🎫 TK-007-E: Dashboard de Reportes de Desperdicio y Eficiencia FEFO en Frontend

## 📝 Descripción
Este ticket consiste en implementar el panel de control y analíticas para administradores en el frontend. Debe consumir los datos agregados del endpoint `/api/reports/waste` y visualizarlos gráficamente, permitiendo analizar las mermas registradas, clasificar el desperdicio por motivos (vencimiento, daño físico, contaminación) y evaluar el indicador de Tasa de Rotación de Remanentes (TRR) para la toma de decisiones.

*   **ID US Relacionada:** `US-009`
*   **Módulo / Vertical Slice:** `reports` (Reportes y Analíticas)
*   **Estimación (Story Points):** 3
*   **Prioridad MoSCoW:** Should Have
*   **Prerrequisitos:** `TK-010` (API de reportes y analítica de mermas)

---

## 🔀 Alcance de Modificación (Hexagonal Layers)
*   **Domain / Application:** Estructura cliente del reporte consolidado de mermas.
*   **Infrastructure / Frontend:**
    *   Componente de UI `ReportsDashboard.tsx`.
    *   Gráficos circulares/de barras táctiles (usando librerías ligeras como SVG puro o Canvas ligero) para mostrar la distribución de mermas por ingredientes y por motivos.
    *   Servicio `ReportsClient` para conectar con `GET /api/reports/waste`.

---

## ⚠️ Mitigación de Riesgos Técnicos
1.  **Carga Excesiva de Datos de Reporte:** El dashboard debe implementar selectores de fecha sencillos (ej. "Hoy", "Últimos 7 días", "Mes Actual") y paginación en el consumo del servicio para evitar transferencias pesadas que congelen la interfaz táctil.
2.  **Seguridad y Control de Roles:** El acceso a esta vista debe requerir obligatoriamente el rol `ADMIN` en la sesión JWT. Si un operario normal intenta entrar, la UI debe redirigir al feed de cocina con un aviso de acceso denegado.

---

## ✅ Criterios de Aceptación & DoD (Definition of Done)

### Criterio de Aceptación 1: Visualización correcta de mermas
*   **Given** que el usuario inicia sesión como Administrador
*   **When** ingresa a la pestaña "Reportes"
*   **Then** visualiza las métricas consolidadas (Total Mermas, Distribución por Motivo, Costo Estimado en Pérdidas) y los gráficos interactivos de barras/donas.

### Criterio de Aceptación 2: Bloqueo para Operadores comunes
*   **Given** un operario autenticado con rol `OPERATOR`
*   **When** intenta forzar la navegación al dashboard de reportes `/reports`
*   **Then** la aplicación bloquea la entrada, muestra un mensaje de acceso restringido y lo mantiene en el feed de cocina.

### DoD Estricto:
1.  **Diseño Visual Premium:** Dashboard oscuro con gráficos interactivos de alto impacto, utilizando colores semánticos armoniosos y fuentes de fácil lectura.
2.  **Testing:** Pruebas unitarias que verifiquen el bloqueo de rutas según el rol JWT y el mapeo correcto del payload JSON de reporte a los elementos visuales de la pantalla.
