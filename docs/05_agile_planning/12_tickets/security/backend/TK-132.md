# 🎟️ TK-132: `trust proxy` + Rate Limiting por Cliente Real (AUDIT-SEC-003)

> [⬅️ AUDIT-SEC-003](../../../../audits/AUDIT-SEC-003-rate-limiter-shared-bucket.md) | [📖 Índice](../../indice_tickets.md)

## 📝 Descripción

**Remediación técnica** (carve-out C-DEV-006-4): no cambia ninguna regla de negocio de cara al usuario — el comportamiento *previsto* (rate limiting por IP, Guard 16) ya estaba documentado; esto cierra un defecto de configuración que lo hacía compartir un único bucket entre todos los clientes detrás de nginx.

Disparador: el humano preguntó por el error "Has realizado demasiados intentos" y si afecta a producción. Al trazarlo se encontró **AUDIT-SEC-003 F-1**: `app.ts` nunca llamó `app.set('trust proxy', …)`, así que detrás de nginx `req.ip` = IP del contenedor de nginx para todos → 10 intentos de login y 100 peticiones globales **compartidos por todo el restaurante**.

*   **Slice:** `security` backend · **SP:** 3 · **Prioridad:** 🟠 P1 (F-1) + 🟡/🟢 (F-2/F-3/O-1)

## 🔀 Alcance

*   **`app.ts` `createApp()`:** `app.set('trust proxy', ['loopback', 'linklocal', 'uniquelocal'])` (override vía `options.trustProxy`). Se confía en `X-Forwarded-For` sólo si el peer del socket está en un rango privado/loopback → una petición directa desde IP pública ignora el XFF (sin spoofing) aunque el puerto `3000` siga expuesto.
*   **`app.ts`:** `resolveLoginRateLimitOptions()` (env `LOGIN_RATE_LIMIT_WINDOW_MS`/`LOGIN_RATE_LIMIT_MAX`, default `900000`/`10`) pasado a `createAuthRouter`. `resolveRateLimitOptions()` default global `100 → 300`.
*   **`auth.routes.ts`:** `createAuthRouter` gana 5º parámetro `loginRateLimit` (default `{15min, 10}` para compat); `loginLimiter` deja de estar hardcodeado.
*   **`rateLimiter.ts`:** mensaje neutral (`"Demasiadas peticiones. Reintente en N segundos."` — servía a ambos limiters, decía "de autenticacion" siempre); añade cabecera `Retry-After`.
*   **`environment.ts`:** valida `LOGIN_RATE_LIMIT_WINDOW_MS`/`LOGIN_RATE_LIMIT_MAX`; default de `RATE_LIMIT_MAX_REQUESTS` `100 → 300`.
*   **`.env.example` / `docker-compose.yml` / `infrastructure/opentofu/main.tf`:** las 2 vars nuevas + default `300`.
*   **Frontend `errorMessageMapper.ts`:** caso `429` propaga el `detail` del servidor (mismo patrón que `403`/`409`/`422`); de paso el mapper se refactoriza a un `HTTP_STATUS_MAP` + helpers (`preferServerMessage`, `mapPlainError`) porque añadir una rama disparaba el gate de complejidad de `mapToUserFriendlyError` (33 → 8; −2 warnings preexistentes).

**Fuera de alcance (decisión explícita):** quitar `ports: "3000:3000"` del backend en `docker-compose.yml` — rompería `workflows/09_live_stack_verification`, y con la lista de subredes de `trust proxy` el puerto directo ya no es un vector.

## ✅ Criterios de Aceptación & DoD

Respuesta `429` con `title: TooManyRequestsException`, `detail` con segundos reales y cabecera `Retry-After`.
