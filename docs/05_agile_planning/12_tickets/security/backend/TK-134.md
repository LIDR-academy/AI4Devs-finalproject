# 🎟️ TK-134: Refresh de Seguridad Pre-Entrega — `fast-uri`/`mysql2` + Base Alpine

> [📖 Índice](../../indice_tickets.md)

## 📝 Descripción

**Remediación técnica** (carve-out C-DEV-006-4, patrón `TK-064` de re-verificación de seguridad). Al correr `ci_local.sh` (TK-063) antes del push de la entrega final, el Job 2 (Security) falló en 3 pasos con CVEs **publicadas en septiembre de 2026** (posteriores a Entrega 2). El PR de la entrega correría contra el mismo `ci.yml` y fallaría igual.

## 🔀 Alcance

### gitleaks (falsos positivos)
*   `.gitleaksignore`: +6 fingerprints — cadenas literales `test-secret-*` / `test_jwt_secret_*` usadas como `jwtSecret`/`masterSecret` en 6 archivos de test añadidos desde Entrega 2. Ninguna es un secreto real (los tests corren `NODE_ENV=test`; la env var real la exige `getEnvironment()` con Fail-Fast en prod). Misma convención del proyecto (fingerprint exacto, nunca regla completa).

### trivy — backend (5 HIGH, paquetes npm)
| Paquete | CVE / GHSA | Ruta |
| :-- | :-- | :-- |
| `fast-uri` 3.1.5 | CVE-2026-75899 / -75931 / -75975 / -76172 (SSRF, host-confusion) | `prisma@7 > mysql2 > ajv > fast-uri` |
| `mysql2` 3.15.3 | GHSA-3f6p-5ww8-9rcr (auth downgrade → fuga de credenciales en claro) | `prisma@7 > mysql2` (Prisma 7 lo lista como `dependencies` fija, junto a `postgres`; el proyecto es PostgreSQL, `mysql2` nunca se carga) |

*   `package.json` `pnpm.overrides`: `"mysql2": "^3.22.0"` → resuelve `3.24.4`; `"fast-uri": "^3.1.6"` → resuelve `3.1.7`.
*   `check_dependency_audit.sh`: se **eliminan** de `ALLOWED_GHSAS` los 5 advisories de `mysql2`/`fast-uri` (evaluados 2026-09-03 como "riesgo residual aceptado") — ya no aplican; si reaparecieran el gate debe fallar, no dejarlos pasar.

### trivy — frontend (9 HIGH, paquetes de SO del base)
`nginx:stable-alpine` (Alpine 3.24) estaba limpio en Entrega 2; nuevos disclosures en `libcrypto3` (OpenSSL DoS, CVE-2026-14456) y `libuuid`/`util-linux` (7 CVEs de TOCTOU/SUID en `mount`/`nsenter` — no explotables en un nginx non-root, pero trivy falla por severidad).

*   `apps/frontend/Dockerfile` stage `runner`: `RUN apk --no-cache upgrade` — trae los paquetes de SO parcheados aunque la capa cacheada del base tag no los tenga.
*   `apps/backend/Dockerfile` stage `runner`: mismo `apk --no-cache upgrade` (el base backend está limpio hoy, pero los CVEs de SO se acumulan — belt-and-braces determinista).

## ✅ Criterios de Aceptación & DoD

1. `gitleaks detect` → `no leaks found`.
2. `docker build` de ambas imágenes + `trivy image --severity CRITICAL,HIGH --exit-code 1` → **0 HIGH/CRITICAL** en ambas (verificado local: `restostock-backend:tk134` y `restostock-frontend:tk134`, alpine 3.24.1, clean).
3. `check_dependency_audit.sh` → solo los 2 residuales dev-only (vite/vitest) que ya estaban.
4. `pnpm test` / `pnpm build` / `pnpm lint` verdes (mysql2 nunca se carga; fast-uri es un patch).
5. `ci_local.sh` completo → los 3 jobs verdes.
6. **Commit:** `fix(security): pre-delivery CVE refresh — fast-uri/mysql2 overrides + Alpine base upgrade (TK-134)`.

## 📌 Notas

*   Fix upstream real de la cadena `mysql2`: que Prisma no arrastre el driver de MySQL para datasources no-MySQL. El override es la mitigación hasta entonces; sin coste (mysql2 no se ejecuta).
*   `mutation testing` sigue omitido en `ci_local.sh` (informativo en CI, no bloqueante).
