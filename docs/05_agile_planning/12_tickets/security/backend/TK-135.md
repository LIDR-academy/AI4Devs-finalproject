# 🎟️ TK-135: `CLIENT_ORIGIN` / `ENCRYPTION_KEY` vacíos abortan el arranque en `docker compose`

> [📖 Índice](../../indice_tickets.md)

## 📝 Descripción

**Remediación técnica** (carve-out C-DEV-006-4). Al correr el smoke test de pila completa de la Fase 0.2 de pre-entrega (`docker compose up` con `NODE_ENV=production`, antes del push del 2026-09-10), el contenedor `restostock_backend` **no arrancó** — reinicio en bucle con:

```
Error de configuracion de entorno Fail-Fast (Guard 14): {
  "CLIENT_ORIGIN": { "_errors": [ "CLIENT_ORIGIN debe ser una URL válida." ] }
}
```

### Causa raíz

`docker-compose.yml` pasa `CLIENT_ORIGIN: ${CLIENT_ORIGIN:-}` y `ENCRYPTION_KEY: ${ENCRYPTION_KEY}`. Cuando el operador no define esas variables (ambas legítimamente opcionales — `CLIENT_ORIGIN` lo es incluso en producción, ver nota de `environment.ts` de `TK-133`), Compose **inyecta la variable como cadena vacía**, no como ausente. El `.optional()` de zod sólo acepta `undefined`; `"".url()` y `"".min(16)` fallan la validación de **formato** antes de que `.optional()` tenga oportunidad de aplicar → Guard 14 aborta el arranque.

Regresión introducida por `TK-133` (`AUDIT-SEC-004`) al añadir los dos campos opcionales. `TK-133` no se reabre (conserva su commit atómico); el fix es este ticket nuevo.

## 🔀 Alcance

*   `apps/backend/src/infrastructure/config/environment.ts`: helper `optionalEnv(schema)` que preprocesa `'' → undefined` antes de `schema.optional()`. Aplicado a `ENCRYPTION_KEY` y `CLIENT_ORIGIN` (los únicos dos opcionales tipo `string` con validación de formato; el resto son `.default(...)`).
*   `apps/backend/src/infrastructure/config/environment.test.ts`: +2 tests — `CLIENT_ORIGIN: ''` no lanza; `ENCRYPTION_KEY: ''` en producción aborta por **obligatorio** (mensaje `ENCRYPTION_KEY es obligatorio`), no por longitud.

`docker-compose.yml` se deja como está: `${VAR:-}` es idiomático y el schema es la capa correcta para normalizar «presente pero vacío».

## ✅ Criterios de Aceptación & DoD

1. `docker compose up` con `CLIENT_ORIGIN` sin definir y `NODE_ENV=production` → `restostock_backend` llega a `healthy`. **Verificado local.**
2. `ENCRYPTION_KEY` vacío en producción → sigue abortando (Fail-Fast intacto), ahora con el mensaje de «obligatorio».
3. `environment.test.ts` verde (7 → 9 tests); `app.test.ts` verde.
4. `pnpm --filter @restostock/backend build` / `lint` verdes.
5. **Commit:** `fix(config): treat empty CLIENT_ORIGIN / ENCRYPTION_KEY as absent (TK-135)`.
