# 🎟️ TK-136: Barrido de CVEs de Dependencias en la Ventana Pre-Push (`js-yaml`)

> [📖 Índice](../../indice_tickets.md)

## 📝 Descripción

**Remediación técnica** (carve-out C-DEV-006-4, continuación de `TK-134`). Al correr `ci_local.sh` **completo** (los 3 jobs) tras cerrar la Fase 1 de pre-entrega, el paso *Dependency Vulnerability Audit* del Job 2 falló con un advisory **nuevo**, publicado después de `TK-134`:

| Advisory | Paquete | Severidad | Cadena |
| :-- | :-- | :-- | :-- |
| `GHSA-2883-xcg3-v3hh` | `js-yaml` `4.3.1` (`>=4.0.0 <4.3.2`) | HIGH — `maxTotalMergeKeys` no limita el uso de CPU con *merge sources* vacías (ReDoS / CPU-DoS) | `eslint@9 > @eslint/eslintrc > js-yaml` — **solo devDependency** |

`js-yaml` entra exclusivamente por `eslint`/`typescript-eslint`; nunca está en el *bundle* de producción ni procesa entrada no confiable (solo parsea nuestros propios ficheros de configuración al lintar). Riesgo real en este proyecto: nulo. Aun así el gate falla por severidad, y el PR correría contra el mismo `check_dependency_audit.sh`.

## 🔀 Alcance

*   `package.json` `pnpm.overrides`: `"js-yaml": "^4.3.2"` (parche mínimo; `4.3.2` es la versión con el fix). `pnpm-lock.yaml` regenerado.
*   Sin cambios en `check_dependency_audit.sh` — no se añade el GHSA a `ALLOWED_GHSAS` porque el override lo elimina de raíz (preferido sobre aceptar riesgo residual, mismo criterio que `TK-134` con `fast-uri`/`mysql2`).

## ✅ Criterios de Aceptación & DoD

1. `pnpm audit --audit-level=high` → HIGH baja de 3 a 2 (los 2 restantes + 2 CRITICAL son los residuales dev-only ya documentados: `esbuild`/`vite`/`vitest`, `GHSA-fx2h-pf6j-xcff` / `GHSA-5xrq-8626-4rwp`).
2. `check_dependency_audit.sh` → exit 0 («todas dentro del riesgo residual documentado»).
3. `pnpm -r run lint` / `build` verdes (`js-yaml` solo lo usa eslint).
4. `ci_local.sh` completo → los 3 jobs verdes.
5. **Commit:** `fix(security): bump js-yaml past GHSA-2883-xcg3-v3hh (TK-136)`.
