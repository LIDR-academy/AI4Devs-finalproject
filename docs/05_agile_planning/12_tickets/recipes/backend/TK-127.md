# 🎟️ TK-127: Deuda de Calidad y Eficiencia del Módulo de Recetas (AUDIT-DEV-007 G-C)

> **Navegación:** [📖 Índice de Tickets](../../indice_tickets.md) | [🛡️ AUDIT-DEV-007](../../../../audits/AUDIT-DEV-007-recipes-module-quality-report.md)

---

## 📝 Descripción

Remediación técnica del grupo **G-C** de `AUDIT-DEV-007` — deuda menor de calidad y eficiencia:

* **F-8** — `CreateRecipeUseCase` genera UUIDs con `crypto.randomUUID()` directo en la capa de aplicación (misma clase que `AUDIT-DEV-006` F-3, no cubierta por `TK-099`/`TK-101`) y valida los insumos en un loop secuencial `await` (N+1).
* **F-10** — el schema Zod de `POST /recipes` acepta `quantity` como string sin validar formato (`"abc"` pasa Zod y revienta en `new DecimalQuantity` → 500), sin tope de nº de ingredientes ni de longitud de `name`/`description`, sin rechazo de `insumoId` duplicado en la misma receta.
* **F-5** — la rama `update` del `upsert` de `PrismaRecipeRepository.save` no persiste `ingredients` (trampa latente para el primer `PUT`).
* **F-7 (parcial)** — `IRecipeRepository` solo expone `findAll()`; el ranking de rescate carga **todo** el catálogo para quedarse con 3.

*   **ID US Relacionada:** `N/A (Técnico)` — enmarcado en `US-023`/`US-035`. Test decisivo Guard 26: el contrato HTTP no cambia de forma (el listado sigue devolviendo un array; el alta sigue devolviendo `{message, recipeId}`). F-10 endurece la validación de entradas ya malformadas: un `quantity` no numérico pasa de `500` a `422`, y una receta con dos líneas del mismo `insumoId` pasa de `201` a `422` — endurecimiento de comportamiento mal implementado (carve-out C-DEV-006-4), no regla de negocio nueva. Sin cambios en `openapi.yaml` (el Zod queda **más estricto** que el `DecimalString` genérico del contrato, como exige `backend_rules.md §3` para la escala física `Decimal(12,4)`).
*   **Módulo:** `recipes` · **5 SP** · **Should Have** · **Prerrequisitos:** TK-125, TK-126.

## 🔀 Alcance de Modificación

### Domain
*   **`domain/recipes/repositories/IRecipeRepository.ts`:** `+ findByInsumoIds(insumoIds: string[]): Promise<Recipe[]>` — recetas con al menos un ingrediente en el conjunto. (**F-7**)

### Application
*   **`application/recipes/use-cases/CreateRecipeUseCase.ts`:** constructor `+ idGenerator: IdGenerator`; `recipeId = idGenerator.next('rec')`, ingredientes `idGenerator.next('ri')`; validación de insumos con `Promise.all` en vez de loop secuencial. (**F-8**)
*   **`application/recipes/use-cases/SuggestRescueRecipesUseCase.ts`:** `buildCatalogProposals` usa `recipeRepo.findByInsumoIds([...atRiskInsumoIds])` en vez de `findAll()` (y elimina el filtro redundante `matching.length === 0`, ya garantizado por la query). (**F-7**)

### Infrastructure
*   **`infrastructure/recipes/repositories/PrismaRecipeRepository.ts`:** implementa `findByInsumoIds` (`where: { ingredients: { some: { insumoId: { in } } } }`); la rama `update` del `upsert` de `save` reconstruye ingredientes (`deleteMany: {}` + `create: [...]`). (**F-5**, **F-7**)
*   **`infrastructure/recipes/repositories/InMemoryRecipeRepository.ts`:** implementa `findByInsumoIds` (filtro en memoria).
*   **`infrastructure/recipes/http/controllers/recipes.controller.ts`:** `createRecipeSchema` endurecido — `quantity`: `z.union([z.number().positive().finite(), z.string().regex(/^\d{1,8}(\.\d{1,4})?$/).refine(v => parseFloat(v) > 0)])`; `name` `max(120)`, `description` `max(500)`, `ingredients` `max(50)`, `.superRefine` que rechaza `insumoId` duplicado (`ValidationError` → 422). (**F-10**)
*   **`infrastructure/recipes/http/routes/recipes.routes.ts`:** inyecta `cryptoIdGenerator` a `CreateRecipeUseCase`.
*   **`infrastructure/http/app.ts`:** wiring si aplica.

**Fuera de alcance (deuda registrada):** paginación del endpoint `GET /recipes` (cambia el contrato → requiere decisión de producto); N+1 de `GetRecipeAvailabilityUseCase` / `ConsumeRecipeUseCase` (requiere métodos batch en `IInsumoRepository` / `IRemanenteQueryRepository`, módulos `stock`/`kitchen`); F-1/F-16 (G-D). Sin cambios en `schema.prisma` ni `openapi.yaml`.

## ⚠️ Mitigación de Riesgos

1. **Regresión de `ManageRecipes.test.ts`:** los `quantity: '0.150'` de los tests existentes satisfacen el nuevo regex; 201/404/403/401/400 se conservan. Se añaden casos 422 para `quantity` no numérico y para `insumoId` duplicado.
2. **`findByInsumoIds` con lista vacía** (sin insumos en riesgo): debe devolver `[]` sin traer nada — test dedicado.
3. **`PrismaRecipeRepository` sin test unitario** (patrón del proyecto): el fix de `save` update se cubre con un test de `InMemoryRecipeRepository` que verifica que re-guardar una receta reemplaza sus ingredientes, más una nota en el ticket de que el camino Prisma se valida en el smoke de despliegue.
