# 🎟️ TK-131: Edición y Baja de Recetas (`PUT` / `DELETE /api/v1/recipes/:id`) — US-037

> **Navegación:** [⬅️ US-037](../../../11_user_stories/catalog/US-037_edicion_baja_receta.md) | [📖 Índice de Tickets](../../indice_tickets.md)

---

## 📝 Descripción

`PUT /api/v1/recipes/:id` (editar) y `DELETE /api/v1/recipes/:id` (soft-delete, `isActive = false`), ambos solo ADMIN. La composición no se puede editar si la receta tiene una `RecipePreparation` `CLOSED`. Las recetas dadas de baja desaparecen del listado, del ranking de rescate y de la disponibilidad. Cierra `AUDIT-DEV-012` C-2 y la deuda de `US-012` §[N].

*   **Módulo:** `recipes` · **8 SP** · **Should Have** · **Prerrequisitos:** `TK-103` (`RecipePreparation`), `TK-127` (`findByInsumoIds`).

---

## 🔀 Alcance de Modificación

### Domain
*   **`domain/recipes/entities/Recipe.ts`:** `+ isActive` (6º param, `= true`). `withDetails({ name?, category?, description?, ingredients? })` y `deactivated()` — inmutables.
*   **`domain/recipes/repositories/IRecipeRepository.ts`:** `findAll()` / `findById()` / `findByInsumoIds()` devuelven solo **activas** por defecto (parámetro `{ includeInactive?: boolean }` para usos administrativos si hiciera falta — no en este ticket).

### Application
*   **`application/recipes/use-cases/UpdateRecipeUseCase.ts`** (nuevo): `findById` → 404. Valida `insumoId` de la nueva lista (batch, como `CreateRecipeUseCase`). Si el request trae `ingredients` **y** existe una `RecipePreparation` `CLOSED` de esa receta (`prepRepo.findByStatus('CLOSED').some(p => p.recipeId === id)`) → `RecipeCompositionLockedException` (409). `recipe.withDetails(...)` + `save`.
*   **`application/recipes/use-cases/DeactivateRecipeUseCase.ts`** (nuevo): `findById` → 404; `save(recipe.deactivated())`.
*   **`domain/recipes/errors/RecipeCompositionLockedException.ts`** (nuevo, `DomainError`, 409).

### Infrastructure
*   **`PrismaRecipeRepository` / `InMemoryRecipeRepository`:** `save` persiste `isActive`; `findAll`/`findById`/`findByInsumoIds` filtran `isActive: true` (Prisma: `where`; InMemory: `.filter`). `toDomain` lee `isActive`.
*   **`recipes.controller.ts`:** `updateRecipeSchema` (reutiliza el body de alta, todos los campos opcionales + `.strict()`); handlers `updateRecipe` / `deactivateRecipe`.
*   **`recipes.routes.ts`:** `router.put('/:id', requireRole('ADMIN'), controller.updateRecipe)`, `router.delete('/:id', requireRole('ADMIN'), controller.deactivateRecipe)`. Inyecta `recipePreparationRepository` al router (nuevo parámetro, como `kitchen.routes.ts`).
*   **`app.ts`:** pasa `recipePreparationRepo` a `createRecipesRouter`.
*   **`schema.prisma`:** `Recipe.isActive Boolean @default(true)` → migración aditiva.
*   **`openapi.yaml`:** `PUT` + `DELETE /api/v1/recipes/{id}`.

**Fuera de alcance:** hard-delete; reactivar una receta dada de baja (se puede añadir luego); versionado de recetas.
