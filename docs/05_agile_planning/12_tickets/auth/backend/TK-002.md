# 🎟️ TK-002: Implementación de Autenticación de Operarios por PIN

## 📝 Descripción
Este ticket implementa el servicio de autenticación rápida por PIN de 4 dígitos para operarios de cocina. El backend debe verificar el hash del PIN mediante `bcrypt`, retornar un token JWT firmado de corta duración (12h) con los claims del operario (ID, rol, nombre) e incrementar el contador de intentos fallidos.

*   **ID US Relacionada:** `US-001`
*   **Módulo / Vertical Slice:** `auth` (Autenticación y Sesiones)
*   **Estimación (Story Points):** 3
*   **Prioridad MoSCoW:** Must Have
*   **Prerrequisitos:** `TK-001` (Core base)

---

## 🔀 Alcance de Modificación (Hexagonal Layers)
*   **Domain:** Entidad `User` / `Operator`, Value Object `Pin` (preservando ceros a la izquierda) y Vo `PasswordHash`. Interfaz `IUserRepository`.
*   **Application:** Caso de uso `AuthenticateByPinUseCase` con manejo de bloqueo tras 3 intentos fallidos consecutivos.
*   **Infrastructure:** Endpoint REST `POST /api/auth/pin`, esquema Zod `AuthenticatePinSchema` y estrategia JWT Token Provider.

---

## ⚠️ Mitigación de Riesgos Técnicos
1.  **Ataques de Fuerza Bruta en Terminales Públicas:** Implementar un middleware de Rate Limiting o contador en memoria/Redis que bloquee durante 5 minutos la cuenta tras 3 intentos fallidos consecutivos en menos de 60 segundos.
2.  **Truncamiento de Ceros Iniciales:** Tratar el PIN como `string` estricto en el esquema Zod (`z.string().length(4)`), impidiendo que la conversión a número borre ceros a la izquierda (ej. `"0007"`).

---

## ✅ Criterios de Aceptación & DoD (Definition of Done)

@critical @smoke
### Criterio de Aceptación 1: Autenticación exitosa (Happy Path)
*   **Given** un operario "Carlos Gomez" registrado con PIN "1234"
*   **When** invoca `POST /api/auth/pin` con `{ userId: "usr_123", pin: "1234" }`
*   **Then** la API responde `200 OK` con un token JWT válido
*   **And** los claims del token incluyen `userId`, `role: 'OPERATOR'` y expiración `exp` en 12 horas.

### DoD Estricto:
1.  **TDD Compliance:** Tests unitarios de hashing `bcrypt` y firma JWT mapeando los escenarios Gherkin de `US-001` con comentarios `// Given`, `// When`, `// Then`.
2.  **Aserción RFC 7807:** Los flujos de error devuelven un error HTTP estructurado bajo la norma RFC 7807 (`type`, `title`, `status`, `detail`, `code`).
3.  **Seguridad:** No almacenar nunca el PIN en texto plano en la base de datos.
