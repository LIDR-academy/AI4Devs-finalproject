# 🎟️ TK-056: Listado de Operarios (Cierre de Deuda de TK-049)

> **Navegación del Framework SDD:**  
> [⬅️ Volver a US-010 (11_user_stories/auth/US-010.md)](../../../11_user_stories/auth/US-010.md) | [📖 Índice de Tickets (12_indice_tickets.md)](../../indice_tickets.md) | [Siguiente: Matriz de Trazabilidad (13_matriz_trazabilidad.md) ➡️](../../../13_matriz_trazabilidad.md)

---

## 📝 Descripción
`TK-049` documentó explícitamente que el backend no exponía ningún endpoint para listar operarios — `TK-049-FE`/`UserStatusForm.tsx` tuvo que pedir el ID exacto por texto en vez de mostrar una lista seleccionable. Este ticket cierra esa deuda: `GET /api/v1/auth/users` (rol `ADMIN`).

*   **ID US Relacionada:** `US-010`
*   **Módulo / Vertical Slice:** `auth`
*   **Estimación (Story Points):** 2
*   **Prioridad MoSCoW:** Should Have
*   **Prerrequisitos:** `TK-049` (Gestión Mínima de Personal)

---

## 🔀 Alcance de Modificación (Hexagonal Layers)
*   **Domain:** `IUserRepository` gana `findAll(): Promise<User[]>`.
*   **Application:** Nuevo `ListUsersUseCase`.
*   **Infrastructure:** `InMemoryUserRepository.findAll()` (devuelve todos los usuarios sembrados/creados), `PrismaUserRepository.findAll()` (`prisma.user.findMany()`). Endpoint `GET /api/v1/auth/users`, protegido con `authMiddleware` + `requireRole('ADMIN')`.

---

## ⚠️ Mitigación de Riesgos Técnicos
1.  **Fuga de PIN:** la respuesta nunca debe incluir `pinHash` — solo `id`, `name`, `role`, `status`.
2.  **Escalada de Privilegios:** mismo guard de rol `ADMIN` ya usado por `createUser`/`setUserStatus`.

---

## ✅ Criterios de Aceptación & DoD (Definition of Done)

### Criterio de Aceptación 1: Listado real (Happy Path)
*   **Given** que existen operarios creados vía `TK-049`
*   **When** un Administrador invoca `GET /api/v1/auth/users`
*   **Then** la API responde `200 OK` con la lista de operarios (`id`, `name`, `role`, `status`), sin `pinHash`.

### DoD Estricto:
1.  **TDD Compliance:** tests cubriendo listado poblado, lista vacía, 403 sin rol ADMIN, 401 sin token, y que la respuesta nunca exponga `pinHash`.
2.  **Contrato Sincronizado:** `openapi.yaml` actualizado con el endpoint nuevo.
