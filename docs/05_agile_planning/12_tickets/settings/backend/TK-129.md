# 🎟️ TK-129: Saneamiento del Módulo de Configuración de IA (AUDIT-DEV-012 L-3/L-4/L-5)

> **Navegación:** [📖 Índice de Tickets](../../indice_tickets.md) | [🛡️ AUDIT-DEV-012](../../../../audits/AUDIT-DEV-012-ai-config-leakage-and-crud-coverage.md)

---

## 📝 Descripción

* **L-3:** `AiConfiguration.replenishmentOn` y `anomalyAuditOn` son toggles que **no están cableados a ningún código** — ningún caso de uso los lee. `anomalyAuditOn` ni siquiera aparece en la UI. Se eliminan (schema + entidad + repos + use cases + Zod + OpenAPI + frontend). Decisión humana (Guard 28): "Quitarlos hasta que existan".
* **L-4:** `UpdateAiConfigUseCase` y `TestAiConnectionUseCase` importan `CredentialEncryptionService` de `infrastructure/` (misma violación de capa que `AUDIT-DEV-007` F-2). Se introduce el puerto de dominio `ICredentialCipher`; los use cases dependen del puerto. Además usan `process.env.AI_API_KEY` — nombre inconsistente con el resolver de recetas (`GEMINI_API_KEY`/`OPENAI_API_KEY`); se unifica en un helper de aplicación `resolveProviderApiKey(provider)`.
* **L-5:** `TestAiConnectionUseCase` pasa la API key de Gemini en la query string (`?key=…`); se mueve al header `x-goog-api-key` (mismo fix que `TK-126` F-3).

*   **ID US:** `N/A (Técnico)` — cambio de contrato menor: `/settings/ai` GET/PUT pierden 2 campos **inertes** (nadie los consumía para alterar comportamiento). `openapi.yaml` actualizado + bump (oasdiff). Carve-out C-DEV-006-4.
*   **Módulo:** `settings` · **5 SP** · **Should Have** · **Prerrequisitos:** ninguno · **Frontend:** `TK-129-FE`.

## 🔀 Alcance de Modificación

### Domain
*   **`domain/settings/gateways/ICredentialCipher.ts`** (nuevo): `{ encrypt(plain: string): string; decrypt(cipher: string): string }`.
*   **`domain/settings/entities/AiConfiguration.ts`:** elimina `replenishmentOn` / `anomalyAuditOn` de `props`, constructor, `createDefault`, getters.

### Application
*   **`application/settings/resolveProviderApiKey.ts`** (nuevo, helper puro): `resolveProviderApiKey(provider): string | null` — `GEMINI` → `process.env.GEMINI_API_KEY`, resto → `process.env.OPENAI_API_KEY`. Único punto que lee esas env vars en el módulo settings.
*   **`GetAiConfigUseCase.ts` / `UpdateAiConfigUseCase.ts`:** DTO/request sin los 2 campos; `hasApiKey` usa `resolveProviderApiKey`. `UpdateAiConfigUseCase` tipa su dependencia como `ICredentialCipher`.
*   **`TestAiConnectionUseCase.ts`:** tipa `ICredentialCipher`; `resolveApiKey` usa `resolveProviderApiKey`; `buildProbeRequest` para GEMINI → header `x-goog-api-key`, sin `?key=`.

### Infrastructure
*   **`infrastructure/security/CredentialEncryptionService.ts`:** `implements ICredentialCipher` (sin cambio de lógica).
*   **`PrismaAiConfigurationRepository.ts` / `InMemoryAiConfigurationRepository`:** sin los 2 campos.
*   **`aiSettings.schemas.ts`:** `updateAiConfigSchema` sin `replenishmentOn` / `anomalyAuditOn`.
*   **`schema.prisma`:** `AiConfiguration` sin las 2 columnas → migración `DROP COLUMN` ×2.
*   **`openapi.yaml`:** `AiConfigurationResponse` / `UpdateAiConfigurationRequest` sin los 2 campos; bump de versión documentado.

**Fuera de alcance:** implementar reposición/auditoría con IA (épica aparte); anonimización del modo CREATIVE (L-1/L-2 — riesgo residual aceptado por el humano); refactor del resolver de credenciales de recetas (ya hecho en TK-125).
