# 🎟️ TK-141: Cabeceras de seguridad y CSP en el `nginx` que sirve el SPA

> [📖 Índice](../../indice_tickets.md) | [⬅️ ADR-005](../../../../02_architecture_design/adr/ADR-005-session-token-storage.md)

## 📝 Descripción

**Remediación técnica** (carve-out C-DEV-006-4). Al enmarcar [`ADR-005`](../../../../02_architecture_design/adr/ADR-005-session-token-storage.md) se midió la superficie XSS real y apareció un hallazgo colateral: **`apps/frontend/nginx.conf` no emitía ni una sola cabecera de seguridad** (`0 add_header` verificado). El backend sí está cubierto por `helmet`, pero el SPA — que es donde vive el token de sesión — se servía a pelo.

Es el hardening **ortogonal y más barato** disponible: acota el daño de una eventual inyección sin tocar la autenticación, y sigue siendo válido después de que `TK-140` mueva el token a cookie `httpOnly`.

## 🔀 Alcance

`apps/frontend/nginx.conf` — cabeceras `always` en `location /` y `location /assets/`:

| Cabecera | Valor |
| :--- | :--- |
| `Content-Security-Policy` | ver abajo |
| `X-Content-Type-Options` | `nosniff` |
| `Referrer-Policy` | `no-referrer` |
| `X-Frame-Options` | `DENY` |
| `Permissions-Policy` | `camera=(self), microphone=(), geolocation=(), payment=()` |

**CSP calibrada contra el build real, no por plantilla:**

| Directiva | Por qué ese valor |
| :--- | :--- |
| `script-src 'self'` | El bundle de Vite es un módulo del mismo origen; `dist/index.html` no tiene ningún `<script>` inline. **Aquí está el cierre que importa.** |
| `style-src … 'unsafe-inline'` | Exigido por la excepción (a) del Guard 29: `style={{ '--bar-pct': … }}` en `ReportsDashboard.tsx:180` y `FEFOInventoryHealthBar.tsx:36`. Sin esto las barras de progreso pierden su ancho. |
| `https://fonts.googleapis.com` / `gstatic.com` | Big Shoulders Display + IBM Plex (`TK-081-FE`), cargadas desde `index.html`. |
| `blob:` en `img/media/worker-src` | `@zxing/browser` usa `createObjectURL` para el stream del escáner (`US-032`). |
| `connect-src 'self'` | La API va por `/api/` en el **mismo origen** (mismo hecho que decide `ADR-005`). |
| `frame-ancestors 'none'` | Anti-clickjacking en tablet compartida. |

**`location /api/` se deja deliberadamente SIN cabeceras propias:** el backend ya emite las suyas con `helmet`, incluida una CSP relajada específica para Swagger UI (`app.ts:167`). Una segunda CSP desde nginx haría que el navegador aplicara la **intersección** de ambas y rompería Swagger. En nginx las cabeceras del `server` no se heredan si el `location` define las suyas, así que basta con no declararlas ahí.

## ✅ Criterios de Aceptación & DoD

Verificado **contra la imagen real construida y corriendo** (`rules/04_verified_implementation_standard.md`, Antipatrón B — no por inspección del fichero):

1. `GET /` devuelve las 5 cabeceras. ✅
2. El SPA sigue sirviéndose (`<div id="root">` presente). ✅
3. Fallback SPA intacto: `GET /estaciones` → `200`, no 404. ✅
4. Los assets con hash de Vite siguen resolviendo y llevan las cabeceras. ✅
5. `GET /api/v1/health` a través del proxy **no** lleva CSP de nginx (0 coincidencias) → `helmet` pasa intacto. ✅
6. `Permissions-Policy` permite `camera=(self)` — un `camera=()` por defecto habría roto `US-032` en producción sin que ningún test lo detectara. ✅
7. **Commit:** `fix(security): add CSP and security headers to SPA nginx (TK-141)`.

## 📌 Notas

*   **Sí entra antes del push** (decisión del humano, 2026-09-09): es aditivo, no toca autenticación ni lógica de negocio, y se verificó end-to-end contra la imagen real.
*   No sustituye a [`TK-140`](../../auth/frontend/TK-140.md): mientras el token siga en `localStorage`, la CSP **reduce** la probabilidad de que un XSS ocurra, pero no impide que lo exfiltre si ocurre. Son capas complementarias.
