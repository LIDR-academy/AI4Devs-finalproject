# 🎟️ TK-137: Test unitario directo para `Temperature.ts` (mutantes sin cobertura)

> [📖 Índice](../../indice_tickets.md)

## 📝 Descripción

**Remediación técnica** (carve-out C-DEV-006-4). La auditoría de preparación para producción (`docs/00_stack_manifest.md` §5, nota del 2026-09-06) encontró como hallazgo colateral que el value object `Temperature` (`US-033`/`TK-120`) **no tiene test unitario propio** — solo se ejercita indirectamente desde `RecordTemperatureLogUseCase.test.ts`, que construye la temperatura con valores válidos pero nunca cubre:

- la guarda `!parsed.isFinite()` (línea 16-18) — `Infinity` / `NaN`,
- `toNumber()`,
- `toDecimal()`.

Corrida real de Stryker sobre `Temperature.ts` (2026-09-09): **60 % de score**, con **4 mutantes `no coverage`** correspondientes exactamente a esos tres puntos.

`Temperature.ts` no se reabre ni se modifica (conserva su commit atómico de `TK-120`); este ticket añade solo el test.

## 🔀 Alcance

*   **`apps/backend/src/domain/kitchen/value-objects/Temperature.test.ts`** (nuevo, co-locado — `.agents/rules/02_testing_architecture_standard.md`): 6 casos —
    - formato a 2 decimales exactos (no 3, que es el de cantidades físicas),
    - lectura negativa legítima de congelador (`-18.00°C`) — el caso que motivó no reutilizar `DecimalQuantity`,
    - precisión arbitraria preservada + `toDecimal()` devuelve el `Decimal` real,
    - entrada `Decimal` ya construida,
    - `isLessThanOrEqualTo` en ambos sentidos + igualdad,
    - rechazo de no finitos (`Infinity`, `-Infinity`, `NaN`) y de string no numérico.
