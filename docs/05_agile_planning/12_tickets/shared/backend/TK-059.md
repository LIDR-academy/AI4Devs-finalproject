# 🎟️ TK-059: Fix de Conectividad Frontend↔Backend en Despliegue Dockerizado

## 📝 Descripción
Ticket técnico puro (bugfix de infraestructura) — sin cambio de comportamiento de negocio. Auditoría de código muerto (`knip`) sobre todo el repo detectó que `apps/frontend/src/config/env.ts` (validación Zod de `VITE_API_URL`) no tenía ningún importador real. Investigado el porqué: `apps/frontend/src/shared/http/apiClient.ts` siempre llamó a rutas relativas fijas (`/api/v1/...`), y el nginx que sirve el build de producción (`apps/frontend/Dockerfile`) no tenía ningún `location /api` que las reenviara al backend — solo servía estáticos. En `docker-compose.yml` e `infrastructure/opentofu/main.tf`, frontend (puerto 80) y backend (puerto 3000) quedan expuestos como servicios independientes del host, sin reverse-proxy entre ellos: un navegador real contra el puerto 80 nunca llegaba a la API (404/HTML de nginx en vez de la respuesta del backend).

## 🔀 Alcance de Modificación (Hexagonal Layers)
*   **Infrastructure/Deploy:** nuevo `apps/frontend/nginx.conf` con `location /api/ { proxy_pass http://backend:3000; }`, copiado en `apps/frontend/Dockerfile` (reemplaza el `sed` que solo cambiaba el puerto de escucha). `infrastructure/opentofu/main.tf` gana `aliases = ["backend"]` en el `docker_container.backend` para que el hostname `backend` resuelva igual que en `docker-compose.yml` (que ya lo genera implícitamente por nombre de servicio).
*   **Frontend:** `apps/frontend/src/config/env.ts` eliminado (dead code — el cliente HTTP nunca lo usó); dependencia `zod` retirada de `apps/frontend/package.json` al quedar sin otro consumidor; `VITE_API_URL` retirado de `apps/frontend/.env.example` (documentaba una variable sin efecto real).
*   **Limpieza adyacente (mismo commit, detectada por la misma auditoría de `knip`):** `apps/frontend/src/features/catalog/components/CreateInsumoForm.tsx` eliminado — huérfano (cero importadores, cero tests) desde que `ba79ed9` quitó la pestaña "Alta de Insumo" en favor del modal "Inventario de Bodega"; `@testing-library/user-event` (devDependency sin uso) retirado.

---

## ⚠️ Mitigación de Riesgos Técnicos y Decisión de Alcance
1.  **Alcance explícito:** no se conecta `VITE_API_URL` de verdad (alternativa descartada con el humano) — se opta por proxy nginx same-origin, que evita CORS y mantiene un único origen público. `env.ts`/`VITE_API_URL` quedan sin razón de ser tras el fix, de ahí su eliminación en el mismo commit.
2.  **Consistencia entre despliegues:** el alias `backend` se añadió también en OpenTofu (no solo en Compose) para que `nginx.conf` funcione igual en ambos, evitando un hostname hardcodeado que solo sirviera a uno de los dos.

## ✅ Criterios de Aceptación & DoD (Definition of Done)

@critical @smoke
### Criterio de Aceptación 1: El navegador llega al backend a través del frontend dockerizado
*   **Given** el stack completo levantado con `docker compose up --build` (o el equivalente OpenTofu)
*   **When** un cliente HTTP hace `POST /api/v1/auth/login-pin` contra el puerto público del frontend (no contra el backend directamente)
*   **Then** la respuesta es un 200 con `accessToken` real emitido por el backend, no un 404/HTML servido por nginx.

### DoD Estricto:
1.  **Verificado en vivo, no solo leído:** `docker compose up --build` real, `curl` contra el puerto del frontend a `/api/v1/auth/login-pin` (200 + JWT real) y a un endpoint autenticado `/api/v1/stock/insumos` con el token (200 + JSON), ambos a través del proxy. Entorno de prueba (`.env` temporal, contenedores, volumen de Postgres) descartado por completo al terminar, mismo criterio que `TK-051`.
2.  **Cero código muerto residual:** `npx knip` ya no lista `env.ts`, `CreateInsumoForm.tsx`, `zod` ni `@testing-library/user-event`.
3.  **Tests:** 80/80 backend + 81/81 frontend en verde (sin tests nuevos — bugfix de infraestructura, no de comportamiento de aplicación).
4.  **Build/Lint:** 0 errores (mismos 2 *warnings* preexistentes de `max-lines-per-function`, no tocados por este ticket).
