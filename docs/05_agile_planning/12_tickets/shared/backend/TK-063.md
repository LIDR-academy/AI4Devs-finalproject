## 📝 Descripción
Ticket técnico puro (tooling de desarrollo) — sin cambio de comportamiento de negocio. El cierre del PR de Entrega 2 requirió 4 rondas de fallos de CI descubiertos recién en GitHub Actions (generación de cliente Prisma faltante, tag inexistente de `trivy-action`, dependencia anidada rota del mismo action, firma inválida de un provider de OpenTofu, y una CVE real transitiva) — cada uno diagnosticado reproduciendo el paso exacto de `ci.yml` a mano, uno por uno. `ci_local.sh` automatiza esa reproducción completa para que los próximos fallos de este tipo se detecten antes del push, no después.

## 🔀 Alcance de Modificación
*   **Script nuevo:** `docs/04_governance_and_quality/scripts/ci_local.sh` — reproduce los 3 jobs reales de `.github/workflows/ci.yml` (`lint-and-validate`, `security-audit`, `test-and-build`) en el mismo orden y con los mismos comandos, invocando los scripts de gate ya existentes (`validate_agents.sh`, `check_iac_syntax.sh`, `check_contract_drift.sh`, `check_env_usage.sh`, `check_dependency_audit.sh`, etc.) en vez de reimplementarlos.
*   **Auto-bootstrap de binarios externos:** `tofu`, `oasdiff` y `gitleaks` se descargan a `.ci-local-tools/` (gitignored) con las mismas versiones pineadas que `ci.yml`, si no están ya instalados — evita que el script falle solo por no tener una herramienta local, igual que CI las instala solo en su propio job.
*   **Flags:** `--quick` (salta el job de seguridad completo — Docker builds + trivy + gitleaks, el más lento, ~4 min); `--with-mutation` (incluye mutation testing, informativo y lento, off por defecto).
*   **Efecto colateral real detectado al validarlo en vivo:** `gitleaks detect --source .` (escaneo completo de historial, distinto del comportamiento incremental de `gitleaks-action` en push/PR) encontró un falso positivo genuino no registrado — un ejemplo de JWT decorativo en `readme.md` (mismo patrón ya documentado en `.gitleaksignore` para otro commit, pero con fingerprint distinto porque `readme.md` se reescribió en `TK-049-FE`). Verificado manualmente contra el valor real (`"eyJhbGciOiJIUzI1NiIsIn..."`, truncado y decorativo) y agregado a `.gitleaksignore` siguiendo el proceso que el propio archivo documenta.

## ⚠️ Mitigación de Riesgos Técnicos y Decisión de Alcance
1.  **Reuso, no reimplementación:** el script invoca los gates ya existentes (`docs/04_governance_and_quality/scripts/*.sh`, `.agents/scripts/*.sh`) en vez de duplicar su lógica — si esos scripts cambian, `ci_local.sh` no queda desincronizado.
2.  **Nunca falla duro por herramienta ausente sin red:** si el auto-bootstrap de `tofu`/`oasdiff`/`gitleaks` falla (sin conexión), el paso correspondiente se omite con un mensaje explícito en vez de abortar todo el script — un desarrollador sin esas herramientas igual obtiene señal de los pasos que sí puede correr (lint, tests, build).
3.  **`--quick` por defecto NO está activado:** el modo completo (incluyendo Docker+trivy+gitleaks) es el comportamiento por defecto, para que "todo en verde localmente" sea una garantía real equivalente a CI, no una versión recortada que dé falsa confianza.

### Criterio de Aceptación 1: Reproduce fielmente el resultado de CI
*   **Given** el estado real de `main` tras el merge de Entrega 2
*   **When** se ejecuta `bash docs/04_governance_and_quality/scripts/ci_local.sh` completo (sin flags)
*   **Then** todos los pasos terminan en verde, igual que los 3 jobs reales de `ci.yml` en GitHub Actions para ese mismo commit.

### DoD Estricto:
1.  **Verificado en vivo, no solo leído:** corrida completa real (`--quick` y sin flags) contra el repo real — no una simulación. Bug real encontrado y corregido en el propio script durante esa verificación (cálculo de `REPO_ROOT` con un nivel de más).
2.  **Cero falsos positivos silenciados sin verificar:** el hallazgo de `gitleaks` se verificó manualmente contra el secreto real antes de agregarlo a `.gitleaksignore` (mismo criterio que exige el propio archivo).
3.  **Tests/build:** sin cambios (herramienta de desarrollo, no toca `src/`) — 88/88 backend + 87/87 frontend siguen en verde.

## 🤖 Instrucciones de Ejecución Autónoma para Agente IA
1. **Fichas creadas/modificadas:**
   - `docs/04_governance_and_quality/scripts/ci_local.sh` (nuevo)
   - `.gitignore` (excluye `.ci-local-tools/`)
   - `.gitleaksignore` (nuevo fingerprint verificado)
2. **Ejecutar el script:** `bash docs/04_governance_and_quality/scripts/ci_local.sh --quick` (rápido) o sin flags (equivalente completo a CI, ~4-5 min)
3. **Comando de Verificación Total:** el propio script es la verificación — no requiere un paso adicional.
