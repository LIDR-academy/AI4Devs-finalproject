# 🎟️ TK-097: Restaurar `prisma migrate deploy` en `docker-entrypoint.sh` (Guard 25)

> **Navegación del Framework SDD:**
> [📖 Índice de Tickets](../../indice_tickets.md)

---

## 📝 Descripción

`apps/backend/docker-entrypoint.sh` aplica el esquema en producción con **`prisma db push --accept-data-loss`**, no con `prisma migrate deploy`.

* **Historia:** el entrypoint nació con `migrate deploy` (`TK-042/043`, commit `3a8e29a`). En `TK-071` (commit `73caab7`) se cambió a `db push` como parche, porque las columnas `User.mustChangePin` (`TK-070`) y `SystemSettings.idleTimeoutMinutes` (`TK-071`) se añadieron a `schema.prisma` sin migración → `migrate deploy` producía un esquema divergente.
* **`TK-094`** (migración `20260903100000_sync_schema_drift`) cerró esa causa raíz: `check_migration_schema_parity.sh` está verde. Pero nadie revirtió el parche del entrypoint.
* **Impacto:** `db push --accept-data-loss` sobre una BD **con datos reales** ejecuta cambios destructivos sin el backfill seguro que sí llevan los archivos de migración (descubierto al desplegar `TK-096`: la migración `20260903230000` re-apunta `MAIN_WAREHOUSE` → sector semilla; `db push` habría intentado añadir `storageLocationId NOT NULL` sin backfill). Viola Guard 25 y OWASP A03 (supply-chain / despliegue reproducible).

## 🔀 Alcance de Modificación

* **`apps/backend/docker-entrypoint.sh`:** `prisma db push --accept-data-loss` → `prisma migrate deploy`. Fail-fast (`set -e` ya activo) con mensaje de diagnóstico: si `migrate deploy` falla porque la BD se gestionaba con `db push` (su `_prisma_migrations` no registra migraciones cuyos cambios ya están presentes), el operador debe hacer **una sola vez** `prisma migrate resolve --applied <migración>` por cada una — no se automatiza el baseline en el entrypoint para no enmascarar drift real.
* **`apps/backend/Dockerfile`:** el comentario del `CMD` ya dice "migrate deploy" — ahora vuelve a ser cierto; sin cambios.
* **`docs/00_stack_manifest.md` §6:** nota histórica documentando el ciclo `migrate deploy` → `db push` (TK-071) → `migrate deploy` (TK-097).
