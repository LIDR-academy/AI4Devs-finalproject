# 🎟️ TK-091: Saneamiento de Duplicación en `auth.controller.ts` (jscpd)

> **Navegación del Framework SDD:**
> [📖 Índice de Tickets](../../indice_tickets.md)

---

## 📝 Descripción
El baseline de `jscpd` subió del 1.68% original a ~3.2% (umbral repo elevado a 3.5% en `US-024` para no bloquear CI por deuda ajena a los tickets en curso). El grueso de esa duplicación está en `apps/backend/src/infrastructure/http/controllers/auth.controller.ts`: bloques casi idénticos de traducción de error a respuesta RFC 7807 repetidos entre los métodos del controlador (`loginPin`, `changePin`, `forgotPin`, `resetPin`, `createUser`, `setUserStatus`, `listUsers`).

Este ticket extrae ese patrón a un helper compartido y devuelve el baseline de `jscpd` por debajo del 3% para poder bajar de nuevo el umbral de `.jscpd.json` a 3.

---

## 🔀 Alcance de Modificación

* **`apps/backend/src/infrastructure/http/`** (o `shared/`): helper `sendProblem(res, error)` / `toProblemDetails(error)` que centraliza el mapeo `Error de dominio → RFC 7807` (`type`, `title`, `status`, `detail`, `instance`) — hoy repetido inline en cada `catch` de `auth.controller.ts`. Reutilizar el patrón/middleware de error ya existente en el proyecto si lo hay; si no, este helper es la primera pieza de esa centralización (candidato a extenderse luego a los otros controladores).
* **`apps/backend/src/infrastructure/http/controllers/auth.controller.ts`:** cada método reemplaza su bloque `catch` duplicado por una llamada al helper. Cero cambio de contrato: mismos `status`, mismo `detail`, mismos códigos.
* **Umbral `jscpd`:** una vez el baseline repo baje de 3%, revertir `.jscpd.json` `threshold` a `3` y actualizar la nota de `docs/00_stack_manifest.md` §5.1.

**Fuera de alcance:** deduplicar los otros controladores (candidato a un ticket de seguimiento si el helper prueba su valor aquí); la deuda de duplicación en `PrismaStockRepository.ts` / `index.css` (clones sueltos de 1 ocurrencia, no concentrados).

---

## ✅ Criterios de Aceptación & DoD

1. **Contrato intacto:** los tests de integración de `auth` (`apps/backend`) pasan sin modificar ninguna aserción — mismos `status`/`detail`/`type` en todas las respuestas de error.
2. **Baseline jscpd < 3%:** `pnpm run duplication` reporta < 3% y `.jscpd.json` vuelve a `threshold: 3`.
3. **TDD:** el helper de mapeo de error tiene tests unitarios propios (entrada = error de dominio conocido, salida = objeto RFC 7807 esperado).
4. **Verificación:** `pnpm test`, `pnpm run build`, `pnpm run lint`, `pnpm run duplication` — 0 errores.
5. **Commit atómico** `refactor(auth): centralize RFC 7807 error mapping in auth controller (TK-091)`.
