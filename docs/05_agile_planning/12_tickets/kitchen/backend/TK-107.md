# 🎟️ TK-107: Catálogo de Motivos de Consumo — CRUD (Backend)

> [⬅️ US-030](../../../11_user_stories/kitchen/US-030.md) | [📖 Índice](../../indice_tickets.md)

## 📝 Descripción
Nueva entidad `ConsumptionReason` (catálogo administrable): `id`, `label`, `isActive`, `createdAt`/`updatedAt`. CRUD mínimo — listar (activos por defecto, todos si `ADMIN` + `includeInactive=true`), crear, editar (`label`/`isActive`). **Desactivar, nunca borrar** (ADR-004 §3.1) — sin endpoint de borrado físico.

*   **US:** `US-030` · **Slice:** `kitchen` · **SP:** 5 · **MoSCoW:** Should Have · **Prioridad:** 🟡 P1 (prerrequisito de `TK-108`/`TK-109`)
*   **Prerrequisitos:** ninguno

## 🔀 Alcance (Hexagonal)

### Domain
*   `domain/kitchen/entities/ConsumptionReason.ts` — `label` no vacío (invariante en constructor).
*   `domain/kitchen/repositories/IConsumptionReasonRepository.ts` — `findAll(includeInactive)`, `findById(id)`, `save(reason)`.

### Application
*   `ListConsumptionReasonsUseCase`, `CreateConsumptionReasonUseCase`, `UpdateConsumptionReasonUseCase`.

### Infrastructure
*   `schema.prisma`: `model ConsumptionReason { id, label, isActive @default(true), createdAt, updatedAt }`. **Migración dedicada** (aprobación humana) — incluye el `INSERT` de la semilla editable (`Preparación de plato`, `Degustación / prueba`, `Cortesía a cliente`, `Error de manipulación`, `Otro`), `ON CONFLICT DO NOTHING` (mismo patrón que el seed de áreas de cocina en `TK-102`).
*   `PrismaConsumptionReasonRepository`, `InMemoryConsumptionReasonRepository`.
*   `consumption-reasons.controller.ts` / rutas: `GET /api/v1/consumption-reasons` (cualquier autenticado; `?includeInactive=true` solo `ADMIN`), `POST` (`ADMIN`), `PUT /:id` (`ADMIN`).
*   `openapi.yaml` / `07_api_specification.md`.

## ✅ DoD
1. **TDD:** listar excluye inactivos por defecto; `includeInactive` solo con rol `ADMIN`; crear rechaza `label` vacío; editar cambia `label`/`isActive` sin afectar el `id`; un motivo desactivado no aparece en el listado activo pero sigue resoluble por `id` (para joins de reportes futuros).
2. RFC 7807 en errores; mutation ≥ 70 % por archivo domain/application.
3. Migración presentada para aprobación humana (AGENTS §3); verificada contra Postgres real.
4. **Commit:** `feat(kitchen): consumption reason catalog CRUD (TK-107)`.

## 📌 Notas de implementación
*   **`requireAdminForInactiveFilter`:** middleware específico de la ruta `GET` que solo exige `ADMIN` cuando `includeInactive=true` está presente — el `GET` simple queda abierto a cualquier autenticado (Escenario 4 de `US-030`), mismo criterio explícito-por-ruta de `TK-093`.
*   **`handleZodOrNext` extraído a `infrastructure/http/utils/responseUtils.ts`:** el manejo de `ZodError → respondValidationError` / resto → `next(err)` estaba duplicado entre este controller y `locations.controller.ts` (jscpd lo detectó dos veces — primero como auto-clon dentro del propio archivo, luego como clon cruzado tras la primera extracción). Se centralizó como utilidad compartida; ambos controllers la importan ahora. Reduce deuda de duplicación preexistente como efecto colateral.
*   **Nombre de archivo `consumption-reasons.controller.ts` (kebab-case, no camelCase):** `check_contract_drift.sh` mapea el segmento de ruta `/api/v1/consumption-reasons` 1:1 contra el nombre de archivo del controller. Es el primer módulo top-level con segmento multi-palabra; se usó kebab-case para que el heurístico del gate matchee sin necesidad de tocar el script generado.
*   **Migración `20260904180000_consumption_reason_catalog`:** `CREATE TABLE` + semilla editable de 5 motivos (`Preparación de plato`, `Degustación / prueba`, `Cortesía a cliente`, `Error de manipulación`, `Otro`) vía `INSERT ... ON CONFLICT DO NOTHING` (mismo patrón que el seed de áreas de cocina de `TK-102`). Verificada contra Postgres 15 real en transacción con `ROLLBACK`; `check_migration_schema_parity.sh` (Postgres efímero) y `check_seed_idempotency.sh` (dos corridas reales, sin duplicar) en verde.
*   **`composition.ts`:** se registró `PrismaConsumptionReasonRepository` — necesario para que el contenedor de producción sirva el catálogo real (sin esto, el endpoint quedaría silenciosamente sobre el repo `InMemory` por defecto de `app.ts`).
*   DoD #2 mutation ≥ 70 % por archivo: verificado (`CreateConsumptionReasonUseCase`, `ListConsumptionReasonsUseCase`, `UpdateConsumptionReasonUseCase`, `ConsumptionReason`, `IConsumptionReasonRepository` — los 5 archivos domain/application tocados, todos ✅ OK, ninguno compensa a otro).
