# 🎟️ TK-103: Agregado `RecipePreparation` y Apertura Automática al Extraer para Receta (Backend)

> [⬅️ US-027](../../../11_user_stories/kitchen/US-027.md) | [📖 Índice](../../indice_tickets.md)

## 📝 Descripción
Introducir el agregado `RecipePreparation` (estado `OPEN`) y abrirlo automáticamente dentro de `RecordExtractionUseCase` cuando `purpose = RECIPE`, etiquetando los remanentes creados. `recipeId` pasa a obligatorio en ese modo. Endpoints de lectura del tablero "preparaciones en curso".

*   **US:** `US-027` · **Slice:** `kitchen` · **SP:** 8 · **MoSCoW:** Should Have · **Prioridad:** 🟢 P2
*   **Prerrequisitos:** `TK-072` (extracción con propósito), `TK-102` (áreas de cocina), `TK-069` (módulo recipes)

## 🔀 Alcance (Hexagonal)

### Domain
*   Nuevo `domain/kitchen/entities/RecipePreparation.ts`: `id`, `recipeId`, `plannedPortions`, `status: OPEN|CLOSED|ABANDONED`, `openedByOperatorId`, `openedAt`, `closedByOperatorId?`, `actualPortions?`, `closedAt?`, `notes?`. Métodos `close(...)` / `abandon()` con guardas de estado.
*   `Remanente`: `+ recipePreparationId: string | null`.
*   `IRecipePreparationRepository` (puerto): `save`, `findById`, `findByStatus`, `findOpenByRecipe`.

### Application
*   `RecordExtractionUseCase` (`purpose = RECIPE`): dentro de `unitOfWork.runExtraction`, además del débito + remanente + movimiento, crea/recupera la `RecipePreparation` (`plannedPortions` del DTO; si el DTO trae `recipePreparationId` existente y `OPEN` → añade a esa) y setea `remanente.recipePreparationId`. `EXTRACTION_RECIPE` referencia la preparación.
*   `RecordExtractionDTO`: `+ plannedPortions?: number`, `+ recipePreparationId?: string`. `recipeId` obligatorio si `purpose = RECIPE` (Zod `.refine`, RFC 7807 `400`).
*   Nuevo `GetOpenPreparationsUseCase` / `GetPreparationDetailUseCase`.

### Infrastructure
*   **`schema.prisma`:** `model RecipePreparation` + `RecipePreparationItem` (este último se llena en TK-104); `Remanente.recipePreparationId String? @db.Uuid` + relación `SetNull`. **Migración dedicada, aprobación humana.**
*   `PrismaRecipePreparationRepository` + `InMemory`.
*   `kitchen.routes.ts` / `kitchen.controller.ts`: `GET /recipe-preparations?status=`, `GET /recipe-preparations/:id`. Rol `ADMIN` + `KITCHEN_STAFF`.
*   `stock.controller.ts`: Zod extendido.
*   `openapi.yaml` / `07_api_specification.md`: nuevos schemas + endpoints; `RecordExtractionRequest + plannedPortions/recipePreparationId`; `RecordExtractionResponse + recipePreparationId`.
*   Governance: schema drift / migration parity / contract drift.

## ✅ DoD
1. **TDD:** apertura de preparación al extraer RECIPE; `recipeId` faltante → `400`; segunda extracción a la misma preparación; `KITCHEN_STOCK`/`DIRECT_DISCARD` no abren nada; `GET ?status=OPEN` filtra.
2. **Atomicidad:** la creación de la preparación ocurre dentro de la misma `runExtraction` (C-DEV-006-1) — si algo falla, no queda una preparación huérfana.
3. **Migración verificada** (docker); mutation ≥ 70 % por archivo domain/application.
4. **Sin regresiones**; contrato documentado.
5. **Commit:** `feat(kitchen): RecipePreparation aggregate opened on recipe extraction (TK-103)`.
