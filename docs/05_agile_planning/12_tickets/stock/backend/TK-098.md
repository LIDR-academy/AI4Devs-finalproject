# 🎟️ TK-098: Integridad Transaccional y Decremento Atómico en Extracción de Bodega (Backend)

## 📝 Descripción
Cerrar los dos defectos **Críticos** de integridad de datos detectados en `AUDIT-DEV-006` sobre `RecordExtractionUseCase`:

* **F-1 — Secuencia de persistencia no atómica:** `insumoRepository.save()`, `remanenteRepository.saveRemanente()` y `recordMovement()` se ejecutan como 3 `await` independientes (3 transacciones separadas en `PrismaStockRepository`). Un fallo intermedio deja stock descontado sin remanente ni movimiento → pérdida silenciosa de inventario y ruptura de la trazabilidad de US-014. La rama `handleDirectDiscard` (deduct + movement) tiene el mismo patrón.
* **F-2 — Race condition / lost update:** el saldo se deduce con read-modify-write (`hasSufficientStockAt` → `deductStockAt` → `save`) y `warehouseStock.upsert` escribe el **valor absoluto**. Dos extracciones concurrentes del mismo sub-sector sobrevenden el stock.

*   **ID US Relacionada:** `US-014` · `US-025`
*   **Módulo / Vertical Slice:** `stock` (Bodega)
*   **Estimación (Story Points):** 8
*   **Prioridad MoSCoW:** Must Have
*   **Prioridad Backlog:** 🔴 P0 - Crítica
*   **Prerrequisitos:** `TK-072`, `TK-096` (modelo multi-sector ya vigente)

## 🔀 Alcance de Modificación (Hexagonal Layers)

### Domain
*   Nuevo puerto `IStockUnitOfWork` (o `withTransaction<T>(work: (ctx) => Promise<T>): Promise<T>`) en `domain/stock/repositories/`. El caso de uso recibe la frontera, no la implementa.
*   `IInsumoRepository`: nuevo método de deducción atómica por línea — `deductStockAtAtomic(insumoId, storageLocationId, quantity): Promise<{ ok: boolean; remainingSectorStock: DecimalQuantity }>` (o firma equivalente que exprese "descontar condicionalmente y devolver el saldo resultante"). El contrato debe permitir a la infraestructura implementarlo como `UPDATE … SET quantity = quantity - :q WHERE quantity >= :q`.
*   `InsufficientStockException` se lanza cuando el `UPDATE` condicional afecta 0 filas (traducción del `count === 0`).

### Application
*   `RecordExtractionUseCase.execute()` y `handleDirectDiscard()`: envolver **todas** las escrituras (`deduct` + `saveRemanente` + `recordMovement`) en una única llamada `withTransaction`. Ante cualquier error, la transacción revierte por completo — sin lógica de compensación manual.
*   La validación previa `hasSufficientStockAt` deja de ser la barrera de saldo (queda como *fail-fast* opcional para el `404`/mensaje temprano); la barrera real es el decremento atómico dentro de la transacción.
*   La respuesta (`remainingSectorStock`, `remainingWarehouseStock`) se calcula a partir del resultado del `UPDATE` atómico, no de un re-`findById` fuera de transacción.

### Infrastructure
*   **`PrismaStockRepository`:**
    *   `withTransaction` implementado con `this.prisma.$transaction(async (tx) => …)`, propagando `tx` a los métodos de escritura (patrón repositorio con cliente transaccional inyectado, ya usado en `save()`).
    *   `deductStockAtAtomic`: `tx.warehouseStock.updateMany({ where: { insumoId, storageLocationId, quantity: { gte: q } }, data: { quantity: { decrement: q } } })`; si `count === 0` → `InsufficientStockException`. Releer la fila para el saldo resultante dentro de la misma `tx`.
    *   `saveRemanente` / `recordMovement` aceptan el cliente `tx` opcional.
*   **`InMemoryStockRepository`:** `withTransaction` = ejecutar el callback y, ante excepción, restaurar un snapshot (`structuredClone` de `insumos`/`remanentes`/`movements` tomado al entrar). `deductStockAtAtomic` reutiliza `Insumo.deductStockAt` (ya atómico por-sector en memoria).
*   Sin cambios de `schema.prisma` (el `WHERE quantity >= :q` + `decrement` no requiere columna nueva; **no** se añade `version` salvo que la revisión de diseño lo prefiera — decisión a documentar en el ticket antes de codificar).

## ✅ Criterios de Aceptación & DoD
1. **TDD (Red-Green-Refactor con InMemory fakes):**
   *   `RecordExtraction.test.ts` — **rollback:** un fake de `IRemanenteRepository.saveRemanente` que lanza tras el `deduct` deja el stock del sub-sector **intacto** y 0 movimientos (hoy este test es 🔴).
   *   **rollback discard:** `recordMovement` que lanza en la rama `DIRECT_DISCARD` deja el stock intacto.
   *   **concurrencia:** dos `execute()` en paralelo sobre `loc-1` con saldo `3.000` y `quantity 2.000` cada una → exactamente **1×201 + 1×`InsufficientStockException`**, saldo final `1.000`, 1 remanente, 1 movimiento (hoy 🔴: ambas pasarían).
   *   **atomicidad happy path:** un `execute()` exitoso deja saldo + remanente + movimiento consistentes (regresión).
2. **Camino Prisma cubierto (F-10):** test de integración con `PrismaStockRepository` contra BD efímera (o el harness de integración existente) que ejercite el decremento condicional y el rollback real de `$transaction`. Si el proyecto no tiene runner de integración con Postgres para stock, documentar la brecha y cubrir el contrato con un fake que verifique que `saveRemanente`/`recordMovement` reciben el mismo `tx`.
3. **Precisión:** toda aritmética de saldo vía `DecimalQuantity` / `Decimal` (Guard 17). El `decrement` de Prisma opera sobre `Decimal` — verificar que no hay coerción a `number`.
4. **RFC 7807:** `InsufficientStockException` → `422` (sin cambio de forma respecto a hoy). Ningún `500` nuevo.
5. **DIP (Guard 18):** el caso de uso recibe `withTransaction` por inyección; las rutas no instancian el cliente Prisma.
6. **Sin regresiones:** `pnpm test`, `pnpm run build`, `pnpm run lint` en verde. Gates acotados al diff (`check_ticket_code_quality`, `check_dead_code`, `check_ticket_duplication`) sin hallazgos nuevos. Mutation score ≥ 70 % en `RecordExtractionUseCase.ts` y el nuevo código de repositorio que no esté excluido por `stryker.conf.json`.
7. **Commit atómico:** `fix(stock): wrap warehouse extraction writes in a transaction with atomic stock decrement (TK-098)`.

## 🧪 Plan de Pruebas
- Unitario: rollback (insumo intacto), rollback discard, concurrencia (paralelo), happy path.
- Integración HTTP: `POST /extraction` feliz + `422` bajo saldo insuficiente (regresión de `RecordExtraction.test.ts`).
- Integración Prisma (si hay harness): `$transaction` revierte ante fallo; `updateMany` condicional devuelve `count 0` cuando el saldo del sector no alcanza.
