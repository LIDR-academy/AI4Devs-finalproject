# 🎟️ Ticket Técnico: TK-074 — Backend Storage Locations API

## 🎯 Objetivo
Cerrar la deuda pendiente de la API CRUD de sectores de almacenamiento (`StorageLocation`): el dominio, los repositorios (`PrismaLocationRepository.ts`, `InMemoryLocationRepository.ts`), los casos de uso (`GetLocationsUseCase`, `CreateLocationUseCase`) y los endpoints `/api/v1/locations` **ya existen**; falta el control de acceso por rol y el `PUT` de update completo.

> **Estado real (auditado):** el CRUD funciona pero `/api/v1/locations` se monta solo con `authMiddleware`, sin `requireRole('ADMIN')` — un `KITCHEN_STAFF` puede crear/editar/borrar sectores vía API directa (gap RBAC, mismo patrón que AUDIT-SEC-001 / TK-093).

---

## 🛠️ Tareas Técnicas
1. Añadir `requireRole('ADMIN')` por ruta a `POST`, `PUT` y `DELETE` de `/api/v1/locations` (patrón `...role('ADMIN')` de `stock.routes.ts`, omitido cuando `isAuthRequired === false`). `GET` permanece accesible a cualquier autenticado.
2. Migrar `registerLocationRoutes` al patrón de inyección por factory usado en `createStockRouter` (Guard 18) y trasladar la validación Zod a respuestas RFC 7807 vía `respondValidationError` (hoy caen a `next(err)` sin formato Problem Details).
3. `GetLocationsUseCase`: devolver también, por sector, un flag `hasStock` (para que el frontend deshabilite el toggle/borrado) — se apoya en el índice `warehouse_stocks(storage_location_id)` de US-025. Si US-096 aún no aplicó el FK, dejar `hasStock: false` y abrir dependencia.
4. Poblar sectores iniciales por defecto en `prisma/seed.ts` de forma idempotente por `name` (*Bodega de Secos*, *Heladera de Carnes*, *Cámara de Congelados*, *Refrigerador Principal Cocina*, *Bodega Principal – Sin clasificar*).
