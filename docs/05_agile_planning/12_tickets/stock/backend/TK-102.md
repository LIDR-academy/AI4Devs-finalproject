# 🎟️ TK-102: Áreas de Cocina como `StorageLocation` y `Remanente.location` → FK (Backend)

> [⬅️ US-026](../../../11_user_stories/stock/US-026.md) | [📖 Índice](../../indice_tickets.md) | [Matriz ➡️](../../../13_matriz_trazabilidad.md)

## 📝 Descripción
Activar las filas `StorageLocation` con `type = KITCHEN` de punta a punta: `Remanente.location` (hoy `String` literal) pasa a FK `storageLocationId`, la extracción acepta un área de cocina de destino elegida del catálogo, y un área de cocina con remanentes activos no puede borrarse/desactivarse. Prerrequisito de ADR-003 (US-027/US-028).

*   **US:** `US-026` · **Slice:** `stock` · **SP:** 8 · **MoSCoW:** Should Have · **Prioridad:** 🟢 P2
*   **Prerrequisitos:** `TK-074` (CRUD `StorageLocation`), `TK-096` (patrón multi-sector)

## 🔀 Alcance (Hexagonal)

### Domain
*   `Remanente`: `location: string` → `storageLocationId: string`. El VO/entidad expone `storageLocationId`; los use-cases dejan de pasar literales.
*   Nueva regla (Invariante 1-ter): `StorageLocation type = KITCHEN` con algún `Remanente` `ACTIVE` es indeleble/indesactivable → reusar `LocationHasStockException` (o análoga `LocationHasRemanentesException`).

### Application
*   `RecordExtractionDTO`: `toLocation: string` (literal) → `toStorageLocationId: string` (FK, requerido para `KITCHEN_STOCK`/`RECIPE`). El use-case valida que sea un `StorageLocation` `type = KITCHEN` activo (→ `EntityNotFoundException`).
*   `GetActiveRemanentesUseCase` y demás lecturas: devolver `storageLocationId` + `storageLocationName` (join).
*   `Get/Delete/Update` de `StorageLocation`: comprobar remanentes activos → `409`.

### Infrastructure
*   **`schema.prisma`:** `Remanente.location String` → `storageLocationId String @db.Uuid` + relación `storageLocation StorageLocation @relation(..., onDelete: Restrict)` + `@@index`. `StorageLocation` gana `remanentes Remanente[]`.
*   **Migración Prisma dedicada** (`prisma migrate dev --name remanente_location_fk`): (1) filas semilla `StorageLocation` `type = KITCHEN` para `KITCHEN_FRIDGE` / `KITCHEN_PREP` / `KITCHEN_LINE` (+ `WASTE_BIN`? decisión: `WASTE_BIN` sigue siendo literal, no es ubicación física); (2) `storage_location_id` nullable; (3) `UPDATE remanentes SET storage_location_id = <semilla>`; (4) `NOT NULL` + FK; (5) `DROP COLUMN location`. **Aprobación humana del archivo (AGENTS §3).**
*   `PrismaRemanenteQueryRepository` / `PrismaStockRepository`: leer/escribir la FK, incluir `storageLocation`.
*   `stock.controller.ts` / `kitchen.controller.ts`: Zod `toStorageLocationId`. `locations.controller.ts`: `409` si el área KITCHEN tiene remanentes activos.
*   `seed.ts`: áreas de cocina por defecto idempotentes.
*   Governance: `check_schema_drift.sh`, `check_migration_schema_parity.sh`, `check_seed_idempotency.sh`, `check_contract_drift.sh`.
