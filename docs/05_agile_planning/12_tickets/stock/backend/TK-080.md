# 🎟️ TK-080: Backend Filtro `insumoId` para Detección de Apertura Duplicada

> **Navegación del Framework SDD:**
> [📖 Índice de Tickets](../../indice_tickets.md) | [Siguiente: TK-080-FE](../frontend/TK-080-FE.md)

---

## 📝 Descripción
Extiende `GET /api/v1/kitchen/remanentes` con un query param opcional `insumoId`, que filtra a los remanentes activos de un único insumo **en cualquier ubicación de cocina** (no se combina con `location`). Reutiliza el endpoint y caso de uso ya existentes de `US-003` — no introduce un endpoint nuevo ni una tabla nueva.

---

## 🔀 Alcance de Modificación (Hexagonal Layers)

### Application:
- `GetActiveRemanentesUseCase.ts` (o equivalente): acepta filtro opcional `insumoId` además del ya existente `location`.

### Infrastructure:
- `PrismaRemanenteRepository.ts` / `InMemoryRemanenteRepository.ts`: soporta filtro por `insumoId` con estado `ACTIVE`, sin restricción de `location`.
- `kitchen.controller.ts`: Zod schema de query params agrega `insumoId` opcional (string UUID).

---

## ✅ Criterios de Aceptación & DoD
1. **Filtro Correcto:** `GET /api/v1/kitchen/remanentes?insumoId=X` retorna únicamente remanentes `ACTIVE` de ese insumo, en cualquier `location` (US-021 Escenario 1).
2. **Sin Remanentes:** Si no hay remanentes activos del insumo, retorna `[]` — el frontend interpreta lista vacía como "sin advertencia" (US-021 Escenario 2).
3. **Retrocompatibilidad:** El comportamiento existente sin `insumoId` (filtro por `location`, o sin filtros) no cambia.
4. **Verificación:** 100% pruebas pasando (`pnpm test`) y 0 errores de build (`pnpm run build`).
