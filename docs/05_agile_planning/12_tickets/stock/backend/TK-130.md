# 🎟️ TK-130: Endpoint de Edición de Insumo (`PUT /api/v1/stock/insumos/:id`) — US-036

> **Navegación:** [⬅️ US-036](../../../11_user_stories/catalog/US-036_edicion_insumo.md) | [📖 Índice de Tickets](../../indice_tickets.md)

---

## 📝 Descripción

Nuevo `PUT /api/v1/stock/insumos/:id` (solo ADMIN) que edita `name`, `unitCost`, `barcode` de un insumo existente. `unitOfMeasure` y las líneas de stock **no** se tocan. Cierra `AUDIT-DEV-012` C-1 y la deuda de `US-012` §[N].

*   **Módulo:** `stock` · **5 SP** · **Must Have** (bloquea la utilidad de `TK-128`) · **Prerrequisitos:** `TK-096` (multi-sector), `TK-119` (barcode).

---

## 🔀 Alcance de Modificación (Hexagonal Layers)

### Domain
*   **`domain/stock/entities/Insumo.ts`:** `+ withDetails(patch: { name?: string; unitCost?: DecimalQuantity | null; barcode?: string | null }): Insumo` — reconstruye el agregado preservando `id`, `unitOfMeasure` y `stockLines` (mismo patrón que `withStockLines`). `null` limpia el campo; `undefined` lo conserva.

### Application
*   **`application/stock/use-cases/UpdateInsumoUseCase.ts`** (nuevo):
    1. `findById(id)` → `EntityNotFoundException` si no existe.
    2. Si `name` cambia → `findByName(trim)` → `InsumoAlreadyExistsException` si pertenece a otro `id`.
    3. Si `barcode` cambia y no es `null` → `findByBarcode(trim)` → `InsumoAlreadyExistsException` si pertenece a otro `id`.
    4. `insumo.withDetails(...)` + `insumoRepository.save(...)` (el `upsert` de Prisma ya persiste `name`/`unitCost`/`barcode` y maneja el `P2002` de barcode como red de seguridad).
    5. Devuelve `InsumoOutputDTO` (`mapInsumoToOutputDTO`).

### Infrastructure
*   **`infrastructure/stock/http/controllers/stock.controller.ts`:** `updateInsumoSchema` (Zod) — `name` `.min(1).max(120).optional()`; `unitCost` `.regex(/^\d{1,10}(\.\d{1,2})?$/).nullable().optional()` (escala `Decimal(12,2)`, `backend_rules.md §3`); `barcode` `.trim().min(1).max(64).nullable().optional()`; `.strict()` para que `unitOfMeasure` u otra clave desconocida → `400` (Escenario 2). Handler `updateInsumo`.
*   **`infrastructure/stock/http/routes/stock.routes.ts`:** `router.put('/insumos/:id', requireRole('ADMIN'), controller.updateInsumo)`.
*   **`infrastructure/http/app.ts`:** wiring del `UpdateInsumoUseCase` en el `StockController`.
*   **`docs/03_persistence_and_api/openapi.yaml`:** `PUT /api/v1/stock/insumos/{id}` + `UpdateInsumoRequest` (aditivo — no breaking).

**Fuera de alcance:** editar `unitOfMeasure`; borrado/desactivación de insumos; recálculo retroactivo de valorizaciones históricas.

---

## ⚠️ Mitigación de Riesgos

1. **Colisión de unicidad bajo concurrencia:** check-then-write en el use case + `P2002` en `PrismaStockRepository.save` como red de seguridad (patrón ya existente de `CreateInsumoUseCase`).
2. **`withDetails` que pierde un campo futuro:** se copian TODOS los campos actuales explícitamente y hay un test que verifica que `stockLines` y `unitOfMeasure` sobreviven a la edición (misma clase de bug que motivó `withStockLines`, TK-119 FASE 4.B).
