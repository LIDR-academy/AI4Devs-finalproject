## 📝 Descripción
Deuda de calidad acotada sobre `RecordExtractionUseCase` (hallazgos Media/Baja/Info de `AUDIT-DEV-006`). Sin cambio de comportamiento observable salvo el endurecimiento de auditoría (F-8) y la forma de `remanenteId` en descarte (F-9).

* **F-3 — IDs y reloj en la capa de aplicación:** `mov-${Date.now()}` **sin sufijo aleatorio** (colisión de PK en el mismo ms → `500`); `rem-${Date.now()}-${random(1000)}` no-UUID; `Date.now()` / `new Date()` en aplicación/dominio rompen la pureza hexagonal (AGENTS §4) y rozan el Guard 3.
* **F-4 — `throw new Error` crudo** para "motivo obligatorio en descarte directo" (`RecordExtractionUseCase.ts:111-113`): no mapea a RFC 7807; si el caso de uso se invoca fuera del controlador (Zod `.refine` bypass) devuelve `500`.
* **F-7 — El movimiento guarda el `name` del sector, no el `id`** (`fromLoc: sector.name`): renombrar un `StorageLocation` desincroniza el histórico.
* **F-8 — `operatorId` aceptado desde el body:** `userObj?.id || parsedBody.operatorId`; US-014 §Decisiones exige que la autoría venga solo del token.
* **F-9 — `remanenteId: ''` como centinela** en la respuesta de descarte directo.

## 🔀 Alcance de Modificación (Hexagonal Layers)

### Domain
*   Nuevos puertos en `domain/shared/` (o `domain/stock/`): `Clock { now(): Date }` e `IdGenerator { next(prefix?: string): string }` (implementación por defecto: `crypto.randomUUID()`).
*   `Remanente.createNew(...)` deja de llamar `new Date()`: recibe `now: Date` (y opcionalmente el `id` ya generado) como parámetro.
*   Nueva excepción de dominio `DiscardReasonRequiredException extends DomainException` (o la jerarquía existente) → mapeada a `400`/`422` RFC 7807 por el `errorHandler`.

### Application
*   `RecordExtractionUseCase` recibe `Clock` e `IdGenerator` por constructor. Todos los `Date.now()` / `new Date()` / plantillas de id se sustituyen.
*   `handleDirectDiscard`: `throw new Error(...)` → `throw new DiscardReasonRequiredException()`.
*   `ExtractionResponseDTO.remanenteId` pasa a `string | null` (`null` en `DIRECT_DISCARD`); alternativa preferida si la revisión de diseño lo aprueba: unión discriminada por `status`.
*   El movimiento registra `fromStorageLocationId` (id) **y** conserva `fromLoc` con el `name` para lectura directa del histórico — o migra el consumidor de histórico a resolver el nombre por join. Decisión a fijar en el ticket antes de codificar (impacta `GetStockMovementHistoryUseCase` y `openapi.yaml`).

### Infrastructure
*   `stock.controller.ts`: cuando `req.user` está presente (auth activa), **ignorar** `parsedBody.operatorId` — la autoría es `req.user.id` y punto. Quitar `operatorId` del `recordExtractionSchema` o marcarlo como solo-test (aceptado únicamente con `requireAuth:false`).
*   `stock.routes.ts` / `composition.ts`: wiring de `Clock` (real: `{ now: () => new Date() }`) e `IdGenerator` reales; los tests inyectan fakes deterministas.
*   `PrismaStockRepository.recordMovement` / `StockMovementRecord`: nuevo campo `fromStorageLocationId`. Revisar si `schema.prisma` `StockMovement` necesita la columna (probable `fromStorageLocationId String? @db.Uuid` + índice) → **migración Prisma dedicada con aprobación humana** (AGENTS §3) y re-ejecución de `check_schema_drift.sh` / `check_migration_schema_parity.sh` / `check_contract_drift.sh`.
*   `openapi.yaml` / `07_api_specification.md`: `remanenteId` nullable; nuevo campo del movimiento en el histórico.

## ✅ Criterios de Aceptación & DoD
1. **TDD:**
   *   `Remanente.test.ts`: `createNew` con `now` inyectado fija `expirationDate = now + 24h` exacta (sin depender del reloj de la máquina).
   *   `RecordExtraction.test.ts`: `IdGenerator` fake → ids deterministas; dos extracciones en el mismo tick **no** colisionan.
   *   Descarte sin `reason` invocando el caso de uso directamente → `DiscardReasonRequiredException` (no `Error` genérico); vía HTTP sigue siendo `400` RFC 7807 (regresión del test existente `:155-169`).
   *   `operatorId` del body **ignorado** cuando hay `req.user` (test con auth activa: body trae `operatorId:'spoof'`, el movimiento registra el id del token).
   *   `DIRECT_DISCARD` → `remanenteId === null` en el payload (actualizar el test `:125-153`).
   *   El movimiento persiste `fromStorageLocationId` correcto.
2. **Guard 3:** `grep` de `new Date(` / `Date.now(` en `application/stock/` y `domain/stock/` → 0 (salvo la implementación real del `Clock` en infraestructura).
3. **RFC 7807** en la nueva excepción; `check_privilege_defaults.sh` / gates de diff verdes.
4. **Contrato:** `openapi.yaml` lint sin errores; `check_contract_drift.sh` reporta el `remanenteId` nullable y el campo nuevo como **cambios documentados en este ticket**, no regresión silenciosa.
5. **Sin regresiones:** `pnpm test` / `build` / `lint` verdes. Mutation score ≥ 70 % en `RecordExtractionUseCase.ts` y `Remanente.ts`.
6. **Commit atómico:** `refactor(stock): inject clock/id generator, domain exception and audit hardening in warehouse extraction (TK-099)`.
