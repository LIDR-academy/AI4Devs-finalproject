# 🎟️ TK-096: Stock Multi-Sector de Bodega y Depósito por Sub-Sector (Backend)

## 📝 Descripción
Activar de punta a punta el modelo `WarehouseStock` como `1:N` real por sub-sector, vinculado por FK a `StorageLocation`, y adaptar los tres casos de uso de bodega (`CreateInsumoUseCase`, `RestockInsumoUseCase`, `RecordExtractionUseCase`) para operar sobre la línea `(insumo, sub-sector)` elegida. Incluye la migración de datos de los insumos preexistentes desde `MAIN_WAREHOUSE`.

*   **ID US Relacionada:** `US-025`
*   **Módulo / Vertical Slice:** `stock` (Bodega)
*   **Estimación (Story Points):** 8
*   **Prioridad MoSCoW:** Should Have
*   **Prerrequisitos:** `TK-003`, `TK-060`, `TK-072`, `TK-074` (catálogo `StorageLocation`)

## 🔀 Alcance de Modificación (Hexagonal Layers)

### Domain
*   `Insumo` pasa a agregado: contiene `WarehouseStockLine[]` (VO `{ storageLocationId, quantity: DecimalQuantity }`). Métodos:
    *   `totalWarehouseStock(): DecimalQuantity` — suma de líneas.
    *   `stockAt(storageLocationId): DecimalQuantity` (0 si no hay línea).
    *   `hasSufficientStockAt(qty, storageLocationId): boolean`.
    *   `deductStockAt(qty, storageLocationId)` / `restockAt(qty, storageLocationId)` — crean la línea si no existe (restock) o lanzan `InsufficientStockException` (deduct).
*   `InsufficientStockException` incluye el `storageLocationId` y el saldo del sector en el mensaje.
*   Nueva regla de dominio (Invariante 4): `StorageLocation` con líneas de saldo `> 0` es indeleble/indesactivable → `LocationHasStockException`.
*   `IInsumoRepository`: `findById` / `listAll` devuelven el agregado con todas sus líneas; `save` persiste el diff de líneas.

### Application
*   `CreateInsumoInputDTO`: `+ storageLocationId` (requerido), `initialWarehouseStock` opcional. Valida que el `StorageLocation` exista y sea `type = WAREHOUSE` activo (→ `EntityNotFoundException`). Crea la línea inicial.
*   `RestockInsumoUseCase`: `+ storageLocationId` (requerido). Upsert de la línea; respuesta `{ storageLocationId, quantityAdded, newSectorStock, newWarehouseStock }`.
*   `RecordExtractionDTO`: `+ fromStorageLocationId` (requerido). `RecordExtractionUseCase` valida saldo con `hasSufficientStockAt`, deduce de esa línea, y el `StockMovement.fromLoc` pasa a ser el `name`/`id` del sector (no `'MAIN_WAREHOUSE'` fijo). Respuesta `+ fromStorageLocationId`, `remainingSectorStock`.
*   `ListInsumosUseCase`: respuesta `+ stockByLocation: [{ storageLocationId, storageLocationName, quantity }]`, `warehouseStock` = suma.
*   `GetLocationsUseCase` / borrado de `StorageLocation`: comprobar `warehouse_stocks` con saldo → `409` (`LocationHasStockException`).

### Infrastructure
*   **`prisma/schema.prisma`:** `WarehouseStock.location` (`String`) → `storageLocationId String @db.Uuid` con relación `storageLocation StorageLocation @relation(..., onDelete: Restrict)`; `@@unique([insumoId, storageLocationId])`; `@@index([storageLocationId])`. `StorageLocation` gana `warehouseStocks WarehouseStock[]`. `quantity` a `Decimal(12,4)` (hoy `12,3`).
*   **Migración Prisma dedicada** (`prisma migrate dev --name warehouse_stock_multi_sector`): (1) crea el `StorageLocation` semilla `loc-seed-unclassified`; (2) añade `storage_location_id` nullable; (3) `UPDATE warehouse_stocks SET storage_location_id = 'loc-seed-unclassified' WHERE location = 'MAIN_WAREHOUSE'` + mapea el resto de literales a sus sectores semilla; (4) `NOT NULL` + FK + unique; (5) `DROP COLUMN location`. **Requiere aprobación humana del archivo de migración (AGENTS §3).**
*   `PrismaStockRepository`: eliminar el id sintético `${insumo.id}_MAIN_WAREHOUSE` y el `.find(s => s.location === 'MAIN_WAREHOUSE')`; leer/escribir todas las líneas (`include: { warehouseStocks: { include: { storageLocation: true } } }`), upsert por `@@unique`.
*   `stock.controller.ts`: Zod — `createInsumoSchema + storageLocationId`, `restockInsumoSchema + storageLocationId`, `recordExtractionSchema + fromStorageLocationId`. Errores RFC 7807.
*   `locations.controller.ts` (`DELETE`/`PUT isActive:false`): `409` si el sector tiene stock.
*   `seed.ts`: sectores de bodega por defecto idempotentes por `name`.
*   Governance: re-ejecutar `check_schema_drift.sh`, `check_migration_schema_parity.sh`, `check_contract_drift.sh`, `check_seed_idempotency.sh`.
