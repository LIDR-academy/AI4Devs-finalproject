# 🎟️ TK-050: Trazabilidad de Movimientos de Stock

## 📝 Descripción
Expone `GET /api/v1/stock/movements` con filtros (`insumoId`/`startDate`/`endDate`). El modelo `StockMovement` ya se poblaba en cada extracción, consumo y descarte, pero no existía forma de consultarlo — un administrador no podía auditar "quién movió qué y cuándo".

*   **ID US Relacionada:** `US-011`
*   **Módulo / Vertical Slice:** `stock`
*   **Estimación (Story Points):** 3
*   **Prioridad MoSCoW:** Should Have
*   **Prerrequisitos:** `TK-003` (Extracciones), `TK-005` (Consumo Parcial), `TK-006` (Descarte)

---

## 🔀 Alcance de Modificación (Hexagonal Layers)
*   **Domain:** Nueva interfaz `IStockMovementQueryRepository` (`StockMovementHistoryItem`, `StockMovementQueryFilters`), siguiendo el mismo patrón CQRS-ish ya establecido por `IRemanenteQueryRepository`. Campo opcional `createdAt` añadido a `StockMovementRecord`.
*   **Application:** Nuevo caso de uso `GetStockMovementHistoryUseCase`.
*   **Infrastructure:** `InMemoryStockMovementQueryRepository` (envuelve la misma instancia de `InMemoryStockRepository`, no un store independiente) y `PrismaStockMovementQueryRepository`. Endpoint `GET /api/v1/stock/movements`, protegido con `requireRole('ADMIN')`.

---

## ⚠️ Mitigación de Riesgos Técnicos
1.  **Divergencia entre Query y Write Model:** al envolver la misma instancia de `InMemoryStockRepository` (en vez de un store de lectura independiente), los movimientos generados por cualquier flujo (extracción/consumo/descarte/conciliación) aparecen automáticamente en la consulta sin paso de sincronización manual.
2.  **Exposición de Datos Sensibles:** el endpoint exige rol `ADMIN` — un operario `KITCHEN_STAFF` no puede auditar movimientos de otros.

---

## ✅ Criterios de Aceptación & DoD (Definition of Done)

@critical @smoke
### Criterio de Aceptación 1: Consulta poblada por un movimiento real
*   **Given** que se registró una extracción real (no seed directo)
*   **When** un Administrador invoca `GET /api/v1/stock/movements`
*   **Then** la API responde `200 OK` con el movimiento generado, incluyendo `insumoId`, `type`, `quantity`, `fromLoc`/`toLoc` y `createdAt`.

### DoD Estricto:
1.  **TDD Compliance:** 5 tests nuevos (historial poblado por movimiento real, filtro por `insumoId`, 403 sin rol ADMIN, 401 sin token, lista vacía sin movimientos).
2.  **Contrato Sincronizado:** `openapi.yaml` actualizado con el endpoint nuevo.
3.  **Tests:** 60/60 backend + 52/52 frontend en verde; duplicación 2.02% (umbral 3%).
