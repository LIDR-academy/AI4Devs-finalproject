# 📖 Historia de Usuario: US-026 — Áreas de Cocina como Ubicaciones de Catálogo y Destino Dinámico en Extracción

## 👤 Rol del Usuario
Como Administrador General (gestión del catálogo) y como Operario Autorizado (al extraer de bodega).

## 🎯 Objetivo / Valor de Negocio
Quiero administrar las áreas físicas de la cocina (*Heladera Principal*, *Mesa de Preparación*, *Línea de Servicio*, *Congelador de Cocina*…) como ubicaciones del mismo catálogo `StorageLocation` que ya usa la bodega, y que el operario elija el área de cocina de destino desde una lista real al extraer un insumo, para que cada `Remanente` quede vinculado por FK a un área concreta y administrable, y no a un literal fijo (`KITCHEN_FRIDGE` / `KITCHEN_PREP` / `KITCHEN_LINE`) codificado en el frontend.

## 📌 Justificación (Gap Analysis)
`StorageLocation` (US-016) ya define `type = WAREHOUSE | KITCHEN`, pero **ningún flujo consume las filas `type = KITCHEN`**: el modal de extracción ofrece 3 literales hardcodeados y `Remanente.location` es un `String` libre. La matriz de trazabilidad marca esto como deuda abierta de `TK-074-FE` ("desplegable destino de cocina dinámico en extracción pendiente"). Esta historia lo cierra y es **prerrequisito de ADR-003** (para poder preguntar "¿en qué área dejaste el sobrante?" hace falta un catálogo de áreas).

## 🗣️ Decisiones de Negocio Consultadas con el Humano (Guard 28)
*   **Áreas de cocina como catálogo:** confirmado — se administran como `StorageLocation` con `type = KITCHEN` (misma decisión #2 de ADR-003).
*   **Migración de literales:** los valores existentes `KITCHEN_FRIDGE` / `KITCHEN_PREP` / `KITCHEN_LINE` en `remanentes.location` se migran a filas semilla de `StorageLocation` (`type = KITCHEN`), y la columna pasa a FK `storageLocationId`. Migración Prisma dedicada con aprobación humana (AGENTS §3).
*   **Borrado de área con remanentes activos:** un `StorageLocation type = KITCHEN` con `Remanente` `ACTIVE` asociado no puede eliminarse ni desactivarse → `HTTP 409` (misma regla que Invariante 1-bis de US-025 para bodega).

## 🔗 Dependencias
*   Depende de **US-016** (catálogo `StorageLocation` + CRUD, ya implementado).
*   Comparte migración de `Remanente.location` con **US-027 / US-028** (ADR-003).

## 🥒 Criterios de Aceptación (BDD - Sintaxis Gherkin)

### Escenario 1: Alta de un Área de Cocina
- **Given** El Administrador en la gestión de ubicaciones (`/ajustes` → estaciones).
- **When** Da de alta `"Congelador de Cocina"` con `type = KITCHEN`.
- **Then** El sistema crea el `StorageLocation` (`HTTP 201`) y esa área aparece como opción de destino en el modal de extracción de bodega.

### Escenario 2: Extracción con Destino de Cocina Elegido del Catálogo (Happy Path)
- **Given** Las áreas de cocina `"Heladera Principal"` y `"Mesa de Preparación"` activas, y `"Lomo Vacuno"` con 10 KG en `"Heladera de Carnes"` (bodega).
- **When** Un operario extrae 3 KG con origen `"Heladera de Carnes"` y destino `"Mesa de Preparación"`.
- **Then** Se crea el `Remanente` con `storageLocationId = "Mesa de Preparación"`; el `StockMovement` `EXTRACTION` registra `toLoc` = esa área; el tablero FEFO muestra el remanente ubicado en `"Mesa de Preparación"`.

### Escenario 3: El Selector de Destino Solo Muestra Áreas de Cocina Activas
- **Given** Un sub-sector de bodega `"Bodega de Secos"` (`type = WAREHOUSE`) y un área de cocina `"Línea de Servicio"` inactiva.
- **When** El operario abre el desplegable "Ubicación Destino en Cocina" del modal de extracción.
- **Then** `"Bodega de Secos"` no aparece (es `WAREHOUSE`), `"Línea de Servicio"` no aparece (inactiva); solo se listan áreas `type = KITCHEN` activas.

### Escenario 4: Bloqueo de Borrado de Área con Remanente Activo (Edge Case)
- **Given** El área `"Heladera Principal"` con un `Remanente` `ACTIVE` de `"Queso Mozzarella"`.
- **When** El Administrador intenta eliminar o desactivar `"Heladera Principal"`.
- **Then** El sistema responde `HTTP 409 Conflict`; el área permanece activa.

### Escenario 5: Migración de Literales Preexistentes
- **Given** `Remanente` existentes con `location` en `KITCHEN_FRIDGE` / `KITCHEN_PREP` / `KITCHEN_LINE`.
- **When** Se aplica la migración de `US-026`.
- **Then** Cada literal se re-apunta a su fila semilla `StorageLocation` (`type = KITCHEN`) sin pérdida de datos; `check_migration_schema_parity.sh` verde; el tablero FEFO sigue mostrando los remanentes con su ubicación.
