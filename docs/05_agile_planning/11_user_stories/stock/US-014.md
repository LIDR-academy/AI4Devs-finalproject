# 📝 US-014: Trazabilidad Completa en Extracciones de Bodega (Responsable, Motivo y Propósito)

> **Navegación del Framework SDD:**  
> [⬅️ Volver a US-013 (stock/US-013.md)](US-013.md) | [📖 Glosario & Reglas](../../01_product_definition/01_glosario_y_reglas_negocio.md) | [Siguiente: Desglose de Tickets (12_tickets/indice_tickets.md)](../12_tickets/indice_tickets.md) ➡️

---

## 🗣️ Narrativa (Comportamiento y Negocio)
**Como** operario de cocina o administrador autenticado,  
**Cuando** realizo la extracción de un insumo desde la bodega central,  
**Quiero** especificar el propósito del movimiento (`KITCHEN_STOCK`, `RECIPE` o `DIRECT_DISCARD`), registrar un motivo descriptivo o receta asociada, y dejar plasmada mi identidad (`operatorId`),  
**Para** garantizar una auditoría integral del inventario, diferenciar mermas directas en bodega de insumos trasladados a cocina y saber exactamente quién y para qué retiró cada ingrediente.

---

## 🚦 Precondiciones
- El operario o administrador cuenta con un token de autenticación válido (`operatorId`).
- El insumo a extraer existe y dispone de stock suficiente en la bodega central.

---

## 🧪 Criterios de Aceptación (BDD Gherkin)

@critical @smoke
### Escenario 1: Extracción con especificación de motivo y receta (Happy Path - RECIPE)
*   **Given** un operario autenticado con ID `"usr-op-001"`
*   **And** un insumo "Queso Mozzarella" con stock disponible de "10.000" KG en bodega
*   **When** solicita extraer "2.000" KG con `purpose = 'RECIPE'`, `recipeId = 'rec-pizza-01'` y `reason = 'Mise en place turno noche'`
*   **Then** la API responde con `201 Created`
*   **And** el saldo en bodega se reduce a "8.000" KG
*   **And** se registra en `StockMovement` el `operatorId = 'usr-op-001'`, `purpose = 'RECIPE'`, `reason = 'Mise en place turno noche'` y `recipeId = 'rec-pizza-01'`.

@critical
### Escenario 2: Extracción para descarte directo desde bodega (Opción A - DIRECT_DISCARD)
*   **Given** un insumo "Leche Entera" dañado o vencido en la bodega central
*   **When** el operario registra una extracción de "1.500" L con `purpose = 'DIRECT_DISCARD'` y `reason = 'Empaque roto en recepción'`
*   **Then** la API responde con `201 Created`
*   **And** el saldo en bodega se reduce en "1.500" L
*   **And** **no se crea ningún remanente activo en cocina**
*   **And** se crea un registro en `StockMovement` con `type = 'DISCARD_DIRECT'`, `toLoc = 'WASTE_BIN'`, `operatorId` y el motivo registrado.

@edge
### Escenario 3: Rechazo de descarte directo sin motivo especificado
*   **Given** una solicitud de extracción con `purpose = 'DIRECT_DISCARD'`
*   **When** no se proporciona el campo `reason` (o viene vacío)
*   **Then** la API rechaza la solicitud con HTTP 400 Bad Request cumpliendo RFC 7807 indicando que el motivo es obligatorio para mermas directas.

---

## 🔒 Decisiones de Negocio Consultadas con el Humano (Guard 28)
- **Modo de Operación:** Se aprobó la **Opción A (Extracción Unificada)**, permitiendo descarte directo desde bodega (`DIRECT_DISCARD`) en el mismo flujo de extracción sin requerir un paso intermedio en cocina.
- **Auditoría de Autoría:** La autoría (`operatorId`) se toma directamente del contexto del token Bearer JWT enviado en la petición HTTP.
