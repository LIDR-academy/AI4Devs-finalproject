# 📖 Historia de Usuario: US-015 — Gestión de Permisos y Roles Dinámicos

## 👤 Rol del Usuario
Como Administrador General o Chef Ejecutivo,

## 🎯 Objetivo / Valor de Negocio
Quiero crear roles personalizados (ej: *Bodeguero*, *Cocinero*, *Sub-Chef*) y asignar una matriz granular de permisos desde la interfaz web, para restringir las acciones disponibles a cada puesto de trabajo y autoredirigir al usuario a su pantalla correspondiente al autenticarse.

---

## 🥒 Criterios de Aceptación (BDD - Sintaxis Gherkin)

### Escenario 1: Creación de un Rol Personalizado con Permisos Específicos
- **Given** El Administrador autenticado en la plataforma.
- **When** Crea un nuevo rol `"Encargado de Bodega"` asignando únicamente los permisos `stock:extract`, `stock:restock`, `stock:read`.
- **Then** El sistema guarda el rol en la tabla relacional `Role`, asocia sus registros en `RolePermission` y retorna `HTTP 201 Created`.

### Escenario 2: Autoredirección e Invariante de Acceso en Login
- **Given** Un usuario operario asignado al rol `"Cocinero Auxiliar"` (con permiso `kitchen:recipe_prepare` y sin permiso `stock:extract`).
- **When** Inicia sesión ingresando su PIN de 4 dígitos.
- **Then** El backend emite un JWT que incluye su lista de permisos y la interfaz frontend lo redirige automáticamente a la pantalla del **Tablero FEFO de Cocina**, ocultando las acciones de bodega.

### Escenario 3: Rechazo HTTP 403 Forbidden por Permiso Denegado
- **Given** Un usuario con un rol que NO posee el permiso `roles:manage`.
- **When** Intenta enviar una petición `POST /api/v1/roles` para crear o modificar un rol.
- **Then** El middleware `authorizePermissions` rechaza la solicitud retornando `HTTP 403 Forbidden` conforme a RFC 7807.
