# Risks — ai-lesson-generation

| # | Risk | Type | Likelihood | Impact | Mitigation |
|---|---|---|---|---|---|
| R1 | **First LLM call in the repo, in Deno.** No Vercel AI SDK / `@ai-sdk/groq` usage exists yet; the Edge runtime (Deno) has never called an LLM here. SDK/runtime import or streaming quirks could surprise. | technical | M | H | Start task-4 with a time-boxed spike proving `@ai-sdk/groq` + `generateObject` run in the real Edge runtime against a live Groq key (mirrors R1's `mupdf` spike). Keep function logic as pure, Jest-testable modules; the SDK call is a thin adapter behind a seam. Fall back to a plain `fetch` to Groq's OpenAI-compatible endpoint if the SDK misbehaves in Deno. |
| R2 | **Deno function outside the Jest/Stryker harness.** This sandbox has no Deno CLI, so `supabase/functions/generate-lesson/` and its `_shared/` are not executed or mutation-tested here (same boundary R1 documented). | technical | H | M | Author all decision logic (prompt build, deck-schema validation, composition enforcement, image placement, deck assembly) as pure TS in `libs/supabase-services` (Jest + Stryker), mirror by hand into `_shared/`. The function file is thin orchestration glue, verified manually against a real PDF after deploy. Flag the boundary for reviewers / `mutation_tester` in `tdd.md`. |
| R3 | **Malformed / non-conforming AI output.** An LLM may return prose, invalid JSON, wrong activity shapes, a broken `correctOptionId`, or violate the composition. | technical | H | M | Use `generateObject` with a strict deck schema (zod) covering all five R3 activity shapes + their invariants (e.g. `correctOptionId ∈ options[].id`, matching perfect-pairing). Any schema/invariant failure → typed `generation_failed` (@s15), atomic (no partial deck). Composition enforced both in-prompt and by a post-parse filter. |
| R4 | **Generation latency / Edge wall-clock.** A chapter-length PDF + a 70B model (plus an optional vision round-trip) may approach the Edge Function timeout; PRD targets ~30s. | technical / product | M | M | Bound input (R1 already caps 20 pages / 10 MB); vision is the rare fallback only; models are a tunable constant so a faster model can be swapped without code change. Surface `timeout` as a readable, retryable error (@s15). Revisit async/streaming only if it routinely exceeds the wall-clock. |
| R5 | **Vault decrypted-read availability on the hosted project (inherited from R6).** R6 flagged that hosted-project Vault/Edge availability was not human-confirmed; this story adds the *read* RPC (`get_api_key`) on top. | technical | L | H | Same fallback R6 documented: if Vault is unavailable, store/read via `pgcrypto`/`pgsodium` `bytea` with a symmetric key given to the function as a Supabase secret — the read RPC signature and every higher layer are unaffected. Verify early in task-3 (mirrors R6's task-1/2 verification). |
| R6 | **Provider swap regresses shipped R6 code/tests.** Changing `AiProvider` `'openai' → 'groq'` breaks ~dozen `provider: 'openai'` fixtures across `@helsoft/hooks`, `@helsoft/components`, `@helsoft/supabase-services`, and the Deno `manage-api-key` tests, plus user-facing copy. | technical | M | M | Make the swap one atomic task (task-1) that updates the type, both mirrors, display/guidance copy, all four locale `guidance` values, and every broken fixture in the same commit; run `pnpm check-types` + `pnpm test` repo-wide before proceeding. See dependency row below. |
| R7 | **Key exposure / logging leak.** The raw key is decrypted server-side and passed to the SDK; a careless log or error passthrough could leak it (@s8). | security | L | H | Read the key only inside the function via the service-role RPC; never include it in the request/response body, never log it (reuse R6's redaction discipline). Normalize provider errors to typed codes — no raw Groq/Supabase error reaches the client. Add an explicit "no key in logs" assertion in the function's own tests/manual smoke. |
| R8 | **Cost of the learner's own key.** Generation spends the learner's Groq quota; a retry storm or a huge deck multiplies cost. | product | L | M | Deck size implicitly bounded by input caps + prompt; a single synchronous call per Generate; retries are explicit user actions. (Metering is a Future Consideration, out of scope.) |
| R9 | **Progress fidelity vs. reality.** A hook-driven stepper over a single black-box invoke shows steps that reflect pipeline *order* but not exact real-time completion, which could mislead. | product / technical | M | L | Steps mirror the true pipeline order and settle deterministically on resolve; the UI contract (ordered steps + current index) is stable so a server-driven upgrade is non-breaking. Documented in spec.md "Progress model". |
