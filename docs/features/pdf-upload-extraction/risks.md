# Risks — pdf-upload-extraction

| # | Risk | Type | Likelihood | Impact | Mitigation |
|---|---|---|---|---|---|
| R1 | **`mupdf`-wasm may not cleanly do text + embedded images + page/position in the Deno Edge runtime**, or its WASM bundle may be too heavy for the Edge cold-start budget. The library is now locked (decision #2), but its real-runtime behavior is still unproven — this remains the highest-risk piece of the MVP. | technical | H | H | Time-boxed spike (task-3, first step) **validates and implements `mupdf`-wasm on real PDFs in the actual Edge runtime**. All build work sits behind a `PdfExtractionAdapter` interface so the DAO/service/hook/UI and their tests target the extraction *contract*, not the library — if `mupdf`-wasm fails the spike, `unpdf` (pdf.js, MIT-ish; text-strong, manual embedded-image work) is the documented fallback behind the same interface, swapped without reworking the build. |
| R2 | **Synchronous extraction exceeds the Edge Function wall-clock limit** for large PDFs (parse + image decode/downscale/re-encode + storage writes), producing timeouts. | technical | M | H | Cap page count (20, tunable) and file size (10 MB) to bound work; downscale to 1024px/JPEG q80 to keep image work cheap; skip <100×100 px images. If the spike shows synchronous invoke is too slow, fall back to the storage-trigger + poll model (documented as the discarded alternative in spec Resolved decisions) — the DAO/service boundary already isolates the trigger mechanism. |
| R3 | **Scanned-PDF detection is a heuristic and can misfire** — a legitimate low-text PDF flagged as scanned (false positive), or a scanned PDF slipping through (false negative → empty/garbage lesson later). | technical / product | M | M | Heuristic = total extracted text length across all pages below a small threshold ⇒ `scanned_or_image_only`; unit-test the heuristic against text-only, image-heavy-but-captioned, and scanned fixtures; keep the threshold a single tunable constant; the error copy invites the user to try a text-based PDF. Revisit the threshold after the spike on real files. |
| R4 | **Edge Function logic is outside the Jest + Stryker workspace** (Deno runtime), so mutation coverage and the standard test loop don't reach it. | technical | H | M | Structure the function as pure, Deno-testable modules (adapter, downscale, scanned-detection, DTO shaping) with Deno unit tests; keep the mutation-scored coverage on the JS layers (DAO/service/hook/UI); the slice integration test mocks `functions.invoke`. Locked as a known boundary at the gate (spec Resolved decisions) so the reviewers/`mutation_tester` know the scope. |
| R5 | **Uploading a file from Expo differs per platform** — web yields a `File`/`Blob`; native yields a file URI that must be read (base64/ArrayBuffer) via `expo-file-system`. Wrong wiring silently breaks upload on native. | technical | M | M | Isolate the platform read in the DAO (`PdfUploadDao`); keep the service/hook/UI platform-agnostic; add `expo-document-picker` + `expo-file-system` as app deps; cover the DAO with tests mocking each platform's picker result; document a manual native smoke check. |
| R6 | **AGPL licensing of `mupdf`-wasm** (the locked primary library). | product | M | L | **Accepted as a known tradeoff** for this portfolio/bootcamp MVP (decision #2). If a permissive license is required later, `unpdf` (pdf.js, MIT-ish) is the fallback — the `PdfExtractionAdapter` makes the swap cheap. |
| R7 | **Storage cost/clutter from images** (many figures per PDF, large originals). | product | M | L | Downscale to 1024px longest edge, JPEG q80, drop <100×100 px images; private buckets keyed per user/document; a future cleanup job can prune failed/orphaned uploads (out of scope now). |
| R8 | **RLS / storage policy gaps** could expose one user's PDFs or images to another. | technical / security | L | H | Migration authors table + storage policies keyed on `auth.uid()` / owner path segment; verify with Supabase Test Helpers (RLS assertions) as part of task-1; buckets private; client renders images via short-lived signed URLs only. |
| R9 | **The locked limits (10 MB / 20 pages) are conservative MVP ceilings** and may still prove wrong once measured (too low = rejects real chapters; too high = timeouts/cost). | product | M | M | Stored as a single-source tunable constant (`PDF_EXTRACTION_LIMITS`); retune after the R1 spike's real-file latency/cost data. Tests assert the *reject behavior*, not the specific number, so retuning won't churn the suite. |
| R10 | **Over-scoping into generation (R2)** — attaching images to slides, calling AI, building the lesson. | timeline | M | M | Spec pins the boundary: this feature only produces + persists extracted source and returns a typed result; the Content-state "continue" CTA is a placeholder. Tasks list exact paths so the implementer adds only extraction. |
| R11 | **i18n copy must exist in all four bundles** (en/es/pt/de); a missing `upload.*` key falls back to `en` and fails the coverage test. | product | M | L | Slice 3 adds all `upload.*` keys to every bundle; the localization lib's key-alignment coverage test catches gaps. |

## Dependencies
| Dependency | Status | Notes |
|---|---|---|
| Supabase Auth + `useSession()` | available | Upload is behind the `(app)` guard; `auth.uid()` scopes rows + storage. |
| Supabase Storage | available | `config.toml` sets a 50 MiB bucket cap; this feature creates private `pdf-uploads` + `pdf-images` buckets via migration. |
| Supabase Edge Functions (Deno) | available (runtime enabled in `config.toml`) | No functions exist yet; `extract-pdf` is the first. `deno_version = 2`. |
| PDF parsing library (Deno-compatible) | **selected — `mupdf`-wasm** | Locked at the gate (decision #2); validated/implemented in the task-3 spike. `unpdf` is the documented fallback behind `PdfExtractionAdapter`. |
| Deno image lib for downscale/recompress | **to confirm in spike** | Prefer `mupdf`-wasm's own image export; `ImageScript` (Deno-native, PNG/JPEG) as an alternative. Isolated behind the downscale module. |
| `expo-document-picker` | **to add** | App dep for choosing a PDF (web + native). |
| `expo-file-system` | **to add** | App dep for reading the picked file's bytes on native. |
| `Card`, `Button`, `Icon`, `ProgressIndicator`, `ScreenContainer` (`@helsoft/components`) | available | Reused by `PdfUploadPanel`; no ad-hoc UI. |
| `@helsoft/localization` | available | Add `upload.*` keys to en/es/pt/de. |
| Upload screen stub (`(app)/upload.tsx`) | available (stub) | Thin shell that renders `PdfUpload`. |
| `expo-image` | available | Renders extracted-image previews via signed URLs (if shown in Content state). |
