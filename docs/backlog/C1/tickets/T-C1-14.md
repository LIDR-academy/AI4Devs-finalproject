# [C1] T-C1-14 · `CompetitionSubject` value object over the twelve-value closed subject type

## Context

`US-C1-03` requires the affected competition subject to be a **closed set of exactly twelve values** named in `FR-INC-01` — Tournament, League, Group/Division, Bracket, Fixture/Match, Standings/Ranking, Registration, Roster, Team, Player Account, Schedule, Result — with stable identifiers and translatable labels, never free text. `ARCHITECTURE.md` §6.2 models it as a `CompetitionSubject` value object.

The subject is the **affected subject of a support record** and carries no in-application sport decision: a Fixture reference never implies the fixture can be rescheduled from here (`CLAUDE.md` §1, and the intake rule of `US-C1-28`).

**Blocked by finding F29.** Who may set the structured subject — agent only, per this backlog reading, or requester too — is unconfirmed. The value object is identical either way; the **permission** attached to setting it is not, so the write path stays behind the agent permission until the Product Owner rules.

## Scope

- `CompetitionSubject` value object in `libs/incident/domain`: a closed `SubjectType` union of exactly twelve members with stable identifiers, plus the instance reference.
- Translatable labels keyed by the stable identifier, resolved through `nestjs-i18n` (`NFR-I18N-05`) — no label text in the domain.
- Rejection of any subject type outside the closed set, as a typed domain error.
- Out of scope: the SCMS lookup and fallback (`T-C1-15`); the picker (`T-C1-16`); any sport-operation capability, which is out of product scope entirely.

## Acceptance criteria

**Given** the `SubjectType` union **When** it is inspected **Then** it contains exactly the twelve values of `FR-INC-01`, each with a stable identifier, and adding a thirteenth requires a deliberate code change rather than passing a string.

**Given** a subject type that is not in the set **When** a `CompetitionSubject` is constructed **Then** a typed domain error is raised and no value object exists.

**Given** a `CompetitionSubject` **When** it is rendered in two locales **Then** the identifier is unchanged and only the label differs.

**Given** the value object **When** it is unit-tested **Then** the tests run with no database, no HTTP and no SCMS dependency.
