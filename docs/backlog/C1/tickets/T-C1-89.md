# [C1] T-C1-89 · `KnowledgeSuggestionPort` and its degraded-availability contract

## Context

`US-C1-29` draws the boundary explicitly: the Incident side **calls the knowledge search through a port**, and **the search itself, its ranking and the article model belong to `C9` and are not implemented here**. It further requires that when the knowledge service is unavailable or returns nothing, intake continues normally with no suggestions and no blocking error — **a degraded optional subsystem never prevents logging an Incident** (`NFR-AVL-03`).

**No `C9` ticket is written in this epic.** Against an undeployed `C9`, the null adapter below is the binding, and the Incident side is complete and testable without it.

## Scope

- `KnowledgeSuggestionPort` in `libs/incident/domain` with its injection token, expressed in Incident vocabulary — description text and category identifier in, suggestion references out.
- Adapter in `libs/incident/infrastructure` calling the `C9` search with a bounded timeout, plus a null adapter selected by configuration when `C9` is absent.
- A contract that treats unavailable, timed-out and empty identically from the caller point of view: no suggestions, no error propagated to intake.
- Out of scope: search, ranking, relevance and the article model — all `C9` (`FR-KNW-*`); the suggestion UI (`T-C1-90`); deflection recording (`T-C1-91`).

## Acceptance criteria

**Given** the knowledge service available **When** suggestions are requested **Then** the port returns the suggestion references, and no `C9` domain type appears in `libs/incident/domain`.

**Given** the knowledge service unavailable, timing out, or returning nothing **When** suggestions are requested **Then** the caller receives an empty result in every case and no error propagates to the intake path.

**Given** the null adapter selected **When** an Incident is logged **Then** logging succeeds with no suggestion request attempted.

**Given** the dependency graph **When** it is inspected **Then** no `scope:incident` project depends on `scope:knowledge`; the adapter is bound in `apps/api`.
