# [C1] T-C1-46 · Clearing the flag removes the uplift and re-derives Priority

## Context

`US-C1-13` requires clearing the flag to remove the uplift, re-derive Priority from the **underlying assessed Impact and Urgency**, and publish the change with actor, justification, previous and new values — so an Incident does not stay at an inflated Priority after the live window has passed. It also requires a change to the **justification alone**, with no change of flag state, to be recorded as its own change in the activity history: every change to the flag or its justification is audited.

And it requires that clearing removes the uplift, **never the record**: the history still shows the flag had been set, by whom, why and for how long.

## Scope

- `ClearCompetitionInProgressFlagUseCase` and `AmendFlagJustificationUseCase` in `libs/incident/application`, both permission-gated and both refusing the system actor per `T-C1-45`.
- Restoration of the underlying assessed Impact retained by `T-C1-40`, followed by re-derivation through `PriorityCalculator`.
- Both operations emit the causal event shape of `T-C1-42`, so a clear and a justification amendment are each one readable history entry.
- The flag history is append-only: clearing writes a new state, it never deletes the prior record.
- Out of scope: the override interaction (`T-C1-47`); the UI (`T-C1-48`).

## Acceptance criteria

**Given** an Incident whose flag is set with an uplift applied **When** an agent clears it with a justification **Then** the effective Impact returns to the underlying assessed value, Priority is re-derived through the matrix, and one event carries actor, justification, previous and new Impact and Priority.

**Given** an agent changing only the justification **When** it commits **Then** the flag state is unchanged and the amendment appears as its own entry in the activity history.

**Given** a cleared flag **When** the Incident is read later **Then** the history still shows that the flag had been set, by whom, why, and the interval between set and clear.

**Given** either operation invoked with the system actor **When** it executes **Then** it is refused by the same rule as `T-C1-45`.
