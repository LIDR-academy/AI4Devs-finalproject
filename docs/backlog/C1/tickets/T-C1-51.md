# [C1] T-C1-51 · `TransitionIncidentUseCase` with typed refusal and terminal-state protection

## Context

`US-C1-15` needs one authorized entry point for state movement so the gates that hang off it — categorization on exit from `New` (`T-C1-25`), resolution code and notes on entry to `Resolved` (`T-C1-54`), and the clock signals on `Pending` (`T-C1-57`) — compose in one place instead of being re-checked per route.

## Scope

- `TransitionIncidentUseCase` in `libs/incident/application`, authorizing the actor and delegating validation to the aggregate.
- Typed domain errors mapped to contract error codes by the existing exception filter (`T-C10-40`); no transition failure escapes as a `500`.
- Post-commit publication of `IncidentStateChanged` and of any gate-specific event raised in the same transaction.
- Contract DTOs and the HTTP route in `apps/api`.
- Out of scope: the resolution gate itself (`T-C1-54`); the pause and resume signals (`T-C1-57`); the UI (`T-C1-52`).

## Acceptance criteria

**Given** an authorized actor and an allowed transition **When** the use case executes **Then** the state changes, the change is persisted, and the events publish after commit.

**Given** a disallowed transition **When** the use case executes **Then** it is refused with a typed error naming current and target state, nothing is persisted, and the HTTP response carries an explicit error code rather than a `500`.

**Given** an actor without the transition permission **When** they invoke it **Then** it is denied with `403` and nothing changes.

**Given** a transition refused by the categorization gate **When** the response returns **Then** the error names the missing category, distinguishable from a plain disallowed-transition error.
