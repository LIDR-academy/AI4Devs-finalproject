# [C1] T-C1-98 · Duplicate-proposal UI at logging and triage

## Context

`US-C1-31` requires proposals at **logging or triage** — the two moments where convergence is still cheap. They must read as proposals, with accept and dismiss both available, and dismissal must be as easy as acceptance or agents will link wrongly to clear the panel.

## Scope

- Proposal panel on the agent intake surface and the triage view, listing candidates with enough context — reference, short description, affected service, subject, age — for a decision without opening each one.
- Accept and dismiss actions per candidate, both keyboard-operable and announced, wired to `T-C1-97`.
- Explicit empty state when nothing is proposed; loading and error states defined; the panel never blocks logging.
- Dismissed candidates removed from the panel and not shown again for the pair.
- Out of scope: the query (`T-C1-96`); the decision use cases (`T-C1-97`); the link panel itself (`T-C1-85`).

## Acceptance criteria

**Given** candidates returned **When** the panel renders **Then** each shows reference, short description, affected service, subject and age, and both accept and dismiss are offered with equal prominence.

**Given** an agent accepting a candidate **When** it commits **Then** the duplicate link appears in the links panel with its direction stated.

**Given** an agent dismissing a candidate **When** the panel refreshes **Then** the candidate is gone and does not return for that pair.

**Given** the detection request failing or returning nothing **When** the agent continues **Then** logging and triage proceed unaffected, with an explicit empty or error state rather than a blank region.
