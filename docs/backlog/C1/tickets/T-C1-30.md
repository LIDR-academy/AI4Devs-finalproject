# [C1] T-C1-30 · Server-side derivation, the not-yet-derived state and `PriorityChanged`

## Context

`US-C1-08` requires the server to derive and persist Priority whenever Impact or Urgency is set or changed; requires an Incident whose assessment is incomplete to report Priority as **explicitly "not yet derived"** rather than defaulting to a middle value that could be mistaken for a real assessment; and requires every Priority change, from any cause, to publish an event carrying the previous and new Priority **and the reason for the derivation**.

That event is what `C7` consumes to re-evaluate SLA targets (`FR-SLA-04`) and what `C18` records. This epic publishes it; neither consumer is written here.

## Scope

- Assessment mutators on the `Incident` aggregate that re-derive Priority through `PriorityCalculator` on every Impact or Urgency change.
- An explicit not-yet-derived Priority state, distinct from every real Priority level, surfaced in the contract rather than as a null the client must interpret.
- `PriorityChanged` domain event carrying previous Priority, new Priority, the derivation reason and the matrix version applied.
- `AssessIncidentUseCase` in `libs/incident/application` authorizing the prioritization permission and publishing post-commit.
- Out of scope: the override (`T-C1-32` → `T-C1-34`); the flag-driven derivation (block E); the SLA re-evaluation itself (`C7`, reached through `T-C1-58`).

## Acceptance criteria

**Given** an Incident with Impact and Urgency assessed **When** either is changed **Then** Priority is re-derived server-side, persisted, and exactly one `PriorityChanged` event is published after commit carrying previous, new, reason and matrix version.

**Given** an Incident whose Impact or Urgency is not yet assessed **When** it is read **Then** Priority is the explicit not-yet-derived value, and no middle-level Priority is returned.

**Given** a client that posts a Priority **When** the assessment use case executes **Then** the posted value is ignored and the derived value is persisted.

**Given** an actor without the prioritization permission **When** they attempt to assess **Then** it is denied with `403` and nothing changes.
