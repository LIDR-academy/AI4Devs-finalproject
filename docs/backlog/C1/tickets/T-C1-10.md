# [C1] T-C1-10 · Requester intake form — plain language, mobile, WCAG 2.1 AA

## Context

`US-C1-01` requires the requester-facing intake form to use plain language with no untranslated ITSM vocabulary (`NFR-USE-01`), to be operable on a mobile device (`NFR-USE-04`), to meet WCAG 2.1 AA, and to state for every validation error what happened and what to do next (`NFR-USE-05`).

**Blocked by finding F29.** `FR-INC-01` is ambiguous about whether a requester may set the *structured* competition subject. This backlog reads it as: **requesters supply free text, agents set the structured reference** (`US-C1-01`, `US-C1-03`). The form is built to that reading, with a free-text competition description and no structured subject picker. If the Product Owner confirms the opposite reading, this form and the permissions of `T-C1-14` and `T-C1-16` change. The rest of the form is unaffected and buildable now.

## Scope

- Routed intake page in `libs/incident/feature` composing presentational components from `libs/incident/ui` and primitives from `libs/shared/ui`; hand-built HTML and SCSS over the design tokens, no third-party component library.
- Reactive Form bound to the requester DTO of `T-C1-08`; `OnPush` on every component; built-in control flow.
- All strings through Transloco; no hardcoded UI text.
- Free-text field for competition context; **no** Impact, Urgency, Priority or competition-flag control anywhere in the form.
- Error summary and per-field messages that state the remedy, announced through the `aria-live` region from `T-C10-14`.
- Out of scope: knowledge suggestions (`T-C1-90`); the scope-rule redirect surface (`T-C1-88`); the structured subject picker (`T-C1-16`).

## Acceptance criteria

**Given** a requester on the intake form **When** it is rendered **Then** it presents no Impact, Urgency, Priority or competition-in-progress control, and the page source contains no such input at any breakpoint.

**Given** a keyboard-only user on a 360px viewport **When** they complete and submit the form **Then** every control is reachable and operable without a pointer, no horizontal scrolling is required, and focus is managed across the submission.

**Given** a submission that fails validation **When** the response returns **Then** each message states what happened and what to do next in the active language, and the error summary is announced.

**Given** a successful submission **When** it returns **Then** the reference number is shown and the requester is told where to track the Incident.
