# [C1] T-C1-63 · Auto-close rule, configurable period and system-actor attribution

## Context

`US-C1-19` requires the confirmation period to be read from **validated configuration through `ConfigService`** with a documented default, with boot failing fast if it is absent or not a positive duration; requires a `Resolved` Incident whose period has elapsed with no response to transition to `Closed`, **attributed to the system actor and not to the last agent who touched it** (`FR-AUD-02`), recording the reason “auto-closed, no response”; and requires the elapsed-time evaluation to use `ClockPort` against persisted UTC timestamps so a restart neither closes early nor misses the window (ADR-009).

Configuration and rule ship together: a rule whose period arrives later would have no defined boundary to test against.

## Scope

- Confirmation period in validated configuration with a documented default; boot fails fast on absent, zero, negative or non-duration values.
- `AutoCloseResolvedIncidentsUseCase` evaluating the window predicate of `T-C1-59` on `ClockPort` and closing the qualifying Incidents.
- Closure attributed to the **system actor** of `FR-AUD-02`, with the reason recorded and the event distinguishable from an agent-driven closure.
- Incidents no longer in `Resolved` — including those the requester rejected — are skipped.
- Out of scope: the scheduler mechanism itself, which belongs to `C12` workflow automation; this ticket exposes the use case and asserts it in isolation. Also out of scope: any interaction with the competition flag, which `T-C1-45` forbids for every automated path.

## Acceptance criteria

**Given** the confirmation period absent, zero, negative or non-numeric **When** the application boots **Then** it fails fast naming the key and does not start.

**Given** a `Resolved` Incident whose period has elapsed with no response **When** the rule runs **Then** it moves to `Closed`, the actor is the system actor, and the reason “auto-closed, no response” is recorded.

**Given** an Incident the requester rejected before the period elapsed **When** the rule runs **Then** it is not auto-closed, because it is no longer in `Resolved`.

**Given** a process restart spanning the boundary **When** the rule next runs **Then** the same Incidents qualify as would have without the restart — the evaluation reads persisted UTC timestamps, not runtime state.

**Given** the auto-close path **When** it executes **Then** it touches no competition-in-progress flag, asserted by the caller enumeration of `T-C1-45`.
