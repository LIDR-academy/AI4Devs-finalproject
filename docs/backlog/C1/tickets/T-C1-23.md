# [C1] T-C1-23 · Taxonomy administration screen

## Context

`US-C1-06` gives the System Administrator a surface to maintain the taxonomy as data. Per `CLAUDE.md` §3 and ADR-010 it is **hand-built** from `libs/shared/ui` primitives and the per-context `type:ui` library — no Angular Material, no CDK, no third-party component library, and no `::ng-deep` or hardcoded colors.

## Scope

- Routed administration page in `libs/incident/feature` listing the three-level tree with add, rename, deactivate and reorder actions.
- Reorder operable by keyboard as well as pointer, with the new position announced — a drag-only interaction would fail WCAG 2.1 AA.
- Delete action surfacing the typed in-use refusal as an actionable message that offers deactivation, rather than a generic error.
- All strings through Transloco; every component `OnPush`; styling through the design tokens only.
- Out of scope: the picker used at intake and triage (`T-C1-24`); the use cases (`T-C1-22`).

## Acceptance criteria

**Given** the administration page **When** an administrator adds, renames, deactivates and reorders nodes **Then** each change is persisted and the tree reflects it without a full reload.

**Given** a delete refused because the node is in use **When** the response returns **Then** the message names the constraint and offers deactivation as the next action.

**Given** a keyboard-only user **When** they reorder a node **Then** the move is performed and the new position is announced through the live region.

**Given** the page **When** it is inspected **Then** it imports no third-party component library and contains no hardcoded color or spacing value.
