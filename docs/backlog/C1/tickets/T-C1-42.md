# [C1] T-C1-42 · One causal event carrying flag, justification, Impact and Priority transitions

## Context

`US-C1-11` requires that when an Incident's Priority changes because of the flag, **one event** carries the flag change, the justification, the previous and new Impact and the previous and new Priority — **so the causal chain is readable in the activity history rather than appearing as two unrelated changes**.

This is a specific, falsifiable property and the easiest one in the epic to lose: emitting `CompetitionImpactFlagged` and `PriorityChanged` separately is the natural implementation and produces exactly the history the story forbids.

## Scope

- `CompetitionImpactFlagged` domain event carrying, in one payload: flag state before and after, justification, actor, `ClockPort` timestamp, Impact before and after, Priority before and after.
- Suppression of a separate `PriorityChanged` emission for the same transaction, so the flag-driven Priority movement is reported once, causally.
- Post-commit publication; `C18` records it and `C7` reads the Priority movement from it. Neither consumer is written here.
- Out of scope: the write path and authorization (`T-C1-43`); the clearing path, which emits the same event shape (`T-C1-46`).

## Acceptance criteria

**Given** a flag set that changes Priority **When** the transaction commits **Then** exactly one event is published for that change, carrying flag before/after, justification, actor, timestamp, Impact before/after and Priority before/after.

**Given** that same transaction **When** the published events are enumerated **Then** no separate `PriorityChanged` event appears for the same Priority movement.

**Given** a flag set that does **not** change Priority — the matrix maps the raised pair to the same level **When** it commits **Then** one event is still published, showing the Impact movement and an unchanged Priority, so the action is not invisible.

**Given** the event **When** an activity-history consumer renders it **Then** the causal chain from justification to Priority is reconstructable from that single entry.
