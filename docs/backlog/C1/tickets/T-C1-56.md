# [C1] T-C1-56 · Resolution form with code selection and notes

## Context

`US-C1-16` is about being stopped from resolving without saying how — so the form exists to make stating the resolution the path of least resistance, while the server remains the authority (`T-C1-54`).

## Scope

- Resolution form in `libs/incident/feature` composed from `libs/incident/ui` and `libs/shared/ui`, opened from the lifecycle actions of `T-C1-52`.
- Resolution code selector fed from the configurable list, labels through Transloco, keyboard-operable.
- Notes field with the server refusal for blank or whitespace-only content surfaced and announced.
- Previous resolutions shown when the Incident has been resolved before, so the agent can see what was tried.
- Out of scope: the gate itself (`T-C1-54`); the code list (`T-C1-53`).

## Acceptance criteria

**Given** the form **When** an agent submits with no code or with whitespace-only notes **Then** the server refusal is surfaced with a message stating what is required, and the Incident state is unchanged in the view.

**Given** a valid code and notes **When** the form is submitted **Then** the Incident shows as `Resolved` and the requester confirmation window is stated to the agent.

**Given** an Incident resolved before and reopened **When** the form opens **Then** the previous resolution is visible and the fields are empty, so the previous values cannot be submitted by inertia.

**Given** a keyboard-only user **When** they complete the form **Then** every control is reachable, and the outcome is announced through the live region.
