# [C1] T-C1-12 · Agent single-flow intake surface with no loss of typed data

## Context

`US-C1-02` requires reporter lookup, description, affected service, category, competition subject and the assessment fields to be reachable in **one continuous flow**, with no forced navigation away and no loss of typed data (`NFR-USE-02`). The driving scenario is an agent keeping a referee on the phone mid-match.

This is a distinct surface from the requester form of `T-C1-10`: it exposes the priority-bearing fields the requester form must never show.

## Scope

- Routed agent intake page in `libs/incident/feature`, composed from `libs/incident/ui` and `libs/shared/ui`, `OnPush` throughout.
- One Reactive Form covering the whole flow; sections are progressive disclosure within the page, never separate routes.
- Draft retention: typed data survives an in-page lookup, a validation failure and an accidental navigation, and is restored with the user told it was restored.
- Assessment fields — Impact, Urgency, competition-in-progress flag entry point — present and permission-gated on the client, with the server remaining the authority (`T-C1-08`, `T-C1-44`).
- Out of scope: reporter lookup itself (`T-C1-13`); the subject picker (`T-C1-16`); the flag interaction detail (`T-C1-48`).

## Acceptance criteria

**Given** an agent mid-flow **When** they complete reporter lookup, categorization and assessment **Then** no step navigates away from the page and no typed value is lost between steps.

**Given** an agent who has typed a long description **When** submission fails validation **Then** every entered value is still present and focus moves to the first field in error.

**Given** an agent without the prioritization permission **When** the page renders **Then** the assessment controls are not offered, and the server rejects them independently if they are sent anyway.

**Given** the page **When** it is exercised with a keyboard only **Then** the whole flow completes without a pointer and meets WCAG 2.1 AA.
