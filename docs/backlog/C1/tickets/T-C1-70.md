# [C1] T-C1-70 · Requester comment thread — mobile, WCAG 2.1 AA

## Context

`US-C1-23` lets a requester follow the conversation on their ticket and reply, so they can answer the agent questions without opening a second ticket. It requires the thread to be **usable and accessible to WCAG 2.1 AA on a mobile device**, since officials and organizers operate from venues (`NFR-USE-04`).

The response contains only public entries because the server filters them (`T-C1-67`); the client does not filter, and a test asserts it does not.

## Scope

- Requester thread component in `libs/incident/ui` and its host page in `libs/incident/feature`, rendering the entries the API returned.
- Comment composer with the server refusal surfaced and announced; new entries announced through the live region.
- Mobile layout with no horizontal scrolling at 360px, touch targets meeting the AA target-size guidance, and full keyboard operability.
- An explicit assertion that the frontend applies **no** visibility filter of its own — if the server ever sent an internal entry, the bug would surface rather than be masked.
- Out of scope: the agent timeline (`T-C1-69`); the server filtering (`T-C1-67`).

## Acceptance criteria

**Given** an Incident with public and internal entries **When** the requester thread renders **Then** the rendered entries equal the API response exactly, with no client-side filtering step.

**Given** a requester posting a comment **When** it commits **Then** it appears in the thread attributed to them and the addition is announced.

**Given** a 360px viewport **When** the thread and composer are used **Then** no horizontal scrolling is required and every control is operable by touch and by keyboard.

**Given** the thread **When** it is checked against WCAG 2.1 AA **Then** contrast, focus visibility, target size and reading order all pass.
