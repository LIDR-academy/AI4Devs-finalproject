# [C1] T-C1-33 · `OverridePriorityUseCase`, permission gate, persistence and contracts

## Context

`US-C1-10` requires a user without the prioritization permission attempting an override **by any path** to be denied with `403` by the **use-case-level predicate**, with nothing changed; and requires an event carrying actor, previous value, new value and the justification text to be published for the audit trail.

Authorization lives in the application layer per `ARCHITECTURE.md` §9, not in a controller decorator alone — that is what makes "by any path" true.

## Scope

- `OverridePriorityUseCase` in `libs/incident/application`, authorizing the prioritization permission through the resolved `Actor`.
- `PriorityOverridden` domain event carrying actor, previous Priority, new Priority and the justification, published post-commit.
- Persistence and migration for the overridden level, the flag, the justification and the retained derived level.
- Request and response DTOs in `libs/shared/contracts`, and the HTTP route in `apps/api`.
- Out of scope: the domain rule (`T-C1-32`); the return-to-derived action (`T-C1-34`); the audit entry itself (`C18`).

## Acceptance criteria

**Given** an authorized agent submitting an override with a justification **When** it commits **Then** the Priority becomes the overridden value, the derived value remains readable, and exactly one `PriorityOverridden` event is published after commit.

**Given** an actor without the prioritization permission **When** they invoke the use case directly and separately through the HTTP route **Then** both are denied with `403`, nothing is persisted and no event is published.

**Given** an override request with no justification field at all **When** it is posted **Then** validation refuses it before the use case runs, and the domain rule refuses it if the use case is invoked directly.

**Given** the persisted Incident **When** it is reloaded **Then** overridden level, flag, justification and derived level all round-trip unchanged.
