# [C1] T-C1-48 · Flag set, change and clear UI with justification and visible history

## Context

`US-C1-11` requires the justification to be visible to agents **wherever the flag is displayed**, and `US-C1-13` requires the history to keep showing that the flag had been set, by whom, why and for how long, even after it is cleared. `US-C1-12` puts the flag on the agent surface only — and the server, not this component, is the control (`T-C1-44`).

## Scope

- Flag control on the agent Incident view: set, amend justification, and clear, each requiring a justification before submission, each surfacing the server outcome.
- The flag is never rendered without its justification and setting actor.
- Flag history panel showing every set, amendment and clear with actor, timestamp and duration held.
- Presentation of the causal chain from one event: the justification and the resulting Impact and Priority movement appear as one history entry, matching `T-C1-42`.
- The control is absent for a requester and for an agent without the permission, with the server refusal still the authority.
- Out of scope: the ceiling message wording, which depends on the **F24** decision (`T-C1-41`) — the component renders whatever typed outcome the server returns.

## Acceptance criteria

**Given** an agent with the permission **When** they set the flag without typing a justification **Then** submission is refused and the server message is surfaced and announced.

**Given** an Incident with the flag set **When** any agent view renders it **Then** the justification and the setting actor are shown with it, in every place the flag appears.

**Given** an Incident whose flag was set and later cleared **When** the history is read **Then** it shows the set, the reason, the actor, the clear and the interval between them, as separate readable entries.

**Given** a flag change that moved Priority **When** the history entry renders **Then** the justification, the Impact movement and the Priority movement appear as one causal entry rather than as unrelated changes.

**Given** a requester or a permission-less agent **When** the view renders **Then** no flag control is offered, and a crafted request is still refused by the server.
