# [C1] T-C1-74 · Reassignment UI showing the full assignment path

## Context

`US-C1-24` exists so **routing mistakes are visible and reassignment ping-pong can be measured**. A UI that shows only the current assignee defeats the purpose of the append-only history; the path is the point.

## Scope

- Reassignment action on the agent Incident view, targeting a Resolver Group or an individual, fed by the `C14` read surface through `incident/data-access`.
- Assignment history panel rendering every entry in order with target, actor and timestamp.
- Server refusals surfaced with their typed reason; loading and error states always defined.
- Hand-built components, `OnPush`, design tokens, keyboard-operable, WCAG 2.1 AA.
- Out of scope: escalation actions (`T-C1-76`); Resolver Group administration, which belongs to `C14`.

## Acceptance criteria

**Given** an Incident reassigned several times **When** an agent opens it **Then** the full assignment path is visible in order without an extra navigation.

**Given** the reassignment action **When** an agent selects a target **Then** groups and individuals are both selectable, distinguishable, and reachable by keyboard.

**Given** a refused reassignment **When** the response returns **Then** the reason is shown and announced, and the previous assignee is still displayed.

**Given** the `C14` read surface unavailable **When** the action is opened **Then** an explicit error state is shown rather than an empty selector.
