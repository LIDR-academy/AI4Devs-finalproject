# [C1] T-C1-29 · `PriorityCalculator` domain service

## Context

`US-C1-08` requires Priority to be derived from the configured Impact × Urgency matrix by a **pure function in the `incident` domain, unit-tested with no infrastructure**. `ARCHITECTURE.md` §6.2 names it `PriorityCalculator` and records what it enforces: Priority is *derived*, never chosen by a requester (risk **R8**).

This is the single derivation point in the product. The competition-in-progress flag of `FR-INC-05` never writes a Priority directly — it raises Impact and comes back through here (`T-C1-40`).

## Scope

- `PriorityCalculator` domain service in `libs/incident/domain` with `derive(impact, urgency, matrix): Priority`.
- Pure: no clock, no I/O, no configuration lookup — the matrix is injected as a value.
- Exhaustive unit tests over the full Impact × Urgency cross-product against a fixture matrix.
- Out of scope: when derivation is triggered and how the result is persisted (`T-C1-30`); the override (`T-C1-32`); the uplift (`T-C1-40`).

## Acceptance criteria

**Given** an assessed Impact, an Urgency and a complete matrix **When** `derive` is called **Then** it returns the Priority the matrix maps to that pair, for every pair in the cross-product.

**Given** the same three inputs **When** `derive` is called repeatedly **Then** it returns the same result every time and mutates nothing.

**Given** the domain service **When** it is inspected **Then** it performs no I/O, reads no configuration and calls no clock.

**Given** the unit tests **When** they run **Then** they require no database, no HTTP and no NestJS container.
