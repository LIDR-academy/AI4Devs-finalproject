# [C1] T-C1-82 · Link persistence, migration and bidirectional read

## Context

`US-C1-20` requires a link between two Incidents to be **visible from both Incidents**. Storing one row and reading it from one side only is the natural implementation and the one that produces a link the other Incident cannot see.

## Scope

- TypeORM entity, mapper and migration for links, keyed by source, target kind, target identifier and link kind, in the `incident` schema.
- Bidirectional read: loading either Incident yields the link, with the direction preserved so a duplicate still reads correctly from both ends.
- Uniqueness constraint preventing the same link being recorded twice between the same pair.
- Out of scope: the value object and its rules (`T-C1-81`); the use cases (`T-C1-83`); target-side records in other contexts.

## Acceptance criteria

**Given** a link created from Incident A to Incident B **When** B is loaded **Then** the link is present on B with the direction intact.

**Given** the same pair and link kind **When** the link is created twice **Then** the second attempt is refused by the constraint rather than creating a duplicate row.

**Given** a link to a target in another context **When** it is persisted **Then** only the target kind and identifier are stored; no foreign key to another context schema exists.

**Given** the migration **When** it is run and reverted **Then** it succeeds both ways and leaves no residual object.
