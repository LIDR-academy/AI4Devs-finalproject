# [C1] T-C1-26 · Impact × Urgency matrix aggregate with the total-coverage invariant

## Context

`US-C1-09` requires **every** combination of the defined Impact and Urgency levels to map to exactly one Priority, and requires the configuration to be unsavable with a combination left unmapped. That total-coverage invariant is what makes the derivation of `US-C1-08` a total function rather than one with a silent default.

`ImpactLevel`, `UrgencyLevel` and `Priority` are shared-kernel primitives delivered by `C10` (`T-C10-08`); this aggregate configures the mapping between them for the `incident` context.

## Scope

- `PriorityMatrix` aggregate in `libs/incident/domain` holding one Priority per (Impact, Urgency) pair.
- Total-coverage invariant enforced at construction and at every mutation: an incomplete matrix cannot exist as a valid aggregate.
- Domain event on change, carrying the previous and new mapping for the audit trail (`FR-AUD-05`).
- Out of scope: persistence, versioning and boot validation (`T-C1-27`); the calculator that consumes it (`T-C1-29`); the screen (`T-C1-28`).

## Acceptance criteria

**Given** a matrix with one combination unmapped **When** it is constructed or saved **Then** a typed domain error names the missing combination and no valid aggregate exists.

**Given** a matrix mapping one combination to two Priorities **When** it is constructed **Then** it is refused — each pair maps to exactly one Priority.

**Given** a complete matrix **When** a mapping is changed **Then** exactly one domain event is returned carrying the pair, the previous Priority and the new Priority.

**Given** the aggregate **When** it is unit-tested **Then** the coverage invariant is asserted over the full cross-product with no infrastructure present.
