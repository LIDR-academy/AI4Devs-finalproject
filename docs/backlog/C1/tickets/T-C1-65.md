# [C1] T-C1-65 · `IncidentEntry`, `NoteVisibility` and the internal-by-default rule, with persistence

## Context

`US-C1-22` requires public comment and internal work note to be **two distinct types on the aggregate, chosen explicitly**, and requires that **when the type is not stated the default is internal — the safe default is to withhold**. `ARCHITECTURE.md` §6.2 models this as `WorkNote.visibility`, a first-class value object, enforcing that internal notes can never leak to requesters (`NFR-SEC-04`).

The default matters more than it looks: a nullable visibility column defaulting to public is the single change that would turn every unlabelled entry into a disclosure.

## Scope

- `IncidentEntry` entity within the `Incident` aggregate with a non-nullable `NoteVisibility` value object.
- Construction with no stated visibility yields **internal**, asserted in the domain rather than relying on a database default.
- TypeORM entity, mapper and migration with a non-nullable visibility column and no public default at any layer.
- `IncidentEntryAdded` domain event carrying the visibility, so consumers can filter without re-reading the aggregate.
- Out of scope: the use cases (`T-C1-66`); the outbound-payload exclusion (`T-C1-67`); the immutability rule (`T-C1-68`); attachment inheritance (`T-C1-18`).

## Acceptance criteria

**Given** an entry created with no stated visibility **When** it is read **Then** its visibility is internal, asserted at the domain level with no database round trip.

**Given** the persistence layer **When** the schema is inspected **Then** the visibility column is non-nullable and has no default that would resolve to public.

**Given** an entry of each type **When** it is saved and reloaded **Then** the visibility round-trips exactly.

**Given** any entry added **When** the events are read **Then** exactly one `IncidentEntryAdded` carries the entry visibility.
