# [C1] T-C1-53 · Resolution-code list: configurable, stable identifiers, translatable labels

## Context

`US-C1-16` requires the resolution code to come from a **configurable list with stable identifiers and translatable labels, not from free text** — because the resolution data behind trend analysis and knowledge creation depends on it being categorical.

Same shape as the taxonomy of `T-C1-20` and `T-C1-21`, at one level rather than three.

## Scope

- `ResolutionCode` reference data in `libs/incident/domain` with stable identifiers, ordering and an active flag.
- TypeORM entity, mapper, migration and a seed migration with a documented default set.
- Labels resolved through `nestjs-i18n` keyed by identifier (`NFR-I18N-05`).
- Deactivated codes stay valid on existing Incidents and are not offered for new resolutions, mirroring `T-C1-21`.
- Out of scope: the resolution gate (`T-C1-54`); the resolution form (`T-C1-56`).

## Acceptance criteria

**Given** the resolution code list **When** it is read in two locales **Then** the identifiers are identical and only the labels differ.

**Given** a deactivated code **When** new-resolution options are read and an Incident already resolved under it is read **Then** it is absent from the options and still valid on the existing record.

**Given** a resolution attempted with a code outside the list **When** it is submitted **Then** it is refused; free text is never accepted as a code.

**Given** the migration **When** it is run and reverted **Then** it succeeds both ways and leaves the default set in place after a re-run.
