# [C1] T-C1-03 · `TicketReference` policy and the `nextReference()` repository port

## Context

`US-C1-05` requires every Incident to carry a human-readable reference number from the moment it is created, quotable aloud on a phone call. `ARCHITECTURE.md` §6.2 places `TicketReference` as an immutable value object generated **by the repository port** — `IncidentRepositoryPort.nextReference()` — not by the aggregate, so the uniqueness guarantee can live in the database (`T-C1-04`).

The `TicketReference` primitive itself is part of the shared kernel delivered by `C10` (`T-C10-08`). This ticket adds the Incident context policy over it and the port that yields one.

## Scope

- The reference format policy for Incidents: prefix, separator and numeric part, stable across environments and unambiguous when read aloud (no characters that sound alike in the spoken alphabet).
- `IncidentRepositoryPort` declared in `libs/incident/domain` as a TypeScript `interface` plus a matching `Symbol` injection token, exposing `nextReference()`, `findById()` and `save()`.
- Parsing and formatting helpers with round-trip unit tests.
- Out of scope: the sequence, the unique constraint and the migration (`T-C1-04`); any adapter implementation; the aggregate itself (`T-C1-05`).

## Acceptance criteria

**Given** the reference format policy **When** a reference is rendered **Then** it matches the documented shape exactly, contains no character pair that is ambiguous when spoken, and parsing the rendered value returns the original components.

**Given** `IncidentRepositoryPort` **When** the `incident` domain library is inspected **Then** the port is an interface with an injection token and no framework, ORM or I/O import, and `pnpm nx lint incident-domain` passes.

**Given** the format helpers **When** they are unit-tested **Then** the tests run with no database and no HTTP.
