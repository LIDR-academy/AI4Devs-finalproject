# [C1] T-C1-69 · Agent entry timeline with a visible public / internal distinction

## Context

`US-C1-22` requires public and internal entries to be **visually and semantically distinguishable at a glance**, so an agent always knows what the requester can see. Semantically as well as visually: an agent using a screen reader must get the same signal, so the distinction cannot rest on a background color.

## Scope

- Entry timeline component in `libs/incident/ui` rendering both entry types in one chronological stream.
- Distinction carried by an accessible label and a text or icon cue as well as a token-based visual treatment — never by color alone (WCAG 2.1 AA, non-text contrast and use-of-color).
- Entry composer with an explicit visibility choice, defaulting to internal, matching the server default of `T-C1-65`.
- Existing entries render as read-only; no reclassification control, per `T-C1-68`.
- Out of scope: the requester thread (`T-C1-70`); the server-side filtering (`T-C1-67`).

## Acceptance criteria

**Given** a timeline containing both entry types **When** an agent scans it **Then** each entry type is identifiable without relying on color, and the type is announced to a screen reader as part of the entry.

**Given** the composer **When** it opens **Then** the visibility choice is explicit and preselected to internal.

**Given** an agent about to post a public comment **When** they submit **Then** the fact that the requester will see it is stated before the entry is created.

**Given** an existing entry **When** an agent inspects it **Then** no control offers to change its type, and the correction path adds a new entry instead.
