# [C1] T-C1-97 · Detection as proposals: agent accept and dismiss recorded, dismissals not repeated

## Context

`US-C1-31` is emphatic that detection produces **proposals**: **the agent decides, and no link is created automatically** — accepting one creates the duplicate link of `US-C1-20`. It further requires the decision to be recorded, so **proposal precision is measurable and dismissals do not keep reappearing for the same pair**.

An automatic link would be a system-made judgement about which report is the real one, and the story rules it out.

## Scope

- `AcceptDuplicateProposalUseCase` delegating to the link use case of `T-C1-83` — one code path for duplicate links, no second one.
- `DismissDuplicateProposalUseCase` recording the dismissal for the pair, so the same pair is not proposed again.
- Proposal decisions persisted with actor and timestamp, giving `C17` the data to measure precision later.
- No code path that creates a link from a detection result without an agent decision, asserted by a caller enumeration.
- Out of scope: the detection query (`T-C1-96`); the UI (`T-C1-98`); precision reporting (`C17`).

## Acceptance criteria

**Given** a detected candidate **When** detection completes **Then** no link exists until an agent accepts, asserted by inspecting the links after a detection run.

**Given** an agent accepting a proposal **When** it commits **Then** a duplicate link is created through the same use case as a manual link, with the direction explicit.

**Given** an agent dismissing a proposal **When** detection runs again for the same pair **Then** the pair is not proposed again, and the dismissal is readable with its actor and timestamp.

**Given** the detection path **When** its callers are enumerated **Then** none reaches the link creation without passing through an agent decision.
