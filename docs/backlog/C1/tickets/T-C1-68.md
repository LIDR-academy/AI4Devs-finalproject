# [C1] T-C1-68 · Entry-type immutability after creation

## Context

`US-C1-22` requires that an attempt to change an entry type from internal to public or the reverse **follows a single documented rule rather than being silently permitted** — because text already sent to a requester cannot be unsent.

**Blocked by finding F27.** `FR-INC-11` defines the two entry types but is **silent on reclassification**. The direction matters in both directions: an internal note made public is a **disclosure**; a public comment made internal is a **retraction of something the requester has already seen and possibly been notified about**. The story recommends **immutable after creation, correction by a new entry**, consistent with `NFR-AUD-02` — and marks it as needing Product Owner confirmation.

Build the recommended rule, in one place, so a different decision is a change to that one rule and not a redesign.

## Scope

- Entry visibility declared immutable on the aggregate: no mutator exists, so reclassification is impossible by absence of capability rather than by a guard that could be bypassed.
- A correction path: adding a new entry that references the one being corrected, leaving the original intact.
- Documentation of the rule at the definition site, naming finding **F27** as the pending confirmation.
- Out of scope: choosing the rule — a Product Owner decision; any migration that would be needed if reclassification is later permitted.

## Acceptance criteria

**Given** an existing entry **When** any code attempts to change its visibility **Then** no such operation exists on the aggregate, and the attempt does not compile.

**Given** an agent who posted an internal note that should have been public **When** they correct it **Then** they add a new public entry referencing the original, and the original is unchanged and still present.

**Given** the rule **When** the domain library is read **Then** it is documented once at the definition site, naming finding **F27**.

**Given** the decision is still open **When** the epic is reviewed **Then** this ticket is reported as blocked and `FR-INC-11` is not claimed complete on reclassification.
