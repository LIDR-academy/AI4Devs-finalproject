# [C1] T-C1-58 · `SlaPolicyAdapter` pause/resume wiring and restart-safe accounting

## Context

`ARCHITECTURE.md` §8 states it plainly: *“`incident` never imports `sla`. The `SlaPolicyAdapter` in `apps/api` is the only object that knows both.”* §5.4 confirms cross-context adapters live in the composition root, not in either context infrastructure library, and `type:app` is the only type allowed to reach across contexts.

This ticket delivers the **Incident side of the seam**: the adapter binding `SlaPolicyPort` (declared in `T-C1-07`) and subscribing the pause/resume signals of `T-C1-57`. **The clock arithmetic, the support schedule and the target recalculation are `C7`** (`FR-SLA-04`, `FR-SLA-08`) and are not written here; against an undeployed `C7` this adapter binds a null implementation and the Incident side is complete and testable without it.

## Scope

- `SlaPolicyAdapter` in `apps/api` implementing `SlaPolicyPort` — `attachFor`, `reevaluate`, `pause`, `resume` — and translating between Incident and SLA vocabulary.
- Subscription of `IncidentClockPaused` / `IncidentClockResumed` to the adapter, post-commit.
- A null adapter selected by configuration for environments where `C7` is not deployed, so the Incident path never fails because SLA is absent (`NFR-AVL-03`).
- Restart-safe accounting proven from the two persisted events rather than from adapter state.
- Out of scope: everything on the `sla` side — policy resolution, targets, business-hours schedules, breach detection. Those belong to `C7`.

## Acceptance criteria

**Given** an Incident entering and leaving a clock-stopping `Pending` state **When** the events publish **Then** the adapter receives exactly one pause and one resume, in order, each carrying the persisted UTC timestamp.

**Given** the null adapter selected **When** an Incident is logged, paused and resumed **Then** every Incident operation succeeds and no error surfaces to the caller.

**Given** a process restart between pause and resume **When** the adapter reconstructs the interval **Then** it derives it from the persisted events, and the result is identical to the no-restart case.

**Given** the dependency graph **When** it is inspected **Then** the only project depending on both `scope:incident` and `scope:sla` is `apps/api`.
