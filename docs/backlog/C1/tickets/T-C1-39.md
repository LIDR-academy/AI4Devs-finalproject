# [C1] T-C1-39 · `CompetitionImpactFlag` value object with mandatory justification

## Context

`US-C1-11` requires the flag to be refused with a **typed domain error** when submitted without a justification, with the flag remaining unset — and states explicitly that the justification is **mandatory in the domain model, not merely a required input**. It further requires the justification to be stored with the flag and visible to agents wherever the flag is displayed, so the assessment can be reviewed later.

This is the product's signature behavior (`epic-map.md` → `C1`, *Size*: the only epic that owns a domain-differentiating behavior). `ARCHITECTURE.md` §6.2 models `CompetitionImpactFlag` with `affectsCompetitionInProgress`, `justification`, `setBy` and `setAt`.

## Scope

- `CompetitionImpactFlag` value object in `libs/incident/domain` carrying the flag state, the justification, the setting actor and the `ClockPort` timestamp.
- Construction impossible without a non-blank justification and an actor — a typed domain error, not a validation annotation.
- Read model exposing the justification wherever the flag is exposed, so no surface can show the flag without its reason.
- Out of scope: the uplift application (`T-C1-40`); the ceiling case (`T-C1-41`); the event (`T-C1-42`); the write path and its authorization (`T-C1-43`).

## Acceptance criteria

**Given** a flag constructed with a blank, whitespace-only or absent justification **When** construction is attempted **Then** a typed domain error is raised and no flag value exists.

**Given** a flag constructed with a justification **When** it is read **Then** it carries the justification, the setting actor and the timestamp taken from `ClockPort`.

**Given** the flag exposed in any read model **When** the response is inspected **Then** the justification is present alongside it, and no representation exposes the flag alone.

**Given** the value object **When** it is unit-tested **Then** the tests run on `FixedClock` with no database and no HTTP.
