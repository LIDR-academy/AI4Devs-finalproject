# [C1] T-C1-15 · `CompetitionSubjectLookupPort`, the SCMS anti-corruption adapter and the free-text fallback

## Context

`US-C1-03` requires the competition instance to be resolved through the `CompetitionSubjectLookupPort` **anti-corruption layer** so SCMS vocabulary never leaks into the Incident model, and requires a free-text fallback recording the reference as unresolved when SCMS reference data is unreachable — so a ticket is never blocked by an unavailable external system (risk **R10**).

Port and both adapters are one ticket because the fallback is only meaningful as the second binding of the same port; splitting them would leave a port with one adapter and no way to test the degradation that is the point of the story.

## Scope

- `CompetitionSubjectLookupPort` in `libs/incident/domain` with its injection token, expressed entirely in Incident vocabulary.
- SCMS adapter in `libs/incident/infrastructure` translating SCMS reference data into `CompetitionSubject`, with a bounded timeout and typed unreachable error.
- Free-text fallback adapter producing an instance reference marked **unresolved**, persisted as such so the state is visible rather than indistinguishable from a resolved one.
- Adapter selection wired in `IncidentModule`; the domain never learns which one answered.
- Out of scope: the picker UI (`T-C1-16`); any write back to SCMS, which does not exist in this product.

## Acceptance criteria

**Given** SCMS reference data reachable **When** an agent resolves an instance **Then** a stable reference is stored, and no SCMS-specific field name, code or type appears anywhere in `libs/incident/domain`.

**Given** SCMS unreachable or timing out **When** the agent records the instance **Then** the fallback adapter is used, the Incident is created, and its reference is explicitly marked unresolved.

**Given** an Incident with an unresolved reference **When** it is read **Then** the unresolved state is part of the response, not inferred from a missing field.

**Given** the port **When** lint runs **Then** no `incident` project imports an SCMS client type outside `libs/incident/infrastructure`.
