# [C1] T-C1-90 · Suggestions at intake — keyboard-navigable, announced, non-blocking

## Context

`US-C1-29` requires suggestions to be shown **before submission**, to be **keyboard-navigable and screen-reader-announced**, and to **not block the requester from continuing to submit**. It also requires that when a requester opens a suggestion and returns to the form, **their entered data is preserved**.

Ranking and content belong to `C9`; this surface renders whatever the port returned.

## Scope

- Suggestion panel on the requester intake form, requesting suggestions as the description and category settle, debounced.
- Results as a keyboard-navigable list with the count and changes announced through the live region.
- Submission never gated on suggestions: the submit action stays enabled while suggestions load, fail or return empty.
- Draft retention across opening a suggestion and returning, matching the retention rule of `T-C1-12`.
- Out of scope: the port and adapters (`T-C1-89`); deflection detection (`T-C1-92`); the article reading surface (`C9`).

## Acceptance criteria

**Given** a requester typing a description and choosing a category **When** suggestions return **Then** they are shown before submission, are reachable by keyboard, and the count is announced.

**Given** the knowledge service unavailable or returning nothing **When** the form renders **Then** no suggestion section blocks the flow, no error is shown to the requester, and submission remains possible throughout.

**Given** a requester who opens a suggestion and returns **When** the form re-renders **Then** every entered value is preserved.

**Given** suggestions still loading **When** the requester submits **Then** submission proceeds; it is never gated on the suggestion request completing.
