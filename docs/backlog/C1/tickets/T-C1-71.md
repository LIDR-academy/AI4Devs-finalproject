# [C1] T-C1-71 · API-E2E: a requester never receives an internal work note on any channel

## Context

`US-C1-22` requires the absence of internal work notes from every channel to be **asserted by an explicit test for each channel**, and `NFR-SEC-04` makes it a security property rather than a presentation preference. `T-C1-67` implements the filtering; this ticket is the standing proof over the real stack, and it is the scenario that should keep passing as later epics add channels.

`agent: —` because this is **e2e-harness work on the backend platform**, in `apps/api-e2e` (`platform:backend`, `type:e2e`), matching the precedent of `T-C10-29`.

## Scope

- Cucumber feature and step definitions in `apps/api-e2e` driving a real API and PostgreSQL.
- Enumeration over every requester-reachable read path — Incident detail, entry list, list and search projections, any export — asserting no internal entry appears in any response body.
- Direct-identifier retrieval of an internal entry and of an internal attachment, asserting a refusal indistinguishable from not-found.
- A negative control: an agent reading the same Incident **does** receive the internal entries, so the test proves filtering rather than emptiness.
- Out of scope: notification payload assertions where `C16` is not deployed — the seam is asserted at the application layer by `T-C1-67` until then, and this scenario is extended when `C16` lands.

## Acceptance criteria

**Given** an Incident with public and internal entries **When** the requester calls every requester-reachable read path **Then** no internal entry text or identifier appears in any response body.

**Given** an internal entry identifier and an internal attachment identifier **When** the requester requests each directly **Then** both are refused indistinguishably from a non-existent record.

**Given** the same Incident **When** an agent reads it **Then** the internal entries are present, proving the assertion is about visibility and not about an empty fixture.

**Given** a new requester-reachable route added later **When** the enumeration runs **Then** it is included automatically and fails if it leaks.
