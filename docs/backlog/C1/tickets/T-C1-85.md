# [C1] T-C1-85 · Link surface with explicit degradation for undeployed target kinds

## Context

`US-C1-21` requires that when a link target kind whose owning context is **not yet deployed** is encountered, the surface **degrades explicitly**: the target kind is either not offered, or shown as unavailable with a stated reason — **never a broken link and never a silent empty section** (`NFR-USE-05`).

`C3` (Problem), `C4` (Change), `C5` (Release) and `C6` (Configuration Items) are **Phase 2 and do not exist**. This ticket delivers the Incident-side surface and its degradation; **no target-side behavior of those epics is written here**, and their acceptance belongs to them.

## Scope

- Links panel on the agent Incident view listing every link with its kind and target, grouped by kind.
- Availability of each target kind read from server-provided configuration; unavailable kinds are either hidden or shown disabled with a stated reason, per the configured presentation — never rendered as a dead link.
- Link and unlink actions for the available kinds, with the server refusal surfaced.
- Duplicate direction rendered explicitly, so an agent can tell the duplicate from the original.
- Out of scope: the Problem, Change, Release and Configuration Item detail surfaces, which belong to `C3`, `C4`, `C5` and `C6`; the Major Incident coordination surface, which belongs to `C13`.

## Acceptance criteria

**Given** target kinds whose contexts are not deployed **When** the links panel renders **Then** none appears as an actionable option that would fail, and any shown kind states why it is unavailable.

**Given** an Incident with no links **When** the panel renders **Then** it shows an explicit empty state rather than a blank region.

**Given** a duplicate link **When** it renders **Then** which Incident is the duplicate and which is the original is stated in text, not implied by order.

**Given** `C3` shipping later **When** its link kind is enabled in configuration **Then** the panel offers it with no frontend code change.
