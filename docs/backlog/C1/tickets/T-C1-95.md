# [C1] T-C1-95 · Conversion action in the agent UI, with the `C2` dependency declared

## Context

`US-C1-27` lets an agent correct a misfiled ticket without losing its reference number or history. The surface must make the consequences legible before the action, and must not offer the action at all when the `C2` side is absent — an offered action that always fails is worse than an absent one.

## Scope

- Conversion action on the agent Incident view, capturing the reason and stating that the reference and history are preserved.
- The action is offered only when the target type is available per server-provided configuration; otherwise it is absent or disabled with the reason stated.
- The typed state-equivalence refusal surfaced with the state named, rather than as a generic failure.
- Confirmation step stating what will change and what will not, keyboard-operable, announced.
- Out of scope: the domain rules and use case (`T-C1-93`, `T-C1-94`); the Service Request surfaces (`C2`).

## Acceptance criteria

**Given** the target type unavailable **When** the Incident view renders **Then** the conversion action is not offered as an operation that would fail, and any shown affordance states why it is unavailable.

**Given** a convertible Incident **When** the agent opens the action **Then** the confirmation states that the reference number and the history are preserved, and requires a reason.

**Given** an Incident in a state with no equivalent **When** conversion is attempted **Then** the refusal names the state and is announced.

**Given** a keyboard-only user **When** they convert **Then** the whole flow completes without a pointer.
