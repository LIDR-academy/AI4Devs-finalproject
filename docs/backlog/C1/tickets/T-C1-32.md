# [C1] T-C1-32 · Priority override domain rule: mandatory justification, derived value retained

## Context

`US-C1-10` requires an override submitted **without a justification** to be refused with a typed domain error, with the justification enforced **in the domain** and not by a required form field alone; and requires the derived value to be retained alongside the overridden one so both are visible. `ARCHITECTURE.md` §6.2 models this as `Priority.overridden` plus `overrideJustification`.

**Blocked by finding F30.** `FR-INC-04`'s override and `FR-INC-05`'s re-derivation can contradict each other and the PRD does not say which wins. `US-C1-10` assumes **the override stands until an agent explicitly returns the Incident to the derived value**. This ticket implements that assumption and marks it as such; the Product Owner must confirm it, because the alternative reading produces different P1 counts. The mandatory-justification rule and the dual-value retention are unaffected by the decision and are buildable now.

## Scope

- `Priority` value object extended in `libs/incident/domain` with the overridden flag, the override justification and the retained derived level.
- Mandatory non-blank justification enforced at the aggregate boundary as a typed domain error.
- Precedence rule stated **once**, in the domain, as a named predicate that `T-C1-34` and `T-C1-47` both consume — so the two mechanisms cannot disagree.
- Out of scope: the use case, permission and persistence (`T-C1-33`); the return-to-derived action (`T-C1-34`); the flag interaction test (`T-C1-47`); the UI (`T-C1-35`).

## Acceptance criteria

**Given** an override with a blank or whitespace-only justification **When** it is applied **Then** a typed domain error is raised and the Priority is unchanged.

**Given** an override with a justification **When** it is applied **Then** the Priority carries the overridden level, the overridden flag, the justification, and the previously derived level, all readable together.

**Given** an Incident with an overridden Priority **When** its Impact or Urgency later changes **Then** the derived value is recomputed and retained, and the effective Priority follows the single named precedence predicate rather than being decided at the call site.

**Given** the precedence predicate **When** the domain library is searched **Then** it is defined exactly once and is the only place the question is answered.
