# [C1] T-C1-83 · Link and unlink use cases with permission and audit events

## Context

`US-C1-20` requires link creation to be **published for the activity history**, and requires link removal to need the **link permission**, be **audited**, and leave the two records otherwise unchanged.

## Scope

- `LinkIncidentUseCase` and `UnlinkIncidentUseCase` in `libs/incident/application`, both gated on the link permission.
- `IncidentLinked` and `IncidentUnlinked` domain events carrying both ends, the link kind, the actor and the timestamp, published post-commit for `C18`.
- Refusal to link to a target kind whose owning context is not enabled, with a typed error naming the reason (`T-C1-85` renders it).
- Contract DTOs and the HTTP routes.
- Out of scope: the domain rules (`T-C1-81`); persistence (`T-C1-82`); the Major Incident parent path (`T-C1-84`); the audit entry itself (`C18`).

## Acceptance criteria

**Given** an agent with the link permission **When** they link two Incidents as duplicate or related **Then** the link is persisted, visible from both, and one `IncidentLinked` event is published after commit.

**Given** an agent removing a link **When** it commits **Then** the link is gone, one `IncidentUnlinked` event is published, and neither Incident is otherwise changed.

**Given** an actor without the link permission **When** they link or unlink **Then** it is denied with `403` and nothing changes.

**Given** a link to a target kind whose context is not enabled **When** it is attempted **Then** it is refused with a typed error naming the unavailable target kind.
