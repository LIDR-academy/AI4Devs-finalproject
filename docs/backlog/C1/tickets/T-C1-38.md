# [C1] T-C1-38 · Uplift administration screen

## Context

`US-C1-14` gives the System Administrator the ability to tune the escalation policy without a release. The screen's job is to make the uplift legible **on the Impact scale** — the story's explicit requirement that it not be an opaque number — so an administrator can see what the change will do before saving it.

## Scope

- Configuration page in `libs/incident/feature` presenting the uplift in Impact levels, with the resulting scale movement shown for each starting level.
- Server-side range refusal surfaced with the valid range stated; the client does not re-implement the rule.
- Hand-built controls from `libs/shared/ui`, Transloco strings, design tokens, `OnPush`.
- Out of scope: the ceiling behavior (`T-C1-41`), which is a domain decision blocked on **F24** — the screen states the configured behavior once it is decided, and does not invent it.

## Acceptance criteria

**Given** the page **When** an administrator selects an uplift **Then** the resulting Impact level is shown for each starting level on the scale before saving.

**Given** an out-of-range value **When** it is submitted **Then** the server refusal is surfaced with the valid range stated in the active language, and nothing is saved.

**Given** the page **When** it is operated by keyboard only **Then** every control is reachable and the resulting-level preview is announced.

**Given** the page **When** it is inspected **Then** it uses no third-party component library and no hardcoded color or spacing.
