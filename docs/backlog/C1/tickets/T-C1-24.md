# [C1] T-C1-24 · Category picker on the intake and triage surfaces

## Context

The taxonomy of `US-C1-06` is only useful where an Incident is categorized: the agent intake surface (`T-C1-12`) and the triage view. `US-C1-07` then gates exit from `New` on a category set **to the Item level**, so the picker must make reaching that level natural rather than optional-looking.

Deactivated nodes are excluded from the options by the server (`T-C1-21`); the client does not re-derive that rule.

## Scope

- Cascading three-level picker component in `libs/incident/ui`, driven by inputs and outputs only — no injected service.
- Taxonomy fetch and caching in `libs/incident/data-access`.
- Labels through Transloco keyed by stable identifier; the selected value emitted is always the Item-level identifier.
- Empty and error states defined; a partially chosen path is visibly incomplete rather than silently accepted.
- Out of scope: the domain gate (`T-C1-25`); the administration screen (`T-C1-23`).

## Acceptance criteria

**Given** the picker **When** a user selects Category and then Subcategory **Then** the Item level is offered and the emitted value is empty until an Item is chosen.

**Given** a deactivated node **When** the options are rendered **Then** it is absent, and the client applies no filtering rule of its own.

**Given** an Incident already carrying a deactivated category **When** it is opened for triage **Then** the existing value is displayed rather than cleared.

**Given** a keyboard-only user **When** they complete the three levels **Then** each level is reachable, the active option is announced, and no pointer is required.
