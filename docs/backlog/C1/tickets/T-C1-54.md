# [C1] T-C1-54 · `ResolveIncidentUseCase` gated on resolution code and notes

## Context

`US-C1-16` requires a transition to `Resolved` with a missing or blank resolution code or resolution notes to be **refused with a typed domain error, with the state unchanged**. On success the Incident enters `Resolved`, the resolution is recorded with actor and timestamp, and **the confirmation window of `US-C1-18` starts** (`T-C1-59`).

`ARCHITECTURE.md` §6.2 places this on the aggregate: `resolve()` refuses without a resolution code and notes.

## Scope

- `resolve(resolutionCode, notes)` on the `Incident` aggregate, refusing blank or whitespace-only notes as well as a missing code.
- `ResolveIncidentUseCase` in `libs/incident/application`, permission-gated, composing with the transition use case of `T-C1-51`.
- `IncidentResolved` event carrying actor, code, notes reference and `ClockPort` timestamp; it is what opens the confirmation window and what `C7` reads to stop the resolution clock.
- Out of scope: the code list (`T-C1-53`); re-resolution after a reopen (`T-C1-55`); the confirmation window mechanics (`T-C1-59`); FCR derivation (`T-C1-79`).

## Acceptance criteria

**Given** a transition to `Resolved` with no resolution code **When** it is attempted **Then** it is refused with a typed domain error and the state is unchanged.

**Given** a transition to `Resolved` with a code but blank or whitespace-only notes **When** it is attempted **Then** it is refused for the same reason — blank notes are not notes.

**Given** a valid code and notes **When** the transition commits **Then** the Incident is `Resolved`, the resolution is recorded with actor and timestamp, and `IncidentResolved` is published after commit.

**Given** the gate **When** it is unit-tested **Then** the tests run with no HTTP and no database, so the rule holds on every inbound path.
