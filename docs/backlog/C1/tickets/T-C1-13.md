# [C1] T-C1-13 · Reporter lookup with an explicit "reporter must exist" path

## Context

`US-C1-02` requires that when a caller is not yet a registered user, the flow **states explicitly** that a reporter must exist and offers the correct path, rather than silently creating an anonymous ticket (`NFR-SEC-01`). The backend refusal is `T-C1-11`; this is the surface that makes the refusal actionable instead of a dead end.

Users are owned by `C10`; this ticket consumes the identity read surface and does not define or create users.

## Scope

- Reporter search control inside the agent intake page, querying the identity read endpoint through `incident/data-access`.
- Explicit empty state naming the constraint and offering the documented path when no match is found — never a free-text fallback that would produce an unattributed Incident.
- Debounced search, loading and error states always defined, results keyboard-navigable and screen-reader-announced.
- Out of scope: user creation or invitation, which belongs to `C10`; the rest of the intake flow (`T-C1-12`).

## Acceptance criteria

**Given** an agent searching for a caller who is registered **When** results return **Then** the reporter can be selected by keyboard alone and the selection is reflected in the form.

**Given** a search that matches nobody **When** the empty state renders **Then** it states that a reporter must exist, offers the correct path, and provides no way to submit the Incident without a reporter.

**Given** the identity endpoint failing **When** the agent searches **Then** an explicit error state is shown, the typed form data is retained, and the failure is not swallowed.

**Given** the lookup results **When** they are announced **Then** the count and the selection change are conveyed through the `aria-live` region.
