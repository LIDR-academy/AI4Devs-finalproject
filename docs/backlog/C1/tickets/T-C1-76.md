# [C1] T-C1-76 · Escalated state visible in the agent work list

## Context

`US-C1-25` requires an escalated Incident to show its escalated state **in the agent work list, so it is not lost among ordinary assignments**. This is the one acceptance criterion of that story that lives outside the Incident detail view.

## Scope

- Escalation indicator on the work-list row and on the Incident header, distinguishing functional from hierarchical escalation (`T-C1-77`).
- Escalation action on the agent Incident view, capturing the reason, with the server refusal surfaced.
- Indicator conveyed by text or an accessible name as well as a token-based visual treatment — never by color alone.
- Filter or sort affordance for escalated Incidents in the work list.
- Out of scope: the use cases (`T-C1-75`, `T-C1-77`); the work list itself as a feature, which is the agent Incident list built alongside `T-C1-52`.

## Acceptance criteria

**Given** a work list containing escalated and ordinary Incidents **When** it renders **Then** escalated rows are identifiable without relying on color, and the state is part of the accessible name of the row.

**Given** an Incident escalated functionally and one escalated hierarchically **When** both render **Then** the two kinds are distinguishable from one another.

**Given** an agent escalating from the Incident view **When** they submit without a reason **Then** the server refusal is surfaced with the required-reason message.

**Given** a keyboard-only user **When** they filter the list to escalated Incidents **Then** the filter is operable without a pointer and the resulting count is announced.
