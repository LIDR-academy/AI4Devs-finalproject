# [C10] T-C10-57 · Sliding inactivity expiry through `ClockPort`

## Context

`US-C10-14` requires a session with no request for longer than the configured period to be rejected with `401` and terminated on the next request, requires the window to **slide** while requests continue, and requires elapsed time to be computed through `ClockPort` rather than `new Date()` in domain or application code.

Phase: `unphased` (`FR-IAM-06`, finding **F9**).

## Scope

- Extend the `Session` aggregate of `T-C10-24` with the last-activity timestamp and an `hasExpired(window, now)` decision expressed on the aggregate.
- Touch the last-activity timestamp on every authenticated request, through the guard of `T-C10-28`, using `ClockPort`.
- On an expired session the guard terminates the session record and rejects with `401` carrying the `UNAUTHENTICATED` code; the termination is the same idempotent operation as sign-out.
- Jest unit tests with `FixedClock`: expiry at the boundary, sliding window, already-terminated session.
- Out of scope: configuration (`T-C10-56`), the client warning (`T-C10-58`).

## Acceptance criteria

**Given** an active session and no request for longer than the configured period **When** the next request is made **Then** it is rejected with `401` and the session record is terminated.

**Given** an active session **When** requests continue within the period **Then** the window slides and the session is not terminated.

**Given** a session exactly at the boundary **When** the decision is evaluated with a fixed clock **Then** the outcome is deterministic and covered by an explicit test at, just below and just above the threshold.

**Given** the domain and application libraries **When** they are grepped for `new Date(` **Then** there is no match; elapsed time comes from `ClockPort`.

**Given** an expired session already terminated by a previous request **When** another request arrives **Then** it is rejected with `401` and no second termination is attempted as a state change.
