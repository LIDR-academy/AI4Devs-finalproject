# [C10] T-C10-58 · Web inactivity warning with a stay-signed-in action

## Context

`US-C10-14` requires the web client to warn the agent when the remaining session time crosses a threshold, offering an explicit **stay signed in** action, and requires that losing the session mid-form does not silently discard entered data.

Phase: `unphased` (`FR-IAM-06`, finding **F9**).

## Scope

- Client-side session timer driven by the window and threshold served by `T-C10-56`; the server remains the authority and the client never extends the window on its own.
- Warning overlay from `T-C10-14` with a stay-signed-in action that issues a lightweight authenticated request to slide the window, and a sign-out-now action.
- The warning is announced assertively through the `aria-live` announcer and receives focus, so it is not missed by a screen-reader user.
- Form-data preservation: on session loss, in-progress form state is retained locally and restored after re-authentication, and the user is told this has happened.
- Localized through Transloco; Jest component tests for the warning, the extension and the restoration.
- Out of scope: the server-side expiry (`T-C10-57`).

## Acceptance criteria

**Given** a session about to expire **When** the remaining time crosses the warning threshold **Then** the client shows a localized warning with an explicit stay-signed-in action.

**Given** that warning **When** the user chooses stay signed in **Then** an authenticated request slides the window server-side and the warning closes.

**Given** the user does not respond **When** the window elapses **Then** the next request is rejected with `401` and the shell routes to sign-in.

**Given** a form with entered data **When** the session is lost **Then** the entered data is not silently discarded; it is retained and restored after re-authentication, and the user is told so.

**Given** the warning overlay **When** it opens **Then** it is announced assertively and receives focus, and focus returns to the previous element when it closes.
