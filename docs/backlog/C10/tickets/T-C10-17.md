# [C10] T-C10-17 · Base migration chain and the bootstrap migration

## Context

Foundation work with no user story behind it. Source: `docs/backlog/epic-map.md` → **Foundation ownership (priced once)**, row *PostgreSQL base schema + the TypeORM migration chain*, priced in `C10` citing `CLAUDE.md` §2 and §3; and finding **F14** of `user-stories.md`.

Every later epic adds migrations to this chain, so the first link must be reversible and the convention must be fixed here. `docs/product/DATA-MODEL.md` is the prescriptive schema the first migrations must produce.

This ticket also fixes the one migration-registration convention that `T-C10-69` (packaging migrations for the deployed image, `ci-cd-expert`) builds on: written once, for both the local `.ts` source and the `.js` that ticket compiles it to, it never needs revisiting as later epics add migrations to this same directory.

## Scope

- Migration directory, naming convention (`<timestamp>-<PascalCaseName>.ts`) and registration in the data source.
- The migration glob registered in the data source resolves both `.ts` (local `ts-node` execution) and `.js` (the compiled artifact `T-C10-69` ships inside the deployed API image) from a single pattern — e.g. `migrations/*.{js,ts}` — with no environment-specific branch in code. Record this rule alongside the primary-key default in the convention note below, so `T-C10-69` and every later migration inherit it without rediscovering it (`.claude/skills/ci-cd/references/gotchas.md`, "TypeORM CLI entity globs must match what the image ships").
- Bootstrap migration creating the per-context schema namespaces of `docs/product/DATA-MODEL.md`, starting with the `identity_access` schema, plus the two contrib extensions the modelled schema requires: `CREATE EXTENSION IF NOT EXISTS citext` (case-insensitive `email` columns, e.g. `iam_user.email`, FR-IAM-01 — `DATA-MODEL.md` §6/§20) and `CREATE EXTENSION IF NOT EXISTS pg_trgm` (the `gin_trgm_ops` GIN index for typo-tolerant knowledge-article search, FR-INC-16 — `DATA-MODEL.md` §11/§16). No extension is needed for identifier generation: `uuidv7()` is a PostgreSQL 18 **core** function (`docs/product/DATA-MODEL.md` §3.1.1, **ADR-012**), and the `tsvector`/`to_tsvector` full-text search used elsewhere in the model is likewise core.
- A documented `up`/`down` rule: every migration in this repository is reversible, and `down` is verified before merge — the `down` step also drops the two extensions created above.
- A short convention note in the migrations directory recording the rule, so later epics inherit it. The note also records the primary-key default every migration in this epic must implement: `DEFAULT uuidv7()`, per `docs/product/DATA-MODEL.md` §3.1/§3.1.1 and **ADR-012** (`ARCHITECTURE.md` §10) — the settled safety-net default, since the application always supplies the id (UUID v7) through the repository port. The note also records the floor this default carries: the schema requires **PostgreSQL ≥ 18** (`uuidv7()` does not exist on earlier majors), so the server major pinned in `CLAUDE.md` §2 must never be lowered without a fresh architecture decision. This ticket and `T-C10-21`, `T-C10-24`, `T-C10-36`, `T-C10-44` implement the default exactly as `docs/product/DATA-MODEL.md` §3.1 specifies.
- Out of scope: every table. `user`, `session`, `role`, `permission`, `user_role` and the scope grants are created by their own tickets (`T-C10-21`, `T-C10-24`, `T-C10-36`, `T-C10-44`).

## Acceptance criteria

Mechanical checks — this ticket has no user scenario.

**Given** an empty database **When** `pnpm typeorm migration:run -d apps/api/src/data-source.ts` runs **Then** it applies the bootstrap migration and reports success.

**Given** the applied migration **When** `pnpm typeorm migration:revert -d apps/api/src/data-source.ts` runs **Then** the database returns to its previous state with no residual schema object.

**Given** the run-then-revert-then-run sequence **When** it is executed twice in a row **Then** the outcome is identical both times.

**Given** the migration file **When** it is inspected **Then** it contains explicit SQL or query-builder statements and no reliance on `synchronize`.

**Given** the bootstrap migration **When** it is inspected **Then** it creates exactly two extensions, `citext` and `pg_trgm` (both `CREATE EXTENSION IF NOT EXISTS`), and no others.

**Given** the data source's migration registration **When** it is inspected **Then** it resolves both `.ts` and `.js` migration files from the same glob pattern, with no environment-specific branch in code.

**Given** the convention note **When** it is read **Then** it states the primary-key default as the settled convention — `DEFAULT uuidv7()`, per `docs/product/DATA-MODEL.md` §3.1/§3.1.1 and ADR-012, safety net only — and states the resulting PostgreSQL ≥ 18 floor; it does not present either as an open question.
