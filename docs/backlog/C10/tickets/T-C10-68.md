# [C10] T-C10-68 · Remove the two `@nx/js` targets `apps/api/project.json` can never run

## Context

Defect in already-shipped code. `apps/api/project.json` — generated by `T-C10-04` (done, committed) via `pnpm nx g @nx/nest:app api` — carries two targets that this workspace can never execute:

```
pnpm nx run api:prune-lockfile
 NX   d:\...\apps\api\package.json does not exist.
 EXIT=1
```

`prune-lockfile` and `copy-workspace-modules` are `@nx/js` executors that require the project to own its own `package.json`. This workspace deliberately declares every dependency in the single **root** `package.json` (`CLAUDE.md` §2), and `eslint.config.mjs`'s `banTransitiveDependencies: true` engages precisely when a project gains its own manifest — so a project-level `package.json` for `apps/api` is not a fix, it is a boundary violation. These two targets, and the `prune` target that only exists to sequence them, are dead weight: nobody ran them until this defect was found, and nothing in this workspace's build, serve, test or Docker path depends on `api:prune`.

**Not a blocker.** `docker/backend/Dockerfile` already works around their absence: it installs from the `package.json` that `generatePackageJson: true` (`apps/api/webpack.config.js`) writes into `dist/apps/api`, verified end to end (images build and run). That Dockerfile's own comment (lines ~19–24) already names this exact defect and defers the fix: *"Worth fixing so those executors work as intended — reported, not fixed here."* This ticket is that fix. `.claude/skills/ci-cd/references/infrastructure.md` ("Per-project build targets") also currently describes `prune-lockfile` / `copy-workspace-modules` as functioning tooling — that description goes stale the moment this ticket lands.

## Scope

- Remove the `prune-lockfile`, `copy-workspace-modules` and `prune` target blocks from `apps/api/project.json`. Leave `build`, `serve` and `test` untouched — they are unaffected by this defect.
- Update the stale explanatory comment in `docker/backend/Dockerfile` (lines ~19–24) that currently narrates these targets as broken-but-intended — once they are gone, the comment describing a future fix is itself the stale artifact.
- Update the "Per-project build targets" section of `.claude/skills/ci-cd/references/infrastructure.md`, which still lists both targets as present.
- Out of scope: any change to how `apps/api` is packaged for the Docker image — the `generatePackageJson: true` / `dist/apps/api/package.json` path stays exactly as it is, already verified working.
- Out of scope: `apps/web/project.json` and any other project — this defect is specific to the `@nx/nest:app` generator output for `api`; do not remove targets elsewhere without the same reproduction.
