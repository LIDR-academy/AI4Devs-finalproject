# [C10] T-C10-31 · Sign-in screen

## Context

`US-C10-01` is only reachable by a Player / Competitor through a screen. This is the first authenticated surface of the product and the first consumer of the in-house design system (`T-C10-12` to `T-C10-15`) — which is exactly why the epic map prices the design system into `C10`.

## Scope

- Routed standalone component in `libs/identity-access/feature`, `OnPush`, composed from the shared design-system form primitives; **no third-party component library**.
- Reactive Form with identifier and password controls, client-side required validation, and a submit button that shows a pending state and cannot be double-submitted.
- Failure rendering: one generic message for a failed sign-in that never distinguishes an unknown identifier from a wrong password, mirroring the API; a distinct message for a provider outage.
- Explicit loading and error states; the error is announced through the `aria-live` announcer from `T-C10-14`.
- All user-facing strings resolved through Transloco keys — the translation catalogue itself belongs to the `NFR` epic i18n slice; this ticket contributes keys, not scaffolding.
- Out of scope: the router guard and interceptor (`T-C10-30`), sign-out (`T-C10-34`).

## Acceptance criteria

**Given** the sign-in route **When** it renders **Then** the form is fully operable by keyboard, each control has an associated label, and focus lands on the first control.

**Given** valid credentials **When** the form is submitted **Then** the button enters a pending state, a second submission is impossible while it is pending, and on success the shell navigates to the preserved return URL.

**Given** an incorrect password and an unknown identifier **When** each is submitted **Then** the screen shows the identical generic message.

**Given** a failed submission **When** it completes **Then** the message is announced through the `aria-live` region and focus is moved so a screen-reader user reaches it.

**Given** the component source **When** it is inspected **Then** there is no hardcoded user-facing string and no third-party component-library import.
