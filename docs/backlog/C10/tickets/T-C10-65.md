# [C10] T-C10-65 · Just-in-time provisioning with the default least-privilege role

## Context

`US-C10-10` requires an SCMS identity that has never signed in before to be provisioned as a local user with the **default least-privilege role and no elevated permission**, and requires that provisioning to be recorded as a domain event.

Phase: `unphased` (`FR-IAM-04`, finding **F9**).

## Scope

- Provisioning branch in the authentication flow: when the resolved external identity has no local user, create one from the mapped profile with exactly the default role.
- The default role identifier is configuration-driven, validated at boot to be one of the eight roles of `T-C10-35`, and defaults to Requester.
- `UserProvisioned` domain event extending `DomainEvent`, published post-commit through the dispatcher of `T-C10-55`; `C18` records it (finding **F5**).
- Provisioning is atomic with the first successful authentication: a failure leaves no partial user.
- Jest unit tests: first sign-in provisions, second sign-in does not, provisioning failure leaves nothing behind.
- Out of scope: profile refresh (`T-C10-66`), the audit entry itself (`C18`).

## Acceptance criteria

**Given** an SCMS identity that has never signed in **When** it authenticates successfully **Then** a local user is provisioned carrying exactly the configured default least-privilege role and no elevated permission.

**Given** that provisioning **When** the transaction commits **Then** a `UserProvisioned` domain event is published post-commit.

**Given** the same identity **When** it signs in a second time **Then** no second user is provisioned and no second provisioning event is emitted.

**Given** a failure during provisioning **When** the transaction rolls back **Then** no partial user exists and no event is emitted.

**Given** a configured default role that is not one of the eight seeded roles **When** the application boots **Then** it fails fast.
