# [C10] T-C10-52 · Role-revocation API adapter and contract

## Context

The inbound path for `T-C10-51`, split from it and from the client action because the three sit at different layers and two different agents own them.

## Scope

- `RevokeRoleRequest` type in `libs/shared/contracts` plus the decorated DTO in `apps/api`.
- Thin controller delegating to `RevokeRoleFromUser`; `403` on denial, `409` with a distinct error code on the last-administrator refusal so the client can explain it, success on the idempotent repeat.
- API-E2E scenarios: revoke and immediately retry a permitted operation with the same token, and the last-administrator refusal.
- Out of scope: the use case, the screen.

## Acceptance criteria

**Given** an administrator **When** a valid revocation is submitted **Then** it succeeds and the user-profile read no longer lists the role.

**Given** a user whose role was just revoked **When** they retry the permitted operation with their existing token **Then** the response is `403` without any sign-out or token refresh.

**Given** the last-administrator refusal **When** it is returned **Then** the response carries a distinct machine-readable error code, not the generic `FORBIDDEN`.

**Given** a body that fails validation **When** it is submitted **Then** it is rejected with `400` before the use case is reached.
