# [C10] T-C10-33 · Sign-out HTTP adapter and contract

## Context

The inbound path for `T-C10-32`. Split from the client action (`T-C10-34`) because the two sit on different platforms and are implemented by different agents.

## Scope

- Sign-out response type in `libs/shared/contracts`; the request carries no body, only the authenticated session.
- Thin controller in `apps/api` delegating to `SignOutSession`; the route is **not** exempt from the global guard, so an anonymous sign-out is rejected as unauthenticated.
- Response `204` on success, including for a repeat sign-out.
- An API-E2E scenario in `apps/api-e2e` proving replay rejection is added by the test plan, not by this ticket.
- Out of scope: the use case, the client.

## Acceptance criteria

**Given** an authenticated caller **When** the sign-out route is called **Then** it responds `204` and the session record is terminated.

**Given** an anonymous caller **When** the sign-out route is called **Then** it responds `401`, because the route carries no `@Public()` marker.

**Given** a token belonging to a signed-out session **When** it is replayed on any protected route **Then** the response is `401`.

**Given** a repeated sign-out with the same token **When** it is called **Then** the response is `401`, because the session is already terminated and the guard rejects before the controller.
