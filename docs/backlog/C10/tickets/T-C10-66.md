# [C10] T-C10-66 · Profile refresh preserving locally assigned roles

## Context

`US-C10-10` requires that when an SCMS identity signs in again with changed upstream attributes, the mapped profile attributes are refreshed while **locally assigned roles are preserved**: SSO supplies identity and profile, never Sport ITSM authorization.

This is the rule that keeps `FR-IAM-05` meaningful once SSO is enabled — otherwise an upstream change could silently undo an administrator decision.

Phase: `unphased` (`FR-IAM-04`, finding **F9**).

## Scope

- On every successful SSO authentication of an existing user, update only the mapped profile attributes: display name, contact attributes, account status where the provider is authoritative for it.
- Role assignments are never read from, written from, or reconciled against the provider response.
- A profile change is idempotent: an unchanged profile writes nothing and emits nothing.
- Jest unit tests: changed attribute refreshed, roles unchanged, unchanged profile writes nothing, provider-supplied role-like claim ignored.
- Out of scope: provisioning (`T-C10-65`), the adapter mapping (`T-C10-64`).

## Acceptance criteria

**Given** an SCMS identity whose profile attributes have changed upstream **When** it signs in again **Then** the mapped profile attributes are refreshed on the local user.

**Given** the same sign-in **When** the local role assignments are inspected afterwards **Then** they are unchanged.

**Given** a provider response carrying a role-like or group-like claim **When** it is processed **Then** it is ignored for authorization purposes and never becomes a role assignment.

**Given** a sign-in where nothing upstream has changed **When** it completes **Then** no write occurs and no change event is emitted.
