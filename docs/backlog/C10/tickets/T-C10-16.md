# [C10] T-C10-16 · PostgreSQL 18 provisioning and the TypeORM data source

## Context

Foundation work with no user story behind it. Source: `docs/backlog/epic-map.md` → **Foundation ownership (priced once)**, row *PostgreSQL base schema + the TypeORM migration chain (`synchronize: false`, migrations only)*, priced in `C10` citing `CLAUDE.md` §2 and §3; and finding **F14** of `user-stories.md`.

Split from `T-C10-17` so that the connection and the migration chain can be reviewed separately: this ticket makes the database reachable, the next one makes the schema reproducible. The `docker-compose` part is workspace tooling on the shared platform; the data source itself is backend infrastructure, which is why the ticket carries `agent: backend-engineer`.

## Scope

- `docker-compose.yml` for a local PostgreSQL 18 instance, image pinned to the explicit tag `postgres:18.6` (the latest 18.x patch verified against the registry on 2026-09-07) — never `postgres:18`, `postgres:latest`, or any other floating tag. A later patch bump is a routine dependency update; moving off major `18` is not and needs the same approval any other pinned-major bump does (`CLAUDE.md` §2). The major is now also a hard functional floor, not only a policy pin: `T-C10-17`'s bootstrap migration relies on the core `uuidv7()` function, which does not exist before PostgreSQL 18 (ADR-012, `ARCHITECTURE.md` §10) — lowering the image major breaks the first migration, not just the convention. Named volume and credentials read from the environment.
- TypeORM 1.1 data source at `apps/api/src/data-source.ts` on the `pg` driver, connection values resolved through `ConfigService` only.
- `synchronize: false`, `migrationsRun: false`; migration auto-run gated to development and never unconditional (`CLAUDE.md` §3).
- The four `pnpm typeorm` scripts of `CLAUDE.md` §3: `migration:generate`, `migration:run`, `migration:revert`, plus `migration:show`.
- Out of scope: any migration file (`T-C10-17`), any entity (`T-C10-21` onward).

## Acceptance criteria

Mechanical checks — this ticket has no user scenario.

**Given** `docker compose up -d` **When** it completes **Then** a PostgreSQL 18 server accepts connections on the configured port.

**Given** the `docker-compose.yml` service definition **When** the `image` line is inspected **Then** it reads `postgres:18.6` — an explicit `major.minor.patch` tag, never `latest` or a bare major.

**Given** the data source **When** `pnpm typeorm migration:show -d apps/api/src/data-source.ts` runs **Then** it connects and reports an empty migration list without error.

**Given** the data source configuration **When** it is inspected **Then** `synchronize` is `false` and no code path sets it to `true` in any environment.

**Given** the API boot sequence in a staging or production configuration **When** it starts **Then** it runs no migration automatically.

**Given** the data-source file **When** it is grepped for `process.env` **Then** the only occurrences are inside the configuration module it delegates to.
