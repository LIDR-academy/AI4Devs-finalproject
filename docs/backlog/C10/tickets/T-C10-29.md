# [C10] T-C10-29 · API-E2E proof that the API exposes no anonymous surface

## Context

`US-C10-02` is a **negative** requirement about every route, present and future. A unit test on the guard cannot prove it; only an enumeration of the live route table can. This ticket produces that proof and turns it into a standing regression check for every later epic.

The work is acceptance-test code in `apps/api-e2e`, a `type:e2e` project on the **backend platform**; it belongs to neither dev agent, hence `agent: —`.

## Scope

- A Cucumber feature in `apps/api-e2e` that enumerates the running application route table and calls **every** route with no `Authorization` header.
- Assertion: every route answers `401`, except exactly the declared exemptions — sign-in and the liveness/readiness probes.
- A companion scenario for an expired token and for a tampered token.
- The exemption list is asserted as an exact set, so adding a new `@Public()` route fails this test until the list is updated deliberately.
- Out of scope: the guard implementation (`T-C10-28`), authorization scenarios (block C), any browser-level test.

## Acceptance criteria

**Given** the running API **When** every route in the route table is called without a token **Then** each responds `401`, apart from the declared exemption set.

**Given** the declared exemption set **When** it is compared with the routes that answered without `401` **Then** the two sets are identical, with no extra and no missing entry.

**Given** a new route added later without a `@Public()` marker **When** this feature runs **Then** it passes, because the route answers `401`.

**Given** a new route added later **with** a `@Public()` marker **When** this feature runs **Then** it fails until the exemption set in the feature is updated, making every new anonymous route a deliberate, reviewed decision.
