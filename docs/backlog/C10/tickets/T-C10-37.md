# [C10] T-C10-37 · Translatable role labels with stable identifiers

## Context

`US-C10-04` requires each role to carry a stable identifier and a **translatable** label, and states that none may carry a hardcoded user-facing string. `CLAUDE.md` §3 forbids hardcoded user-facing strings on the backend and routes them through `nestjs-i18n`.

**Dependency:** the `nestjs-i18n` bootstrap itself is not priced in `C10` — the epic map assigns the i18n scaffolding slice to the `NFR` epic. This ticket contributes the role translation resources and is blocked on that scaffolding being available; it does not stand it up.

## Scope

- Translation resource entries for the eight role labels and their descriptions, keyed by the stable identifiers of `T-C10-35`.
- Role responses resolve labels through `nestjs-i18n` driven by `Accept-Language`, with a documented fallback locale.
- A check that no role label is emitted from a literal in code.
- Out of scope: the i18n module bootstrap and the locale catalogue structure (`NFR` epic); the frontend Transloco keys, which the role-administration screen contributes (`T-C10-50`).

## Acceptance criteria

**Given** a request carrying `Accept-Language` for a supported locale **When** the role catalog is returned **Then** each label is rendered in that locale.

**Given** a request for an unsupported locale **When** the role catalog is returned **Then** each label falls back to the documented default locale rather than to a missing-key placeholder.

**Given** the backend source **When** it is grepped for the literal English role names **Then** the only occurrences are inside the translation resource files.

**Given** a role identifier **When** it is compared across locales **Then** it is identical; only the label changes.
