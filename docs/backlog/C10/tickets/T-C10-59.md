# [C10] T-C10-59 · Privileged-operation declaration and the step-up validity window

## Context

`US-C10-15` requires privileged operations to be satisfied **by declaration** rather than by remembering to add a check, so a newly added privileged operation inherits the rule through the same marker.

**Blocked by finding F16.** Neither the PRD nor the architecture defines which operations are privileged. `FR-IAM-06` requires re-authentication for *privileged administrative actions* and `FR-IAM-07` requires recording denials *when it concerns privileged operations*, but the set is never enumerated. `US-C10-15` proposes one — role assignment and revocation, plus Admin Console configuration of catalog, taxonomy, SLA policies, workflows and notification templates — explicitly as an **assumption of this backlog**. **The Product Owner must confirm or replace that set.** Until then the marker and the window can be built, but the membership of the set cannot be fixed and the requirement is not testable end to end.

Deliverable split: the mechanism is unblocked and is built here against the proposed set as a provisional list held in one place; the list contents stay open until F16 is resolved.

Phase: `unphased` (`FR-IAM-06`, finding **F9**).

## Scope

- A `@Privileged()` declaration marker readable by the application layer, and a single registry that enumerates the declared privileged operations.
- The provisional membership of that registry seeded from the `US-C10-15` proposal, marked in code as pending Product Owner confirmation with a reference to finding **F16**.
- Extend the `Session` aggregate of `T-C10-24` with a step-up verification timestamp and a `isStepUpValid(window, now)` decision using `ClockPort`.
- Step-up validity window added to the validated configuration schema.
- Jest unit tests for the window decision at, below and above the boundary.
- Out of scope: the re-authentication use case (`T-C10-60`), the prompt (`T-C10-61`), and any decision about which operations belong in the set.

## Acceptance criteria

**Given** an operation carrying the declaration marker **When** the registry is enumerated **Then** the operation appears in it without any additional registration step.

**Given** a new privileged operation added later **When** it carries the marker **Then** it is covered by the rule with no change to the enforcement code.

**Given** a session with a step-up verification timestamp inside the configured window **When** validity is evaluated with a fixed clock **Then** it is valid; outside the window it is not, and the boundary is covered explicitly.

**Given** the provisional registry **When** it is read **Then** it names finding **F16** and states that its membership is an assumption pending Product Owner confirmation.
