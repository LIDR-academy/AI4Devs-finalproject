# [C10] T-C10-01 · Bootstrap the Nx workspace with pnpm and strict TypeScript

## Context

Foundation work with no user story behind it. Source: `docs/backlog/epic-map.md` → **"Foundation ownership (priced once)"**, row *"Nx workspace bootstrap, pnpm, ESLint 9 flat config with `@nx/enforce-module-boundaries`, Prettier, the three-axis tag scheme"*, priced in `C10`; and finding **F14** of `docs/backlog/C10/user-stories.md`, which records that the Business Analyst deliberately wrote no story for scaffolding because it has no persona and no user-observable behavior.

The repository currently contains documentation only — no `package.json`, no `apps/`, no `libs/`. Nothing in this epic, and nothing in the other 18 epics, can compile until this ticket lands. `agent: —` because workspace tooling is not owned by `backend-engineer` or `frontend-engineer`; the work sits on the **shared platform** at the **workspace tooling** layer.

## Scope

- Create the Nx 21.6 workspace at the repository root, integrated monorepo preset, `pnpm` as the package manager (`pnpm-lock.yaml`, `pnpm-workspace.yaml`).
- Pin the versions declared in `CLAUDE.md` §2: Node.js 22 LTS (`.nvmrc` = `22`, `engines.node` = `>=22.0.0 <23.0.0`), TypeScript 5.9, Nx 21.6.
- Root `tsconfig.base.json` with `strict: true`, `noImplicitOverride`, `noUnusedLocals`, `noFallthroughCasesInSwitch`, and the path-alias block that lib barrels will register into.
- `.gitignore` covering `node_modules`, `dist`, `.nx/cache`, `tmp`, Cypress artifacts.
- Nx cache and `namedInputs` / `targetDefaults` for `build`, `test`, `lint`, `e2e`.
- Out of scope: any application, any library, ESLint and Prettier configuration (`T-C10-02`), the boundary matrix (`T-C10-03`).

## Acceptance criteria

Mechanical checks — this ticket has no user scenario.

**Given** a clean checkout **When** `pnpm install` runs **Then** it completes with no error and produces exactly one lockfile, `pnpm-lock.yaml`; no `package-lock.json` and no `yarn.lock` exists anywhere in the tree.

**Given** the installed workspace **When** `pnpm nx report` runs **Then** it prints Nx 21.6, TypeScript 5.9 and Node 22.x.

**Given** `tsconfig.base.json` **When** it is inspected **Then** `compilerOptions.strict` is `true`.

**Given** the workspace **When** `pnpm nx graph --file=tmp/graph.json` runs **Then** it succeeds and reports zero projects, confirming the graph is operational before any project exists.

> **Status note.** The zero-projects criterion above was satisfied when this ticket was accepted and is kept as its evidence. Re-running it today reports the projects that later tickets created, so the re-runnable form of the check is "exactly the projects the tickets created, and nothing else" — `pnpm nx show projects`.
