# [C10] T-C10-03 · Encode the type constraint matrix and the scope/platform rules

## Context

Foundation work with no user story behind it. Source: `docs/backlog/epic-map.md` → **"Foundation ownership (priced once)"** (`@nx/enforce-module-boundaries`, three-axis tag scheme, priced in `C10`, citing `ARCHITECTURE.md` §5.2 and §5.5); and finding **F14** of `user-stories.md`.

This is the single most load-bearing rule in the repository (`ARCHITECTURE.md` §5.4: *"This is the single most important structural rule in this document"*). Every later epic is sized assuming an illegal import fails the build rather than passing review. Workspace tooling on the **shared platform**, hence `agent: —`.

## Scope

- Configure `@nx/enforce-module-boundaries` with `depConstraints` encoding **all three** rule families of `ARCHITECTURE.md` §5.3:
  - the ten-row **type constraint matrix**, including `type:app` (may depend on every type within its platform plus shared) and `type:e2e` (may depend only on `type:contracts` and `type:util`), and the ban on any library depending on `type:app`;
  - the **scope rule** — `scope:<context>` may depend only on the same scope and on `scope:shared`; `scope:shared` may depend only on `scope:shared`;
  - the **platform rule** — `platform:frontend` and `platform:backend` may never depend on each other; both may depend on `platform:shared`.
- Enforce that every project carries **exactly three** tags, one per axis (`ARCHITECTURE.md` §5.2, "no exceptions").
- Ban deep imports past a library barrel (`enforceBuildableLibDependency` / `banTransitiveDependencies` as applicable, plus `allow: []`).
- Out of scope: creating any project.

## Acceptance criteria

Mechanical checks — this ticket has no user scenario.

**Given** the boundary configuration **When** `pnpm nx run-many -t lint` runs **Then** it passes on the empty workspace.

**Given** a temporary probe import from a `type:domain` file into a `type:infrastructure` library **When** `pnpm nx lint <project>` runs **Then** the build **fails** with an `@nx/enforce-module-boundaries` violation naming both tags; the probe is reverted before the ticket is closed.

**Given** a probe import from a `platform:frontend` project into a `platform:backend` project **When** lint runs **Then** it fails.

**Given** a probe import from `scope:identity-access` into another `scope:<context>` **When** lint runs **Then** it fails.

**Given** a project declared with two tags instead of three **When** lint runs **Then** it fails.

**Given** `pnpm nx graph` **When** it is generated **Then** it contains no edge that the matrix forbids.
