# [C10] T-C10-24 · `Session` aggregate, `SessionRepositoryPort`, entity and migration

## Context

`US-C10-03` requires the guard to validate a **session record**, not only a token signature, so that a signed-out token cannot be replayed before its natural expiry. That record must therefore exist before sign-in issues the first token, which is why this ticket is scheduled ahead of `T-C10-25` even though its story comes later.

Phase note: `US-C10-03` traces `FR-IAM-01` (phase 0) and `FR-IAM-06` (unphased, finding **F9**). It is scheduled with its phase-0 half; the inactivity behavior that `FR-IAM-06` adds on top lands in block F (`T-C10-57`).

## Scope

- `Session` aggregate in `libs/identity-access/domain`: session id, user id, issued-at, last-activity, terminated-at, and the derived active/terminated state.
- Termination is a domain operation that is idempotent and irreversible; a terminated session is never revived (`US-C10-03`).
- `SessionRepositoryPort` in the domain: create, find active by id, terminate.
- TypeORM `SessionEntity`, mapper and `TypeOrmSessionRepository` in infrastructure; migration creating `identity_access.session` with an index on the user id and on the terminated flag. Primary-key default per the convention `T-C10-17` fixes (`DEFAULT uuidv7()`, `DATA-MODEL.md` §3.1/§3.1.1, ADR-012).
- Jest unit tests for the aggregate; integration test for the repository.
- Out of scope: the sliding inactivity window (`T-C10-57`), the step-up mark (`T-C10-59`) — both extend this aggregate later.

## Acceptance criteria

**Given** an active session **When** it is terminated twice **Then** the second termination changes nothing and raises no error.

**Given** a terminated session **When** any code attempts to reactivate it **Then** the aggregate exposes no operation to do so.

**Given** the migration **When** it runs and is reverted **Then** `identity_access.session` is created and removed cleanly.

**Given** the domain library **When** it is grepped for `new Date(` **Then** there is no match; the aggregate takes its timestamps from `ClockPort`.

**Given** the repository **When** it looks up a terminated session **Then** it does not return it as active.
