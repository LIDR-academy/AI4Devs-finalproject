# [C10] T-C10-38 · Deny-by-default authorization predicates

## Context

`US-C10-05` requires authorization to be decided **in domain terms** — for example *actor may assign roles* — evaluated against the actor passed into the use case, denying by default when no permission grants it. `ARCHITECTURE.md` §9 places authorization in the use cases, expressed in domain vocabulary, not as controller decorators alone.

This is the predicate layer. Wiring it into the use cases is `T-C10-39`.

## Scope

- `Actor` domain type in `libs/identity-access/domain`: identity, resolved role identifiers, resolved permission set, and the competition/league scope grants added by `T-C10-43`.
- `AuthorizationPolicy` exposing named predicates in domain vocabulary, one per privileged operation this epic needs, each returning an allow/deny decision carrying a **reason** on denial — the reason is what `US-C10-16` records.
- Deny by default: an operation with no granting permission is denied; there is no wildcard and no implicit allow.
- Typed `AuthorizationError` carrying the attempted operation and the denial reason.
- Jest unit tests constructing actors and permissions directly, with no HTTP, no database and no framework import.
- Out of scope: record-visibility predicates (block D), the actor assembly (`T-C10-39`), the HTTP mapping (`T-C10-40`).

## Acceptance criteria

**Given** an actor whose permission set grants the required permission **When** the predicate is evaluated **Then** it allows.

**Given** an actor whose roles do not include the required permission **When** the predicate is evaluated **Then** it denies and the decision carries a reason.

**Given** an operation for which no predicate has been declared **When** authorization is evaluated **Then** the outcome is deny, not allow.

**Given** the predicate suite **When** `pnpm nx test identity-access-domain` runs **Then** it passes with no database, no HTTP layer and no framework import in `type:domain`.

**Given** the domain library **When** it is inspected **Then** no predicate reads a request object, a header or a decorator.
