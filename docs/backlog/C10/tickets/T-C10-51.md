# [C10] T-C10-51 · `RevokeRoleFromUser` use case with the last-administrator safeguard

## Context

`US-C10-12` requires a revoked role to stop granting access at once and requires the platform to refuse an administrator who attempts to revoke their **own last System Administrator role**, so Sport ITSM cannot be left with no administrator.

The immediate-effect half is already structural: `T-C10-39` resolves permissions server-side per request, so a revocation lands on the next request without waiting for token expiry. This ticket owns the revocation itself and the safeguard.

## Scope

- `RevokeRoleFromUser` use case in `libs/identity-access/application`, guarded by the same predicate as assignment.
- Idempotent: revoking a role the user does not hold succeeds and changes nothing.
- Safeguard: refuse with a typed error when the revocation would remove the last System Administrator assignment in the system, evaluated inside the transaction so a concurrent revocation cannot slip past it.
- Jest unit tests: allowed revocation, denied revocation, revoke a role not held, self-revocation of the last administrator role, revocation of an administrator role while another administrator exists.
- Out of scope: the API adapter (`T-C10-52`), the client (`T-C10-53`), the events (`T-C10-54`).

## Acceptance criteria

**Given** a user holding a role and an administrator actor **When** the revocation executes **Then** the assignment is removed and the operation reports success.

**Given** the same user with an existing token **When** they make the next request **Then** the assembled actor no longer carries the revoked permissions, because permissions are resolved server-side per request.

**Given** that user **When** they retry an operation the revoked role permitted **Then** it is denied with `403` through the filter of `T-C10-40`.

**Given** an administrator attempting to revoke their own last System Administrator role **When** the use case executes **Then** it is refused with a typed error and the assignment remains.

**Given** two concurrent revocations that would each leave zero administrators **When** they execute **Then** at most one succeeds and the safeguard holds.
