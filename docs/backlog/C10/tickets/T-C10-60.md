# [C10] T-C10-60 · Step-up re-authentication use case and outcome

## Context

`US-C10-15` requires a privileged operation invoked without a valid step-up mark to be refused with a **distinct, machine-readable** re-authentication-required outcome — not a generic `403` — with nothing persisted, and requires the original operation to succeed on retry once credentials have been re-entered.

**Blocked by finding F16**, for the same reason as `T-C10-59`: the enforcement is buildable, but which operations it guards is an unconfirmed assumption of this backlog and must be decided by the Product Owner. Build the mechanism; do not close the ticket as satisfying `FR-IAM-06` until the set is agreed.

Phase: `unphased` (finding **F9**).

## Scope

- Step-up enforcement in the application layer: before executing a declared privileged operation, evaluate `isStepUpValid`; on failure raise a typed `ReauthenticationRequired` error and persist nothing.
- `ReauthenticateSession` use case verifying the presented credential through `IdentityProviderPort` and, on success, marking the session step-up-verified with a `ClockPort` timestamp.
- A failed step-up leaves existing privileges untouched, grants no mark, and is logged.
- Exception-filter mapping of `ReauthenticationRequired` to a distinct status and error code, separate from `FORBIDDEN`.
- Jest unit tests plus API-E2E scenarios for refuse, re-authenticate, retry.
- Out of scope: the prompt UI (`T-C10-61`); the membership of the privileged set (finding **F16**).

## Acceptance criteria

**Given** a declared privileged operation and a session not re-authenticated within the window **When** it is invoked **Then** it is refused with the distinct machine-readable re-authentication-required outcome and nothing is persisted.

**Given** that refusal **When** the administrator re-enters valid credentials **Then** the session is marked step-up-verified for the configured window and the retried operation succeeds.

**Given** invalid credentials at the step-up prompt **When** they are submitted **Then** the session keeps its existing privileges, gains no step-up mark, and the attempt is logged.

**Given** the refusal outcome and an authorization denial **When** both are returned **Then** they carry different error codes, so a client can tell them apart without parsing a message.

**Given** a session already step-up-verified inside the window **When** a second privileged operation is invoked **Then** it proceeds without a further prompt.
