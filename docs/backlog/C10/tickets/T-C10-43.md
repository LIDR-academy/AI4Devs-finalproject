# [C10] T-C10-43 · Competition and league scope grants in the domain

## Context

`US-C10-07` requires a competition grant to be a **persisted, explicitly scoped grant** in the `identity-access` domain — never inferred from a name match, a text field or a role label. `US-C10-08` needs the same for a league. Both scopes are modelled here before either predicate consumes them.

## Scope

- `ScopeGrant` in `libs/identity-access/domain`: subject user, grant kind (competition or league), and the target identifier.
- `ScopeGrantRepositoryPort`: list grants for a user, resolve the competition set covered by a league grant.
- The `Actor` of `T-C10-38` extended to carry its resolved grants.
- Competition and league identifiers are opaque identifiers to this context — `identity-access` never imports a competition model.
- Jest unit tests for grant construction, equality and the actor extension.
- Out of scope: persistence (`T-C10-44`), the predicates (`T-C10-45`, `T-C10-46`).

## Acceptance criteria

**Given** a `ScopeGrant` **When** it is constructed **Then** it carries an explicit kind and an explicit target identifier, and construction with a free-text target is rejected.

**Given** the domain library **When** it is inspected **Then** it holds no competition or league model, only opaque identifiers.

**Given** an `Actor` **When** it is assembled **Then** its grants are an explicit collection, empty by default rather than absent.

**Given** the port **When** it is inspected **Then** league-to-competition resolution is declared as an operation, so it can be answered at evaluation time rather than frozen into the grant.
