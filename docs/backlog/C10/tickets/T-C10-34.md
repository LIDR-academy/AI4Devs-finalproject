# [C10] T-C10-34 · Web sign-out action

## Context

`US-C10-03` requires that on sign-out the client discards the token and the shell navigates to the sign-in route. The client half of `T-C10-33`.

## Scope

- Sign-out call in `libs/identity-access/data-access` invoking the API route and clearing the signal-based auth state from `T-C10-30`.
- Sign-out control in the shell, reachable by keyboard and labelled for assistive technology.
- The local token is discarded even if the API call fails, so a network error cannot leave a live token in the client.
- Navigation to the sign-in route on completion, with the browser history entry replaced so the back button does not return to an authenticated view.
- Out of scope: the API route, session termination semantics.

## Acceptance criteria

**Given** an authenticated agent **When** they choose sign out **Then** the API is called, the client token is discarded and the shell navigates to sign-in.

**Given** the API call fails **When** sign-out is attempted **Then** the client token is still discarded and the shell still navigates to sign-in.

**Given** the user has signed out **When** they press the browser back button **Then** they are not returned to an authenticated view; the router guard sends them to sign-in.

**Given** the sign-out control **When** it is reached by keyboard **Then** it is focusable, has an accessible name and activates with both `Enter` and `Space`.
