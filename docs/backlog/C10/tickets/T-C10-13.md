# [C10] T-C10-13 · `libs/shared/ui` — form primitives

## Context

Foundation work with no user story behind it. Source: `docs/backlog/epic-map.md` → **Foundation ownership (priced once)**, the `libs/shared/ui` row (ADR-010); and finding **F14** of `user-stories.md`.

The sign-in screen (`T-C10-31`), the role-administration screen (`T-C10-50`) and the step-up prompt (`T-C10-61`) are all forms. With no third-party component library, their controls must be built once here.

## Scope

- Hand-built, `OnPush`, standalone components with plain HTML templates and component-scoped SCSS on the tokens from `T-C10-12`: button (with pending/disabled state), form field wrapper (label, hint, error, required marker), text input, password input, select, checkbox.
- Native semantics first, then ARIA: label association, `aria-describedby` for hint and error, `aria-invalid`, `aria-busy` on a pending button.
- Reactive Forms compatible via `ControlValueAccessor`; state in, events out — no injected service, no store, no `HttpClient`.
- Jest component tests for a11y wiring and value propagation.
- Out of scope: overlays and the a11y primitives (`T-C10-14`); table and state primitives (`T-C10-15`); any validation message text, which is i18n and belongs to the `NFR` epic slice.

## Acceptance criteria

Mechanical checks — this ticket has no user scenario.

**Given** every component in the library **When** its decorator is inspected **Then** `changeDetection` is `OnPush` and the component is standalone.

**Given** the library source **When** it is grepped for `inject(`, `HttpClient` and any store import **Then** there is no match.

**Given** a form field rendered with a hint and an error **When** the DOM is inspected **Then** the control carries `aria-describedby` referencing both, and `aria-invalid` is `true` only while the error is shown.

**Given** the library **When** `pnpm nx test shared-ui` and `pnpm nx lint shared-ui` run **Then** both pass.
