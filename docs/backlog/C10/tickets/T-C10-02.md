# [C10] T-C10-02 · ESLint 9 flat config, Prettier 3 and the three-axis tag scheme

## Context

Foundation work with no user story behind it. Source: `docs/backlog/epic-map.md` → **"Foundation ownership (priced once)"**, same row as `T-C10-01`; and finding **F14** of `user-stories.md`. Workspace tooling on the **shared platform**, hence `agent: —`.

This ticket installs the lint and format toolchain and declares the tag vocabulary of `ARCHITECTURE.md` §5.2. The constraint matrix that consumes those tags is `T-C10-03`, split out because the matrix is a deliverable in its own right with its own verification.

## Scope

- ESLint 9 **flat config** at `eslint.config.mjs` with `@nx/eslint-plugin`, `typescript-eslint` and — for Angular projects — `angular-eslint`.
- Prettier 3 with `singleQuote: true` and `semi: true` (`CLAUDE.md` §3); `.prettierignore`; no stylistic ESLint rule that conflicts with Prettier.
- Nx `lint` and `format:check` targets wired through `targetDefaults`.
- Declare the three-axis tag vocabulary as the allowed value set: `platform:` ∈ {`backend`, `frontend`, `shared`}, `scope:` ∈ {`shared`, plus one per context of `ARCHITECTURE.md` §4.1}, `type:` ∈ {`domain`, `application`, `infrastructure`, `feature`, `ui`, `data-access`, `contracts`, `util`, `app`, `e2e`}.
- Out of scope: the `depConstraints` matrix itself (`T-C10-03`).

## Acceptance criteria

Mechanical checks — this ticket has no user scenario.

**Given** the workspace **When** `pnpm nx run-many -t lint` runs **Then** it completes with exit code 0.

**Given** any staged file **When** `pnpm prettier --check .` runs **Then** it reports no formatting difference, with single quotes and semicolons applied.

**Given** `eslint.config.mjs` **When** it is inspected **Then** it is flat config (an exported array), contains no `.eslintrc` fallback, and enumerates the three tag axes and their allowed values in one place.

**Given** a project created later with fewer than three tags **When** `T-C10-03`'s rule is added on top **Then** the tag vocabulary declared here is the set that rule validates against.
