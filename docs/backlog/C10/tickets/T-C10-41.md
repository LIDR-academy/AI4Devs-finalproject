# [C10] T-C10-41 · Requester-scoped visibility predicate and the `ScopeRestriction` result

## Context

`US-C10-06` requires a requester to see and act on only the records they raised, and requires the predicate to yield a **scope restriction** that the consuming context can push into its repository query, so denied records are never fetched and then filtered in memory.

Finding **F15** applies: `FR-IAM-03` is observable only through a record that `C10` does not own. This ticket is written against the predicate and the restriction it yields, verifiable by Jest unit tests with no ticket aggregate present. End-to-end proof over real tickets lands with `C1` and `C2`.

## Scope

- `RecordVisibilityPolicy` in `libs/identity-access/domain`, taking an `Actor` and a record descriptor — requester id, affected competition id — expressed in `identity-access` vocabulary, never importing another context.
- Two operations with a shared decision: `mayView` and `mayActUpon` (comment, confirm resolution, submit CSAT), which must never diverge for the requester rule.
- A `ScopeRestriction` result type expressing the restriction declaratively (own records; own records plus a competition set), consumable by any context to build a query predicate.
- Jest unit tests: own record allowed, other record denied, identical outcome for view and act-upon, restriction shape for a plain requester.
- Out of scope: the not-found masking (`T-C10-42`); competition and league scopes (`T-C10-43` to `T-C10-46`); any repository in another context.

## Acceptance criteria

**Given** an actor holding only the Requester role **When** the predicate is evaluated for a record they raised **Then** it grants visibility.

**Given** the same actor **When** the predicate is evaluated for a record raised by another user **Then** it denies, and it denies identically for view and for act-upon.

**Given** a requester issuing a list query **When** the predicate is applied **Then** it yields a `ScopeRestriction` that names the restriction rather than a filtered collection, so the consuming repository can push it into the query.

**Given** the `identity-access/domain` library **When** its imports are inspected **Then** it imports no other bounded context and no framework.

**Given** the predicate suite **When** it runs **Then** it passes with no ticket aggregate, no database and no HTTP present.
