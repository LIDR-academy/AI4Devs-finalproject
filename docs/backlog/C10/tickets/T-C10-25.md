# [C10] T-C10-25 · `AuthenticateUser` use case

## Context

`US-C10-01` requires authentication to succeed only for a registered, active user, to fail with a **single generic** response that never discloses whether an identifier exists, and to compare the credential through the identity port rather than in a controller. This use case is where those rules live, and it must be unit-testable against a port double with no database and no HTTP (`US-C10-09`).

## Scope

- `AuthenticateUser` use case in `libs/identity-access/application`, depending on `IdentityProviderPort`, `SessionRepositoryPort`, `ClockPort` and the token issuer port from `T-C10-26`.
- Flow: verify the credential presentation through the port, map every failure onto one generic authentication failure, create a `Session`, issue a token, return the token plus the identity projection.
- Failure mapping is explicit and total: `InvalidCredential` and `AccountInactive` both produce the same outward result; `IdentityProviderUnavailable` produces a distinct typed error (`US-C10-10`).
- Jest unit tests with a stub port covering: success, wrong credential, unknown identifier, inactive account, provider unavailable.
- Out of scope: HTTP (`T-C10-27`), JWT mechanics (`T-C10-26`), the sign-in screen (`T-C10-31`).

## Acceptance criteria

**Given** a registered active user and a valid credential **When** the use case executes **Then** it returns a token and an identity projection carrying the user identifier, display name and assigned role identifiers, and no credential and no hash.

**Given** an incorrect credential **When** the use case executes **Then** it returns the same generic failure as for an unknown identifier, and no token and no session are created.

**Given** an inactive account and an otherwise valid credential **When** the use case executes **Then** it returns the generic failure and creates no session.

**Given** the identity provider is unavailable **When** the use case executes **Then** it returns a distinct typed error and never the invalid-credential failure.

**Given** the `identity-access/application` library **When** its imports are inspected **Then** there is no NestJS, TypeORM, Express or HTTP import, and the unit suite runs with no database and no server.
