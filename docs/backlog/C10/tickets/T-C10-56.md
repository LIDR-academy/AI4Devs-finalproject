# [C10] T-C10-56 · Configurable inactivity window with fail-fast validation

## Context

`US-C10-14` requires the inactivity period to be read through `ConfigService` with a documented default, and requires boot to **fail fast** if the value is missing or is not a positive duration.

Phase: `unphased`. `FR-IAM-06` is assigned to no phase in PRD §14 — finding **F9** — even though it is a security control. Whoever sequences this epic must resolve that; it is not decided here.

## Scope

- Inactivity-window key added to the validated configuration schema of `T-C10-04`, typed as a positive duration with a documented default.
- A second key for the warning threshold consumed by `T-C10-58`.
- Boot-time rejection of an absent, zero, negative or non-numeric value, with a message naming the key.
- The values exposed to the client through an existing authenticated endpoint, so the warning threshold is not duplicated as a client constant.
- Out of scope: the expiry behavior (`T-C10-57`) and the client warning (`T-C10-58`).

## Acceptance criteria

**Given** a valid positive duration **When** the application boots **Then** it starts and the value is available through `ConfigService`.

**Given** the key absent, zero, negative or non-numeric **When** the application boots **Then** it fails fast with a message naming the key, and does not start.

**Given** the configured window **When** the source is grepped for a hardcoded timeout literal **Then** there is no match outside the configuration schema default.

**Given** an authenticated client **When** it requests the session policy **Then** it receives the window and the warning threshold from the server rather than holding its own copy.
