# [C10] T-C10-04 · Scaffold `apps/api` — NestJS 11 composition root with validated configuration

## Context

Foundation work with no user story behind it. Source: `docs/backlog/epic-map.md` → **Foundation ownership (priced once)**, row *`apps/api`, `apps/api-e2e`, `apps/web`, `apps/web-e2e` (4 applications)*, priced in `C10`; and finding **F14** of `user-stories.md`.

`apps/api` is the composition root (`ARCHITECTURE.md` §5.4, ADR-002, ADR-003): the only backend project allowed to reach across contexts, and the place where every port is bound to an adapter. It must exist before any `identity-access` library can be wired.

## Scope

- `pnpm nx g @nx/nest:app api --directory=apps/api` with tags `platform:backend,scope:shared,type:app`.
- NestJS 11 on **Express 4** (pin intentional, `CLAUDE.md` §2).
- `@nestjs/config` with a **validated** schema, `isGlobal: true`; no raw `process.env` access outside the configuration module.
- Global `ValidationPipe` (`whitelist`, `forbidNonWhitelisted`, `transform`).
- Global `/api` prefix, with the health probes explicitly excluded from it (`CLAUDE.md` §3).
- Out of scope: structured logging, health probes and Swagger — those belong to the `NFR` epic standalone observability slice (`epic-map.md`, Suggested drill order, closing paragraph). This ticket only reserves the route exclusions they will use, so the exemption list of `T-C10-28` is stable.
- Out of scope: the database connection (`T-C10-16`).

## Acceptance criteria

Mechanical checks — this ticket has no user scenario.

**Given** the workspace **When** `pnpm nx build api` runs **Then** it succeeds.

**Given** the application **When** `pnpm nx serve api` runs with a complete environment **Then** it boots and answers on the configured port.

**Given** a required configuration key removed from the environment **When** the application boots **Then** it **fails fast** with a message naming the missing key, rather than starting with an undefined value.

**Given** the project configuration **When** its tags are inspected **Then** they are exactly `platform:backend`, `scope:shared`, `type:app`, and `pnpm nx lint api` passes the boundary rule of `T-C10-03`.

**Given** any source file under `apps/api` **When** it is grepped for `process.env` **Then** the only match is inside the configuration module itself.
