# [C10] T-C10-30 · Angular auth interceptor, token store and router guard

## Context

`US-C10-02` requires that an unauthenticated visitor requesting any route other than sign-in is redirected to sign-in **with the requested URL preserved** for post-authentication return. That needs three pieces on the client: somewhere to hold the token, an interceptor to attach it, and a router guard to enforce the rule.

## Scope

- Signal-based auth state in `libs/identity-access/data-access`: current identity, token, and derived authenticated flag. No `NgRx` (`CLAUDE.md` §3).
- Functional HTTP interceptor attaching the bearer token to API requests and, on a `401`, clearing the state and routing to sign-in — no swallowed HTTP errors.
- Functional router guard in the shell redirecting unauthenticated navigation to sign-in with the attempted URL captured as a return target.
- Post-authentication navigation back to the captured URL, defaulting to the home route when there is none.
- Jest tests for the guard and the interceptor.
- Out of scope: the sign-in screen itself (`T-C10-31`), sign-out (`T-C10-34`), the inactivity warning (`T-C10-58`).

## Acceptance criteria

**Given** an unauthenticated visitor **When** they request any route other than sign-in **Then** the router redirects to sign-in and the requested URL is preserved.

**Given** that preserved URL **When** the visitor authenticates successfully **Then** the shell navigates to it rather than to the default route.

**Given** an authenticated session **When** any API request is issued **Then** the interceptor attaches the bearer token, and it attaches nothing to non-API requests.

**Given** an API response of `401` **When** it reaches the interceptor **Then** the client state is cleared and the shell routes to sign-in; the error is never silently discarded.

**Given** the interceptor **When** it is inspected **Then** it is a functional interceptor registered through `provideHttpClient(withInterceptors(...))`, not a class-based `HTTP_INTERCEPTORS` provider.
