# [C10] T-C10-32 · `SignOutSession` use case

## Context

`US-C10-03` requires an explicit sign-out to terminate the **server-side session record**, so a token cannot be reused on a shared service-desk workstation. The aggregate and its port exist from `T-C10-24`; this ticket is the use case that drives them.

Phase note: `US-C10-03` traces `FR-IAM-01` (phase 0) and `FR-IAM-06` (unphased, finding **F9**); it is scheduled with its phase-0 half.

## Scope

- `SignOutSession` use case in `libs/identity-access/application`: terminate the session named by the caller session claim, using `ClockPort` for the termination timestamp.
- Idempotent: signing out an already terminated session succeeds and changes nothing.
- A caller may terminate only their own session; a request to terminate another session is denied.
- Jest unit tests against a stubbed `SessionRepositoryPort` and a fixed clock.
- Out of scope: the HTTP adapter (`T-C10-33`), the client action (`T-C10-34`), inactivity expiry (`T-C10-57`).

## Acceptance criteria

**Given** an active session **When** the use case executes **Then** the session record is terminated and the termination timestamp comes from `ClockPort`.

**Given** an already terminated session **When** the use case executes again **Then** it succeeds, changes nothing and raises no error.

**Given** a caller attempting to terminate a session that is not theirs **When** the use case executes **Then** it is denied and no session is terminated.

**Given** a user who signs out and then signs in again **When** the second sign-in completes **Then** a new session record and a new token are created and the previous ones remain terminated.

**Given** the application library **When** its imports are inspected **Then** it contains no framework, ORM or HTTP import and the suite runs with no database.
