# [C10] T-C10-53 · Web revoke action and the explicit no-entitlements state

## Context

`US-C10-12` requires that a user whose last role is revoked can still sign in, but sees an explicit **no entitlements** state rather than an empty screen or a silent error. It also requires the administrator to be told why a last-administrator revocation was refused.

## Scope

- Revoke action on the role-administration screen of `T-C10-50`, with a confirmation overlay from `T-C10-14` and an `aria-live` confirmation on success.
- Distinct rendering for the last-administrator refusal, explaining the reason rather than showing a generic error.
- A no-entitlements state in the shell: an authenticated user with no granting role lands on an explicit, localized screen explaining they have no entitlements and how to request them.
- Jest component tests for the three outcomes.
- Out of scope: the API, the safeguard logic.

## Acceptance criteria

**Given** an administrator **When** they revoke a role and confirm **Then** the row updates without a manual reload and the change is announced through the `aria-live` region.

**Given** the last-administrator refusal **When** it is returned by the API **Then** the screen explains the specific reason and the role remains listed.

**Given** a user whose last role has been revoked **When** they sign in **Then** authentication succeeds and the shell renders the explicit no-entitlements state, not an empty screen and not a silent error.

**Given** that no-entitlements state **When** it is inspected **Then** every string is a Transloco key and the state component comes from `libs/shared/ui`.
