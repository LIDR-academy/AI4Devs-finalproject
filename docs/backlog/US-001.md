## US refinada

**Historia de usuario:**
Como corredor, quiero ver el catálogo completo de productos de running al acceder a RunMarket, para explorar la oferta disponible y descubrir opciones antes de acotar por mis criterios.

### Ambigüedades resueltas

| Punto ambiguo | Decisión |
|---|---|
| **Paginación** | Fuera del alcance de US-001. El seed tiene 12 productos; se devuelven todos sin paginar. La paginación se pospone a una US posterior. |
| **Ordenación** | Sin criterio de orden explícito. El backend devuelve los productos en orden natural (`createdAt ASC`). |
| **Badge de nivel** | Se muestran todos los valores del array `level[]` del producto como badges independientes. Mapeo: `beginner` → "Principiante", `intermediate` → "Popular", `advanced` → "Avanzado", según DESIGN-SYSTEM.md. |
| **Enlace de la tarjeta** | `ProductCard` enlaza a `/product/[id]` para navegar a la ficha (flujo CU1→CU2). Es implícito en el caso de uso y se incluye en el contrato. |
| **Estado de carga** | `CatalogPage` es un Server Component (SSR). No hay estado de carga client-side para la carga inicial. El estado de error se gestiona con un wrapper Client Component que permite reintentar la llamada a la API. |
| **Campos de Product devueltos** | El endpoint devuelve el objeto `Product` completo para reutilización en US-002/005, pero la tarjeta de US-001 solo consume `id`, `name`, `brand`, `price`, `image` y `level[]`. |

Crear o ampliar `frontend/src/lib/api-client.ts` con la función `fetchProducts()`.

```typescript
// types/index.ts — tipos de dominio compartidos
export interface Product {
  id: string;
  name: string;
  brand: string;
  price: number;
  image: string;
  category: 'shoes' | 'clothing' | 'accessories';
  subcategory: string;
  description: string;
  features: string[];
  distance: string[];
  surface: string[];
  level: string[];
  objective: string[];
  sizes: string[];
  colors: string[];
  stock: number;
}

export interface ProductsResponse {
  products: Product[];
  total: number;
}

// lib/api-client.ts
const API_BASE = process.env.NEXT_PUBLIC_API_URL ?? 'http://localhost:4000';

export async function fetchProducts(): Promise<ProductsResponse> {
  const res = await fetch(`${API_BASE}/api/products`, { cache: 'no-store' });
  if (!res.ok) throw new Error(`Error ${res.status}: no se pudieron cargar los productos`);
  return res.json() as Promise<ProductsResponse>;
}
```

**Criterios de hecho**

- Llama a `${API_BASE}/api/products` con `cache: 'no-store'` (productos pueden cambiar con filtros)
- Lanza `Error` si `res.ok === false` con mensaje genérico (sin exponer detalles de red al cliente)
- Tipado estricto: devuelve `Promise<ProductsResponse>`; prohibido `any`
- `NEXT_PUBLIC_API_URL` se documenta en `.env.example` del frontend
- Cumple las reglas de seguridad aplicables de `CLAUDE.md` (no almacenar secretos client-side)
