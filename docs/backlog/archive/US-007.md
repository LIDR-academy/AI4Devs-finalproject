## US refinada

**Historia de usuario:**
Como corredor, quiero añadir un producto al carrito desde su ficha, para reservarlo y poder continuar comprando o proceder al pago cuando esté listo.

**Contexto técnico:**

- Esta US implementa por primera vez el endpoint `POST /api/cart` y la capa completa `Controller → CartService → CartRepository`, que hasta ahora no existen en el backend.
- US-006 creó `ProductVariantSelector` con un `handleAddToCart` stub sin llamada real a la API. US-007 conecta ese stub al endpoint real, añadiendo la prop `onAddToCart` al componente.
- El `sessionId` identifica el carrito de la sesión. Se genera server-side con `crypto.randomUUID()` (regla de seguridad CLAUDE.md) si la cookie no existe en la request y se devuelve en `Set-Cookie: sessionId=<uuid>; HttpOnly; SameSite=Strict; Path=/`.
- El backend debe hacer `upsert` sobre `CartItem` aprovechando la restricción única `@@unique([cartId, productId, size, color])`: si la combinación ya existe, incrementa la cantidad; si no, crea la línea.
- La validación de stock contra la BD ocurre en `CartService.addItem`, no solo en el frontend. El precio del ítem en la respuesta se lee de `Product.price` en la BD, nunca del body del cliente.
- El `CartContext` (React Context + localStorage) es la fuente de verdad del carrito en el frontend. Tras un añadido exitoso, `CartContext` se actualiza con los nuevos ítems y el badge del header refleja la nueva cantidad total.
- Los toasts de confirmación y error se emiten con Sonner, ya incluido en el stack.

**Comportamiento explicitado:**

| Situación | Comportamiento |
|---|---|
| Añadido exitoso (variante nueva) | Backend crea `CartItem`; devuelve `Cart` actualizado con `200 OK`; frontend actualiza `CartContext`; toast «Producto añadido al carrito» |
| Producto ya en carrito (misma talla y color) | Backend incrementa `quantity` del `CartItem` existente; devuelve `Cart` actualizado con `200 OK` |
| `quantity + existente > product.stock` | Backend responde `409 Conflict` con `{ error: "Stock insuficiente", available: N }`; frontend muestra toast de error |
| `productId` inexistente | Backend responde `404 Not Found` con `{ error: "Producto no encontrado" }` |
| Body inválido (Zod) | Backend responde `400 Bad Request` con errores de validación |
| `stock === 0` al cargar la ficha | El botón «Añadir al carrito» está deshabilitado con texto «Agotado» (heredado de US-006); no se hace llamada a la API |
| Error de red o error interno del servidor | Frontend muestra toast «No se pudo añadir al carrito. Inténtalo de nuevo.»; corredor permanece en la ficha |
| Sin `sessionId` en cookie | El backend genera uno nuevo con `crypto.randomUUID()` y lo envía en `Set-Cookie` |

**Contrato de la API:**

```
POST /api/cart
Cookie: sessionId=<uuid>  (opcional en la primera llamada)

Request body (Zod .strict()):
{
  productId: string (uuid, requerido),
  quantity:  number (entero, mínimo 1, requerido),
  size?:     string (opcional),
  color?:    string (opcional)
}

Response 200 OK — Set-Cookie: sessionId=...; HttpOnly; SameSite=Strict; Path=/
{
  sessionId: string,
  items: Array<{
    productId:    string,
    productName:  string,
    productBrand: string,
    productPrice: number,
    image:        string,
    quantity:     number,
    size?:        string,
    color?:       string
  }>,
  subtotal: number,
  shipping: number,
  total:    number
}

Errores:
  400 — body inválido (validación Zod)           { error: string }
  404 — productId no existe en la BD             { error: "Producto no encontrado" }
  409 — stock insuficiente                       { error: "Stock insuficiente", available: number }
  500 — error interno (sin detalles internos)    { error: "Error interno del servidor" }
```

**Contrato del componente `ProductVariantSelector` actualizado:**

```tsx

  colors:   string[];
  stock:    number;
  // Nuevas props introducidas en US-007:

}

// onAddToCart es interno — el componente llama directamente a addToCart(cartContext)
```

**Criterios de aceptación cubiertos:**

1. El corredor pulsa «Añadir al carrito» con variante válida; el producto se añade al carrito, el badge del header se actualiza y aparece un toast «Producto añadido al carrito».
2. Si el mismo producto (misma talla y color) ya está en el carrito, la cantidad se incrementa.
3. El corredor permanece en la ficha tras añadir; no hay redirección automática.
4. La cantidad acumulada en el carrito no supera el stock disponible del producto.
5. Si el producto está agotado, el botón «Añadir al carrito» está deshabilitado; el añadido no es posible bajo ninguna interacción.

### `US-007-TASK-02` — `CartService.addItem` — lógica de negocio con validación de stock

- [x] Implementado
- **Capa:** Backend
- **Depende de:** US-007-TASK-01
- **Criterio de aceptación cubierto:** «la cantidad acumulada en el carrito no supera el stock disponible del producto» · «si el mismo producto ya está en el carrito, la cantidad se incrementa»

**Descripción técnica**

Crear `backend/src/services/cart.service.ts` implementando `ICartService`. El servicio recibe mocks de repositorios en tests — nunca accede a Prisma directamente.

Flujo de `addItem(sessionId, item)`:
1. Obtener el carrito de la sesión via `cartRepository.findOrCreateCart(sessionId)`.
2. Leer el stock actual del producto via `productRepository.findById(item.productId)`.
3. Si el producto no existe → lanzar `NotFoundError`.
4. Calcular la cantidad ya existente en el carrito para esa combinación (`productId + size + color`).
5. Si `existing_quantity + item.quantity > product.stock` → lanzar `StockError` con `available = product.stock - existing_quantity`.
6. Delegar el upsert a `cartRepository.upsertItem`.
7. Obtener el carrito actualizado, calcular totales (subtotal, shipping, total) y devolverlo.

Reglas de cálculo de totales:
- `subtotal = sum(item.price * item.quantity)` — el precio se lee de `Product.price`, nunca del payload del cliente.
- `shipping = subtotal >= 50 ? 0 : 4.99`.
- `total = subtotal + shipping`.

Crear `backend/tests/unit/cart.service.test.ts` con mocks de `ICartRepository` e `IProductRepository`.

**Criterios de hecho**

- `addItem` lanza `NotFoundError` cuando el producto no existe en la BD.
- `addItem` lanza `StockError` (con campo `available`) cuando `qty_carrito + qty_nueva > stock`.
- `addItem` llama a `cartRepository.upsertItem` cuando hay stock suficiente.
- El precio devuelto en el ítem proviene del `Product` leído de la BD, no del cuerpo del request.
- El cálculo de `shipping` aplica envío gratuito cuando `subtotal >= 50`.
- Cumple las reglas de seguridad aplicables de `CLAUDE.md` (precio siempre de BD).

## OWASP — Revisión de seguridad

> Pendiente — se completa en Fase 5.

### Superficie de ataque identificada en Fase 1

| Vector | Componente | Regla CLAUDE.md aplicable |
|---|---|---|
| **IDOR sobre sessionId** | `POST /api/cart`, `CartRepository` | El carrito se resuelve siempre desde `req.sessionId` (cookie HttpOnly), nunca desde el body del request |
| **Price tampering** | `CartService.addItem` | El precio de cada ítem se lee de `ProductRepository` en la BD; el body nunca incluye precio |
| **Zod passthrough** | `CartController` | El schema Zod usa `.strict()`; campos extra son rechazados con `400` |
| **sessionId predecible** | Middleware de sesión | Generado con `crypto.randomUUID()` (Node.js nativo); nunca con `Math.random()` ni timestamp |
| **Cookie insegura** | `Set-Cookie` header | `HttpOnly; SameSite=Strict; Path=/`; sin `Secure` solo en desarrollo local |
| **Stack trace expuesto** | `error-handler.ts` | Errores de Prisma y errores internos mapeados a `{ error: string }` genérico antes de responder |
| **Rate limiting insuficiente** | `POST /api/cart` | Rate limiting más restrictivo que el catálogo (conforme a CLAUDE.md) configurado en `rate-limit.ts` |
| **PII en localStorage** | `CartContext` | `sessionId` no se persiste en `localStorage`; solo ítems de carrito sin PII |
| **dangerouslySetInnerHTML** | Componentes de carrito | Prohibido; todo contenido dinámico renderizado como JSX texto |
