## US refinada

**Historia de usuario:**
Como corredor, quiero ver todos los productos que he añadido al carrito, modificar cantidades y eliminar artículos, para revisar mi selección final y conocer el coste total antes de proceder al pago.

**Contexto técnico:**

- Esta US construye sobre la infraestructura de carrito implementada en US-007: `CartRepository` (con `findOrCreateCart`, `upsertItem`, `getCartWithItems`, `removeItem`, `clearCart`), `CartService.addItem`, `CartController` (`POST /api/cart`), middleware de sesión y `CartContext`. Los métodos `getCart`, `updateItem` y `removeItem` del servicio se definieron en la interfaz `ICartService` en US-007 pero su implementación completa corresponde a esta US.
- La `CartPage` en `/cart` es un **Client Component** (sin SSR necesario, conforme a `docs/ARCHITECTURE.md`). Lee el estado del `CartContext` hidratado desde el backend al montarse.
- El `sessionId` viaja siempre en cookie HttpOnly; nunca en el body ni en la URL. El middleware de sesión de US-007 está disponible y se reutiliza sin cambios.
- Los precios de los ítems se leen siempre de la BD a través de `CartRepository.getCartWithItems`. Jamás se confía en precios provenientes del cliente.
- El umbral de envío gratuito es **50 €** (subtotal). Por debajo, el envío cuesta 4,99 € y se muestra el mensaje incentivador «¡Añade X€ más para envío gratis!».
- La respuesta del carrito se amplía en esta US para incluir `stock` por ítem (del producto relacionado), lo que permite al frontend limitar el stepper al stock disponible. Esta adición es retrocompatible con `POST /api/cart` de US-007 (campo nuevo, no se rompe ninguna respuesta existente).
- El botón «Tramitar pedido» navega a `/checkout` (flujo cubierto en US-009+). En US-008 solo se exige que el botón esté deshabilitado cuando el carrito está vacío.

**Comportamiento explicitado:**

| Situación | Comportamiento |
|---|---|
| Carrito con artículos | Se muestran todos los ítems con imagen, nombre, marca, variante (talla, color), precio unitario y stepper; subtotal, envío y total se recalculan en tiempo real |
| Modificar cantidad (stepper +/-) | El frontend llama a `PUT /api/cart/:productId`; al recibir el carrito actualizado del servidor, `CartContext` y la UI se refrescan |
| Eliminar ítem (botón eliminar) | El frontend llama a `DELETE /api/cart/:productId`; al recibir el carrito actualizado, `CartContext` y la UI se refrescan |
| Subtotal ≥ 50 € | `shipping = 0`; se muestra «Gratis» en verde |
| Subtotal < 50 € | `shipping = 4.99`; se muestra «4,99 €» y «¡Añade X€ más para envío gratis!» como incentivo |
| Carrito vacío (todos los ítems eliminados) | Estado vacío: icono, texto «Tu carrito está vacío» y CTA «Ver catálogo» (enlaza a `/`) |
| «Tramitar pedido» con carrito vacío | Botón deshabilitado (`disabled`); navegación a `/checkout` no permitida |
| «Tramitar pedido» con artículos | Botón activo; navega a `/checkout` |
| Navegación fuera y vuelta | Los ítems persisten: `CartContext` + caché `localStorage` (sesión activa) |
| `PUT /api/cart/:productId` con `quantity > stock` | Backend responde `409 Conflict`: `{ error: "Stock insuficiente", available: N }` |
| `PUT /api/cart/:productId` con ítem no encontrado | Backend responde `404 Not Found` |
| `DELETE /api/cart/:productId` con ítem no encontrado | Backend responde `404 Not Found` |
| Error de red en stepper o eliminar | Toast de error («No se pudo actualizar el carrito. Inténtalo de nuevo.»); el estado del carrito no cambia |

`updateItemQuantity`: a diferencia de `upsertItem` (que incrementa), este método **establece** la cantidad exacta. Usa `prisma.cartItem.updateMany` filtrando por `{ cartId, productId, size, color }`. Si no encuentra el ítem, lanza `NotFoundError`.

  color?: string

### `US-008-TASK-02` — Ampliar `CartController` y rutas

- [x] Implementado
- **Capa:** Backend
- **Depende de:** US-008-TASK-01
- **Criterio de aceptación cubierto:** todos los criterios backend: consulta, modificación de cantidades, eliminación, errores 404/409

**Descripción técnica**

Ampliar `backend/src/controllers/cart.controller.ts` y `backend/src/routes/cart.routes.ts`.

**`GET /api/cart` → `CartController.getCart`:**
1. Extrae `sessionId` de `req.sessionId` (middleware de sesión de US-007).
2. Llama a `cartService.getCart(sessionId)`.
3. Responde `200` con el carrito (incluyendo `stock` por ítem).
4. Errores no controlados pasan al `error-handler.ts` global.

**`PUT /api/cart/:productId` → `CartController.updateItem`:**
1. Valida el body con schema Zod `.strict()`:
   ```typescript
   const UpdateCartItemSchema = z.object({
     quantity: z.number().int().min(1),
     size:     z.string().optional(),
     color:    z.string().optional(),
   }).strict();
   ```
2. Extrae `productId` de `req.params.productId` (validar que sea una cadena no vacía).
3. Extrae `sessionId` de `req.sessionId`.
4. Llama a `cartService.updateItem(sessionId, productId, quantity, size, color)`.
5. Si `NotFoundError` → `404 { error: "Ítem no encontrado en el carrito" }`.
6. Si `StockError` → `409 { error: "Stock insuficiente", available: N }`.
7. Éxito → `200` con el carrito actualizado.

**`DELETE /api/cart/:productId` → `CartController.removeItem`:**
1. Extrae `productId` de `req.params.productId`.
2. Extrae `size?` y `color?` de `req.query` (sanitizados: solo se usan si son strings no vacíos).
3. Extrae `sessionId` de `req.sessionId`.
4. Llama a `cartService.removeItem(sessionId, productId, size, color)`.
5. Si `NotFoundError` → `404 { error: "Ítem no encontrado en el carrito" }`.
6. Éxito → `200` con el carrito actualizado.

**Rate limiting:** aplicar `mutationLimiter` (de `rate-limit.ts`, ya definido en US-007) a los tres nuevos endpoints.

**OpenAPI:** documentar los tres nuevos endpoints en `backend/src/docs/openapi.ts`.

**Criterios de hecho**

- `PUT /api/cart/:productId` con ítem inexistente devuelve `404`.
- `PUT /api/cart/:productId` con `quantity > stock` devuelve `409` con `available`.
- `DELETE /api/cart/:productId` con ítem existente devuelve `200` con carrito actualizado.

## OWASP — Revisión de seguridad

### Superficie de ataque identificada en Fase 1

| Vector | Componente | Regla CLAUDE.md aplicable |
|---|---|---|
| **IDOR sobre sessionId** | `GET /api/cart`, `PUT /api/cart/:productId`, `DELETE /api/cart/:productId` | El carrito se resuelve siempre desde `req.sessionId` (cookie HttpOnly), nunca desde el body ni la URL; un corredor no puede acceder al carrito de otra sesión |
| **Price tampering** | `CartService.updateItem` | El precio de cada ítem se lee de `Product` en BD a través del repositorio; el body de `PUT` solo acepta `quantity`, `size?` y `color?` |
| **Zod passthrough** | `CartController.updateItem` | Schema `.strict()` en `PUT`; campos extra rechazados con `400` |
| **Stock manipulation** | `CartService.updateItem` | Stock re-validado en el backend antes de actualizar; `409` si `quantity > stock` |
| **sessionId predecible** | Middleware de sesión (US-007, reutilizado) | Generado con `crypto.randomUUID()`; validado como UUID en cada request |
| **Query param injection** | `CartController.removeItem` | `size` y `color` leídos de `req.query`; son strings que se pasan a Prisma como valores parametrizados (no se usan en raw queries) |
| **Rate limiting insuficiente** | `PUT /api/cart/:productId`, `DELETE /api/cart/:productId` | `mutationLimiter` aplicado en ambos endpoints (conforme a CLAUDE.md) |
| **Stack trace expuesto** | `error-handler.ts` (global, de US-007) | Errores internos mapeados a `{ error: string }` genérico |
| **PII en localStorage** | `CartContext` | Solo ítems de carrito (datos de producto, sin PII); `sessionId` exclusivamente en cookie HttpOnly |
| **dangerouslySetInnerHTML** | Componentes de carrito | Prohibido; contenido dinámico (nombre, marca, variante) renderizado como texto escapado por JSX |
