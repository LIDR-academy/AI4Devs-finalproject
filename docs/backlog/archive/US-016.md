## US refinada

### Historia de usuario

Como equipo de desarrollo, queremos que el backend emita las cabeceras de seguridad HTTP
estándar y que el frontend declare una Content Security Policy, para reducir la superficie
de ataque ante clickjacking, MIME-sniffing y ataques de downgrade, y para que el
rate-limiting sea efectivo en producción detrás de un proxy inverso.

### Contexto técnico

El análisis de pentesting identificó seis vulnerabilidades CRÍTICO/ALTO de infraestructura
que no tocan lógica de negocio:

| Vulnerabilidad | Impacto | Archivo afectado |
|---|---|---|
| Sin `helmet` → sin security headers | Clickjacking, MIME-sniffing, downgrade HTTPS | `backend/src/app.ts` |
| Sin CSP en Next.js | XSS sin restricción de fuentes de scripts | `frontend/next.config.mjs` |
| Swagger UI accesible en producción | Disclosure completo del esquema API | `backend/src/routes/docs.routes.ts` |
| Sin `trust proxy` en Express | Rate-limiter usa IP del proxy, no del cliente | `backend/src/app.ts` |
| Body JSON sin límite explícito | Parser consume CPU antes de rechazar entradas grandes | `backend/src/app.ts` |
| 404 hace eco del path | Información sobre rutas internas en respuesta de error | `backend/src/middleware/error-handler.ts` |

### Contrato técnico

#### Backend — cabeceras emitidas por `helmet`

`helmet()` aplicado como primer middleware en `app.ts` produce (entre otras):

| Cabecera | Valor por defecto de helmet |
|---|---|
| `X-Frame-Options` | `SAMEORIGIN` → sobrescribir a `DENY` |
| `X-Content-Type-Options` | `nosniff` |
| `Strict-Transport-Security` | `max-age=15552000; includeSubDomains` |
| `Referrer-Policy` | `no-referrer` |
| `X-DNS-Prefetch-Control` | `off` |

#### Backend — trust proxy y body limit

```ts
app.set('trust proxy', 1);               // antes de cualquier middleware
app.use(express.json({ limit: '10kb' })); // sustituye al express.json() actual
```

- Con `trust proxy: 1`, `req.ip` resolverá el primer valor de `X-Forwarded-For`.
- Con `limit: '10kb'`, Express responde 413 antes de invocar cualquier middleware propio.

#### Backend — guard de Swagger UI

```ts
if (process.env.NODE_ENV !== 'production') {
  docsRouter.get('/docs.json', ...);
  docsRouter.use('/docs', ...);
}
```

En producción, las rutas `/api/docs` y `/api/docs.json` no se registran → Express delega al
handler de 404 global → responde `{"error":"Not found"}`.

#### Backend — 404 sin eco del path

```ts
// Antes:
next(new NotFoundError(`Route ${req.method} ${req.path} not found`));
// Después:
next(new NotFoundError('Not found'));
```

La clase `NotFoundError` existe y el `errorHandler` ya emite `{ error: err.message }`.

#### Frontend — security headers en Next.js

`next.config.mjs` → función `headers()` que aplica a todas las rutas (`source: '/(.*)'`):

| Cabecera | Valor (producción) | Valor (desarrollo) |
|---|---|---|
| `Content-Security-Policy` | `default-src 'self'; script-src 'self' 'unsafe-inline'; …` | igual + `'unsafe-eval'` en `script-src` (necesario para HMR) |
| `X-Frame-Options` | `DENY` | `DENY` |
| `X-Content-Type-Options` | `nosniff` | `nosniff` |
| `Referrer-Policy` | `no-referrer` | `no-referrer` |

> `'unsafe-inline'` en `script-src` y `style-src` es necesario en Next.js 15 porque los
> Server Components inyectan estilos y scripts inline. `'unsafe-eval'` es necesario
> adicionalmente en modo desarrollo para el HMR; se omite en producción. En una iteración
> futura se puede endurecer con nonces si se añade un middleware que los genere por petición.

### `US-016-TASK-01` — Instalar helmet y aplicar security headers en Express

- [x] Implementado

- **Criterio de aceptación cubierto:** CA-1 — `GET /api/health` emite `X-Frame-Options`, `X-Content-Type-Options`, `HSTS` y `Referrer-Policy`

**Descripción técnica**

Instalar el paquete `helmet` (`npm install helmet --workspace=backend`) y registrarlo como
primer middleware en `backend/src/app.ts`, antes de `corsMiddleware`. Helmet aplica un
conjunto de cabeceras de seguridad por defecto. Se necesita sobrescribir `frameguard` para
forzar `DENY` en lugar del valor por defecto `SAMEORIGIN`:

```ts
import helmet from 'helmet';

```

Capas afectadas: únicamente `app.ts` (configuración de middleware). No afecta ninguna capa
de negocio.

- `npm install` en el workspace de backend incluye `helmet` en `dependencies`.
- `helmet` es el primer middleware registrado en `app.ts`, antes de `cors`.
- `GET /api/health` en tests incluye al menos: `x-frame-options: DENY`,
  `x-content-type-options: nosniff`, `strict-transport-security`, `referrer-policy`.

### `US-016-TASK-05` — Security headers (incluida CSP) en Next.js

- [x] Implementado
- **Capa:** Frontend
- **Depende de:** —
- **Criterio de aceptación cubierto:** CA-2 — `GET /` responde con `Content-Security-Policy`

**Descripción técnica**

Añadir la función `headers()` en `frontend/next.config.mjs` aplicando security headers a
todas las rutas. La CSP debe permitir lo estrictamente necesario para Next.js 15 con App
Router (scripts inline propios del runtime de hidratación):

```js
const securityHeaders = [
  {
    key: 'Content-Security-Policy',
    value: [
      "default-src 'self'",
      "script-src 'self' 'unsafe-inline'",
      "style-src 'self' 'unsafe-inline'",
      `img-src 'self' data: ${process.env.NEXT_PUBLIC_ASSETS_BASE_URL ?? 'http://localhost:4000'}`,
      "font-src 'self'",
      `connect-src 'self' ${process.env.NEXT_PUBLIC_API_URL ?? 'http://localhost:4000'}`,
    ].join('; '),
  },
  { key: 'X-Frame-Options', value: 'DENY' },
  { key: 'X-Content-Type-Options', value: 'nosniff' },
  { key: 'Referrer-Policy', value: 'no-referrer' },
];

const nextConfig = {
  async headers() {
    return [{ source: '/(.*)', headers: securityHeaders }];
  },
};
```

> `'unsafe-inline'` en `script-src`/`style-src` es un compromiso necesario en Next.js 15
> App Router (los Server Components inyectan chunks inline). Se puede endurecer con nonces
> en una iteración futura cuando se implemente un middleware que los genere por petición.

**Criterios de hecho**

- `next build` y `next dev` arrancan sin errores tras el cambio.
- La respuesta HTTP de `GET /` incluye la cabecera `Content-Security-Policy`.
- La respuesta HTTP de `GET /` incluye `X-Frame-Options: DENY`.
- Cumple las reglas de seguridad aplicables de `CLAUDE.md`.

**Tests TDD (obligatorios)**

| Test | Tipo | Aserción |
|---|---|---|
| `GET / incluye Content-Security-Policy` | Playwright (`e2e/tests/security-headers.spec.ts`) | `response.headers()['content-security-policy']` definido y contiene `default-src 'self'` |
| `GET / incluye X-Frame-Options DENY` | Playwright | `response.headers()['x-frame-options'] === 'DENY'` |

- Test en rojo escrito antes del código de producción: sí.
- Nota: los tests de headers de Next.js no son verificables con Vitest/RTL porque dependen
  del servidor HTTP real. Se usa Playwright (ya instalado en `e2e/`) con un spec dedicado
  `security-headers.spec.ts` que no forma parte de los specs de flujo de usuario.

## Seguridad OWASP

| ID | Severidad | Componente | Vector / Exploit | Fix | Estado |
|---|---|---|---|---|---|
| SEC-01 | LOW | `frontend/next.config.mjs` | `unsafe-inline` en `script-src`/`style-src` debilita la protección XSS de la CSP: un XSS que inyecte scripts inline no queda bloqueado por la política | Tradeoff necesario en Next.js 15 App Router (scripts de hidratación son inline). Mitigable en el futuro con nonce-based CSP + middleware que genere el nonce por petición. No accionable en el MVP sin refactorizar el runtime de Next.js | aceptado — LOW, no accionable en MVP |
| SEC-02 | LOW | `backend/src/app.ts` | `trust proxy: 1` confía en la cabecera `X-Forwarded-For`. Si el backend se expone directamente a internet (sin proxy inverso delante), un atacante puede falsificar esa cabecera y eludir el rate-limiter enviando IPs arbitrarias | Requiere que el despliegue siempre coloque un proxy inverso (nginx, AWS ALB, Cloudflare) delante del backend. Documentar como prerrequisito de infraestructura. En desarrollo local no aplica | aceptado — LOW, mitigable por infraestructura |
| SEC-03 | HIGH | `backend/package.json` (devDep) | `form-data < 4.0.6` (transitivo de `supertest`): CRLF injection (GHSA-hmw2-7cc7-3qxx). Sólo en devDependencies — no deployable a producción | Resuelto con `npm audit fix` → 0 vulnerabilidades | fixed |
| SEC-04 | LOW | `frontend/next.config.mjs` | La CSP inicial omitía `'unsafe-eval'` en `script-src`. El servidor de desarrollo de Next.js (HMR, compilación dinámica de módulos) necesita `eval()`, lo que rompía la hidratación en dev y hacía fallar 8 de los 11 tests E2E existentes | `next.config.mjs` añade `'unsafe-eval'` a `script-src` condicionalmente cuando `NODE_ENV !== 'production'`; en build de producción la directiva queda estricta sin `'unsafe-eval'`. Detectado al ejecutar la suite E2E completa por primera vez con el stack levantado | fixed |
