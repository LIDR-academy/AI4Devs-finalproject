# 🎫 RESTO-TK-007: Implementación de Pantalla de Notificaciones y Alertas Dinámicas en Frontend

## 📝 Descripción
Este ticket consiste en implementar la pantalla táctil de notificaciones en el cliente y la lógica de renderizado del feed de alertas críticas en la tablet. La lógica de negocio calcula las alertas dinámicamente en el cliente o la API sin persistir datos extras de alerta en PostgreSQL, detectando vencimientos próximos (FEFO), niveles mínimos de stock en línea y estado de red offline (IndexedDB local queue).

*   **ID US Relacionada:** `US-006`
*   **Módulo / Vertical Slice:** `kitchen` (Operaciones de Cocina)
*   **Estimación (Story Points):** 3
*   **Prioridad MoSCoW:** Should Have
*   **Prerrequisitos:** `RESTO-TK-001`, `RESTO-TK-004` (Requiere el endpoint de consulta de remanentes activos)

---

## 🔀 Alcance de Modificación (Hexagonal Layers)
*   **Domain / Application:** Definición de la lógica utilitaria de detección y tipado de alertas (`CRITICAL`, `WARNING`, `INFO`) basada en la fecha actual (`calculatedExpirationDate - Date.now()`) y el stock restante.
*   **Infrastructure / Frontend:**
    *   Creación de la ruta Next.js `/app/kitchen/notifications/page.tsx`.
    *   Componentes de visualización React `NotificationFeed.tsx` y `NotificationBanner.tsx` diseñados en estética oscura (dark mode) con elementos semafóricos de alto contraste.
    *   Integración con el hook de cola local `useOfflineQueue.ts` para capturar el estado `offline` y alertar al usuario en tiempo real.

---

## ⚠️ Mitigación de Riesgos Técnicos
1.  **Congelamiento / Degradación de UI en Tablets de Gama Media:** La evaluación continua de fechas de expiración en milisegundos de muchos ingredientes en pantalla puede saturar el hilo principal de renderizado de React. Mitigar esto calculando las alertas dinámicas mediante un hook optimizado con `useMemo` y configurando un temporizador (`setInterval`) para refrescar las alertas cada 1 minuto, en lugar de en cada ciclo de render.
2.  **Excepciones de Red no Controladas:** Asegurar que si la API del backend no responde, la UI muestre un estado de desconexión amable sin colapsar la aplicación (uso de React Error Boundaries).

---

## ✅ Criterios de Aceptación & DoD (Definition of Done)

### Criterio de Aceptación 1: Visualización correcta del feed semafórico
*   **Given** que el operario de cocina accede a `/kitchen/notifications`
*   **And** existen remanentes activos en el estado del cliente con menos de 6 horas de vida útil restante
*   **When** se carga la pantalla
*   **Then** las alertas correspondientes se renderizan en la parte superior con estilo de color rojo e icono de urgencia crítica.

### Criterio de Aceptación 2: Banner persistente de estado Offline
*   **Given** que la conexión del navegador se interrumpe (`navigator.onLine` es falso)
*   **When** se muestra la interfaz del feed
*   **Then** aparece un banner persistente e inamovible en la cabecera advirtiendo del modo offline y garantizando que los registros locales están a salvo.

### DoD Estricto:
1.  **Diseño Responsivo / Táctil:** El banner offline y las alertas críticas deben diseñarse bajo el estándar de accesibilidad de alto contraste y tamaño mínimo de botón `64px` conforme a las guías UX/UI.
2.  **Testing:** Simular el estado `navigator.onLine = false` mediante tests unitarios de React para validar la renderización del banner.
