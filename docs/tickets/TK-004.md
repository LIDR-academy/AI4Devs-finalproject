# 🎫 TK-004: Implementación del Slice de Consulta de Remanentes Activos en Cocina (FEFO)

## 📝 Descripción
Este ticket consiste en la exposición de una consulta optimizada para obtener los remanentes abiertos y disponibles en cocina. La respuesta debe ordenarse cronológicamente por su fecha de expiración acelerada de menor a mayor, garantizando que el personal de cocina pueda identificar a primera vista qué ingredientes están más próximos a vencer (FEFO).

*   **ID US Relacionada:** `US-003`
*   **Módulo / Vertical Slice:** `kitchen` (Servicio y Línea)
*   **Estimación (Story Points):** 3
*   **Prioridad MoSCoW:** Must Have
*   **Prerrequisitos:** `TK-001`, `TK-003` (Requiere existencia del modelo y la lógica de creación de remanentes)

---

## 🔀 Alcance de Modificación (Hexagonal Layers)
*   **Domain:** Interfaz del puerto `IRemanenteRepository` con consulta específica de remanentes activos.
*   **Application:** Caso de uso `GetActiveRemanentesUseCase` con ordenación FEFO.
*   **Infrastructure:** Endpoint `GET /api/kitchen/remanentes` con soporte opcional de filtro por ubicación (`location`), adaptador de consulta Prisma optimizado y pruebas unitarias/de carga rápidas.

---

## ⚠️ Mitigación de Riesgos Técnicos
1.  **Problema de Consultas N+1 (N+1 Select Query):** Al listar los remanentes activos de cocina, el backend necesitará desplegar los datos básicos del insumo asociado (nombre, unidad). Si no se realiza un join correcto, Prisma ejecutará una consulta SQL por cada remanente. Mitigar esto utilizando `include: { insumo: true }` o `select` explícito en la llamada de Prisma para traer los datos agrupados en una sola query SQL.
2.  **Rendimiento en Base de Datos:** Verificar mediante un plan de consulta (`EXPLAIN ANALYZE`) que la base de datos utiliza el índice compuesto indexado `idx_remanente_fefo` (`status`, `calculated_expiration_date`).

---

## ✅ Criterios de Aceptación & DoD (Definition of Done)

### Criterio de Aceptación 1: Consulta de remanentes en orden FEFO (Happy Path)
*   **Given** que existen remanentes abiertos en la cocina con vencimientos calculados para mañana (Remanente A) y hoy (Remanente B)
*   **When** se invoca al endpoint `GET /api/kitchen/remanentes`
*   **Then** la API responde con estado `200 OK`
*   **And** el primer elemento del JSON es el Remanente B (vence antes) y el segundo es el Remanente A.

### DoD Estricto:
1.  **TDD Compliance:** Desarrollar una prueba unitaria del caso de uso utilizando un repositorio en memoria (`InMemoryRemanenteRepository`) donde se registren elementos desordenados y se valide que el resultado del caso de uso retorne la lista ordenada cronológicamente.
2.  **Seguridad:** Validar que el endpoint requiere autenticación JWT con rol mínimo `OPERATOR`.
