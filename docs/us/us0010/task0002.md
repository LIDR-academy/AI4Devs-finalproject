# TASK0002 — Frontend: página Mis Reservas + confirmar asistencia

## User Story Padre
[US0010](us0010.md) — Ver historial + confirmar asistencia

## Descripción
Implementar página "Mis Reservas" con listado de bookings, indicadores de estado, botón confirmar asistencia y CTA de calificación.

## Detalles de Implementación
- **Capa**: Frontend
- **Componentes afectados**: `frontend/src/app/features/bookings/`
- **Endpoint(s)**: Consume `GET /api/bookings/me` y `POST /api/bookings/{id}/complete`

## Pasos Técnicos
1. Crear ruta `/mis-reservas` (protegida con AuthGuard)
2. Crear `BookingListPage`:
   - Lista de booking cards ordenadas
   - Skeleton loading mientras carga
   - Estado vacío: "No tienes reservas aún" con CTA a vitrina
3. Crear `BookingCardComponent`:
   - Nombre artista (clickeable → perfil), fecha, hora, estado, monto
   - Indicadores visuales por estado:
     - Confirmada: badge azul
     - Completada: badge verde
     - Cancelada: badge rojo
   - Si confirmed + fecha pasó: botón "Confirmar asistencia"
   - Si completed + !hasReview: CTA "Calificar" (link a US0013)
4. Acción "Confirmar asistencia":
   - Dialog de confirmación: "¿Asististe a esta sesión?"
   - POST /api/bookings/{id}/complete
   - Al confirmar: actualizar card (badge verde + mostrar CTA calificar)
   - Toast: "Asistencia confirmada"
5. Crear `BookingDetailDialog/Page`:
   - Click en card → detalle completo (fecha, hora, estilo, zona, precio, notas)
6. Tests:
   - Lista renderiza bookings correctamente
   - Estados con colores correctos
   - Botón confirmar asistencia visible solo si fecha pasó
   - Confirmar asistencia actualiza estado

## Criterios de Done
- [ ] Lista de reservas funcional con estados visuales
- [ ] Confirmar asistencia funciona (solo si fecha pasó)
- [ ] CTA Calificar aparece para completed sin review
- [ ] Estado vacío manejado
- [ ] Dialog de confirmación antes de completar
- [ ] Tests de componentes
- [ ] Ruta protegida (redirect a login si no auth)

- Tiempo estimado: 4 horas
- Complejidad: Media
