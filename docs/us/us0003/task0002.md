# TASK0002 — Frontend: página vitrina con secciones y cards

## User Story Padre
[US0003](us0003.md) — Ver vitrina principal de tatuajes sin login

## Descripción
Implementar la página principal con las 4 secciones de artistas, cards visuales, lazy loading de imágenes y geolocalización del navegador.

## Detalles de Implementación
- **Capa**: Frontend
- **Componentes afectados**: `frontend/src/app/features/showcase/`, `frontend/src/app/shared/components/artist-card/`
- **Endpoint(s)**: Consume `GET /api/showcase`

## Pasos Técnicos
1. Crear `ShowcaseService` que llama a GET /api/showcase con lat/lng opcionales
2. Crear componente `ShowcasePage` (ruta: `/`):
   - Al cargar: solicitar geolocalización con `navigator.geolocation.getCurrentPosition()`
   - Si acepta: pasar coords al service
   - Si rechaza: llamar sin coords (retorna por rating)
3. Crear componente `ArtistCard` (standalone, reutilizable):
   - Imagen con lazy loading (`loading="lazy"` + Intersection Observer)
   - Nombre del artista, rating (estrellas), estilo principal, comuna
   - Badge "Certificado" si isCertified (usa componente de US0007)
   - Click → navega a /artista/{slug}
4. Crear componente `ShowcaseSection` (título + grid de cards + "Ver más")
5. Layout responsive:
   - Mobile: 1 columna, cards full-width
   - Tablet: 2 columnas
   - Desktop: 4 columnas
6. Thumbnails desde URL (400x400 ya servidas desde backend)
7. Tests:
   - ShowcasePage: renderiza 4 secciones
   - ArtistCard: muestra datos correctos, navega al click
   - Manejo de error: muestra mensaje si API falla

## Criterios de Done
- [ ] Vitrina muestra 4 secciones con cards
- [ ] Geolocalización solicitada y usada si se acepta
- [ ] Imágenes con lazy loading
- [ ] Responsive mobile-first
- [ ] Cards navegables a perfil de artista
- [ ] Tests de componentes
- [ ] No requiere login (ruta pública)
- [ ] Carga percibida < 3s (skeleton loading)

- Tiempo estimado: 4 horas
- Complejidad: Media
