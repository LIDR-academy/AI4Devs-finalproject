# TASK0001 — Backend: endpoints de disponibilidad y hold temporal

## User Story Padre
[US0008](us0008.md) — Seleccionar slot disponible y ver resumen de reserva

## Descripción
Implementar endpoints para obtener disponibilidad semanal del artista y para crear un hold temporal de 5 minutos sobre un slot seleccionado.

## Detalles de Implementación
- **Capa**: Backend
- **Componentes afectados**: `backend/Controllers/AvailabilityController.cs`, `backend/Controllers/BookingsController.cs`, `backend/Domain/Services/AvailabilityService.cs`
- **Endpoint(s)**:
  - `GET /api/artists/{id}/availability?week=YYYY-MM-DD`
  - `POST /api/bookings/hold`

## Pasos Técnicos
1. GET /api/artists/{id}/availability:
   - Recibe semana (lunes) como parámetro
   - Para cada día de la semana: obtener Availability del artista
   - Generar slots según slot_duration_minutes
   - Excluir: slots con bookings confirmados, blocked_dates, slots ya con hold no expirado
   - Retornar: `{ weekStart, slots: [{date, startTime, endTime, available: bool}] }`
2. POST /api/bookings/hold (autenticado):
   - Body: `{ artistProfileId, date, startTime, endTime }`
   - Validar: slot realmente disponible (re-check para evitar race condition)
   - Crear Booking con status='pending_payment', expires_at = now + 5 min
   - Retornar: booking con resumen (artista, fecha, hora, deposit_amount calculado)
   - deposit_amount = artista.min_session_price * artista.deposit_percentage / 100
3. Job/cleanup: liberar holds expirados (status pending_payment + expires_at < now → delete o cancel)
   - Puede ser middleware que limpia al consultar, o background job simple
4. Tests TDD:
   - Disponibilidad excluye slots con bookings confirmados
   - Disponibilidad excluye blocked dates
   - Hold exitoso crea booking pending_payment
   - Hold falla si slot ya tomado (409 Conflict)
   - Hold falla si no autenticado (401)
   - Hold expira: después de 5 min el slot vuelve a estar disponible
   - Deposit calculado correctamente

## Criterios de Done
- [ ] Disponibilidad retorna slots correctos excluyendo ocupados
- [ ] Hold crea booking temporal con TTL 5 min
- [ ] Race condition manejada (check-and-set atómico o lock optimista)
- [ ] Deposit amount calculado según tarifas del artista
- [ ] Tests TDD: unitarios + integración
- [ ] Hold expirado se limpia automáticamente
- [ ] Solo usuarios autenticados pueden hacer hold
