# TASK0001 — Backend: integración con Flow Chile (crear orden + webhook)

## User Story Padre
[US0009](us0009.md) — Pagar depósito vía Flow y confirmar reserva

## Descripción
Implementar integración con la API de Flow Chile: crear orden de pago, recibir webhook de confirmación, y actualizar booking/payment.

## Detalles de Implementación
- **Capa**: Backend
- **Componentes afectados**: `backend/Controllers/PaymentsController.cs`, `backend/Domain/Services/PaymentService.cs`, `backend/Infrastructure/External/FlowClient.cs`
- **Endpoint(s)**:
  - `POST /api/payments/init` (autenticado)
  - `POST /api/payments/callback` (webhook Flow)
  - `GET /api/payments/return` (redirect post-pago)

## Pasos Técnicos
1. Crear `FlowClient` (HttpClient wrapper):
   - Método `CreatePaymentOrder(amount, bookingId, subject, returnUrl, callbackUrl)`
   - Usa Flow API: POST /payment/create con apiKey + secretKey
   - Retorna: paymentUrl + token
2. POST /api/payments/init:
   - Validar: booking existe, pertenece al usuario, status=pending_payment, no expirado
   - Crear Payment con status='pending', amount=booking.deposit_amount
   - Calcular: platform_fee (configurable %, default 7%), artist_amount = amount - fee
   - Llamar FlowClient.CreatePaymentOrder
   - Retornar: { paymentUrl, token }
3. POST /api/payments/callback (webhook):
   - Verificar firma HMAC del webhook (seguridad)
   - Obtener status del pago desde Flow (GET /payment/getStatus)
   - Si exitoso: Payment.status='completed', Booking.status='confirmed', Payment.paid_at=now
   - Idempotencia: si payment ya completed, ignorar (200 OK)
   - Si fallido: Payment.status='failed', liberar slot (booking → cancelled)
4. GET /api/payments/return:
   - Recibe token, busca payment asociado
   - Redirect al frontend: /reservas/{bookingId}?status=success|failed
5. Configuración: FlowSettings (ApiKey, SecretKey, BaseUrl, CallbackUrl, ReturnUrl, CommissionRate)
6. Tests TDD:
   - Init: crea payment y retorna URL
   - Init falla si booking no es del usuario (403)
   - Init falla si booking expirado (409)
   - Callback exitoso: actualiza estados
   - Callback idempotente: segundo call no duplica
   - Callback con firma inválida: 401
   - Comisión calculada correctamente
7. Test de integración con Flow sandbox (si disponible) o mock

## Criterios de Done
- [ ] Orden de pago se crea en Flow
- [ ] Webhook recibe y procesa confirmación
- [ ] Booking pasa a confirmed al pagar exitosamente
- [ ] Payment registra flow_transaction_id, fees
- [ ] Idempotencia en webhook (no duplica)
- [ ] Verificación de firma HMAC en webhook
- [ ] Tests TDD unitarios con mock de FlowClient
- [ ] Secrets de Flow en configuración (no hardcodeados)
- [ ] Logging de transacciones (sin datos sensibles)
