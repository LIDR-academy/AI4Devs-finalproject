# TASK0002 — Frontend: flujo de pago y pantalla de confirmación

## User Story Padre
[US0009](us0009.md) — Pagar depósito vía Flow y confirmar reserva

## Descripción
Implementar el flujo de redirect a Flow para pago y la pantalla de confirmación/error post-pago.

## Detalles de Implementación
- **Capa**: Frontend
- **Componentes afectados**: `frontend/src/app/features/booking/components/payment/`, `frontend/src/app/features/booking/components/confirmation/`
- **Endpoint(s)**: Consume `POST /api/payments/init`

## Pasos Técnicos
1. En BookingSummary, botón "Pagar depósito":
   - Llama POST /api/payments/init con bookingId
   - Recibe paymentUrl
   - Redirect: window.location.href = paymentUrl (sale de la SPA)
2. Crear `PaymentReturnPage` (ruta: /reservas/:bookingId):
   - Lee query param `status`
   - Si success: muestra pantalla de confirmación
   - Si failed: muestra error con opción reintentar
3. `BookingConfirmationComponent`:
   - Muestra: ícono check verde, "¡Reserva confirmada!"
   - Detalles: número de reserva, artista, fecha, hora, monto pagado
   - CTAs: "Ver mis reservas", "Volver a la vitrina"
4. `PaymentErrorComponent`:
   - Muestra: ícono error, "El pago no se completó"
   - CTA: "Reintentar pago" (vuelve a llamar init)
   - Info: "Tu slot se mantendrá reservado por X minutos"
5. Manejo de pago abandonado: si el usuario vuelve sin completar, el countdown del hold sigue corriendo
6. Tests:
   - Botón pagar llama a init y redirige
   - Confirmación muestra datos correctos
   - Error muestra opción reintentar

## Criterios de Done
- [ ] Redirect a Flow funciona correctamente
- [ ] Pantalla de confirmación post-pago exitoso
- [ ] Pantalla de error con opción reintentar
- [ ] Datos de la reserva visibles en confirmación
- [ ] Tests de componentes
- [ ] No se almacena información de pago en frontend
