# TASK0002 — Backend: endpoint POST /api/auth/login + JWT

## User Story Padre
[US0001](us0001.md) — Inicio de sesión de usuarios

## Descripción
Implementar endpoint de autenticación que valida credenciales y retorna JWT con claims según rol.

## Detalles de Implementación
- **Capa**: Backend
- **Componentes afectados**: `backend/Controllers/AuthController.cs`, `backend/Domain/Services/AuthService.cs`, `backend/Infrastructure/Security/JwtTokenGenerator.cs`
- **Endpoint(s)**: `POST /api/auth/login`

## Pasos Técnicos
1. Crear DTO `LoginRequest` (email, password) con validación FluentValidation
2. Crear DTO `LoginResponse` (token, expiresAt, user: {id, email, firstName, lastName, role, artistProfileId?})
3. Implementar `AuthService`:
   - Buscar usuario por email (case-insensitive)
   - Verificar password con BCrypt.Net
   - Si inválido: retornar error genérico (no revelar si email existe)
   - Si válido: generar JWT
4. Implementar `JwtTokenGenerator`:
   - Claims: user_id, email, role, first_name
   - Si role == "artist": agregar claim artist_profile_id
   - Expiración: 24 horas
   - Algoritmo: HS256 con secret desde configuración
5. Configurar `appsettings.json`: JwtSettings (Secret, Issuer, Audience, ExpirationHours)
6. Registrar servicios en DI
7. Tests unitarios (TDD):
   - Login exitoso retorna 200 + token válido
   - Password incorrecto retorna 401 con mensaje genérico
   - Email inexistente retorna 401 con mismo mensaje (no enumeration)
   - Token contiene claims esperados
   - Token de artista incluye artist_profile_id
   - Token expira en 24h

## Criterios de Done
- [ ] Endpoint responde 200 con JWT válido para credenciales correctas
- [ ] Responde 401 con "Credenciales inválidas" para cualquier error (sin revelar causa)
- [ ] JWT contiene claims correctos según rol
- [ ] Tests unitarios escritos ANTES de la implementación (TDD red-green-refactor)
- [ ] Secret JWT no hardcodeado (viene de configuración/variables de entorno)
- [ ] Rate limiting básico configurado (prevenir brute force)
- [ ] No se loguea información sensible (passwords, tokens)

## Estimación
- Tiempo estimado: 3 horas
- Complejidad: Baja
