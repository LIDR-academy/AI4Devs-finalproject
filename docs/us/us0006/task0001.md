# TASK0001 — Backend: endpoint GET /api/artists/:slug (perfil completo)

## User Story Padre
[US0006](us0006.md) — Ver perfil de artista con portafolio, tarifas y certificaciones

## Descripción
Implementar endpoint que retorna el perfil completo de un artista por slug, incluyendo todas las relaciones (portafolio, estilos, certificaciones, premios, sponsors, disponibilidad).

## Detalles de Implementación
- **Capa**: Backend
- **Componentes afectados**: `backend/Controllers/ArtistsController.cs`, `backend/Domain/DTOs/ArtistDetailDto.cs`
- **Endpoint(s)**: `GET /api/artists/{slug}`

## Pasos Técnicos
1. Crear DTO `ArtistDetailDto` extendiendo ArtistCard:
   - Agregar: yearsExperience, instagramUrl, portfolioImages[], certifications[], awards[], sponsorships[], availableSlots[]
2. Query con Includes:
   - PortfolioItems (ordenados por sort_order)
   - Styles (via ArtistStyle)
   - Certifications (solo is_active = true)
   - Awards (ordenados por year desc)
   - Sponsorships (solo is_active = true)
   - Availabilities (solo is_active = true)
3. Retornar 404 si slug no existe o artista no publicado
4. Endpoint separado `GET /api/artists/{slug}/reviews?page=&pageSize=`:
   - Reviews paginadas del artista
   - Incluir nombre del cliente (solo first_name)
   - Ordenadas por created_at desc
5. Tests TDD:
   - Slug válido retorna perfil completo con todas las relaciones
   - Slug inválido retorna 404
   - Artista no publicado retorna 404
   - Reviews paginadas correctamente
   - No expone datos sensibles (emails, passwords)

## Criterios de Done
- [ ] Perfil completo retornado por slug
- [ ] Todas las relaciones incluidas
- [ ] 404 para slug inválido o artista no publicado
- [ ] Reviews paginadas en endpoint separado
- [ ] Tests TDD
- [ ] No N+1 queries (eager loading correcto)
- [ ] No expone información sensible
