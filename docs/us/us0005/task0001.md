# TASK0001 — Backend: parámetro search en GET /api/artists + full-text

## User Story Padre
[US0005](us0005.md) — Buscar artistas por texto

## Descripción
Agregar parámetro `search` al endpoint GET /api/artists que busca por nombre, estilo, comuna y bio usando full-text search de PostgreSQL.

## Detalles de Implementación
- **Capa**: Backend
- **Componentes afectados**: `backend/Domain/Services/ArtistQueryService.cs`, `backend/Migrations/`
- **Endpoint(s)**: `GET /api/artists?search={text}`

## Pasos Técnicos
1. Agregar migración con columna generada `search_vector` (tsvector) en ArtistProfile:
   - Concatenar: first_name || last_name || bio || commune
   - Incluir estilos asociados (denormalizados o via subquery)
2. Crear GIN index en search_vector
3. En ArtistQueryService: si `search` param presente, filtrar con `to_tsquery` o fallback a ILIKE para MVP rápido
4. El search se combina con los demás filtros (AND)
5. Endpoint GET /api/artists/suggestions?q={text} para autocompletado:
   - Retorna top 5 estilos y top 5 comunas que matchean el texto
6. Tests TDD:
   - Buscar por nombre: encuentra artista
   - Buscar por estilo: encuentra artistas del estilo
   - Buscar por comuna: encuentra artistas de esa comuna
   - Search + filtro combinados
   - Búsqueda case-insensitive
   - Sin resultados: retorna array vacío

## Criterios de Done
- [ ] Parámetro search filtra correctamente por nombre, estilo, comuna, bio
- [ ] Case-insensitive
- [ ] Se combina con filtros existentes
- [ ] Endpoint de sugerencias funcional
- [ ] Tests TDD unitarios + integración
- [ ] Índice GIN creado para performance

## Estimación
- Tiempo estimado: 3 horas
- Complejidad: Baja
